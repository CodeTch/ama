The JSON data has exactly these members: logicalBusinessKey,inputId,inputFingerprint,protocolVersion,modelIdentity,payloadSha256,roots. Roots has exactly objects {artifactType,version,sha256}, containing the full authentic reached root union prepared from original generation/processing/review closure, ordered by artifactType then exact UTF8 version. No duplicate (artifactType,version), contradictory hash, extra/unknown member, unsorted root or silently omitted/truncated root is accepted. Existing archive identifier/hash grammar and effective archive/root count/string budgets apply. The adapter owns complete authenticated original closure production; the provider validates supplied root identity grammar/order/uniqueness and canonical binding, not DB/archive authenticity it cannot observe.

## Exact encoding and bounded parsing

Header names are HTTP case-insensitive. Require one field occurrence and one value. Missing, repeated (including differently cased names), combined comma values, empty, whitespace-bearing/folded or malformed encoding is rejected before store reservation/computation. The alphabet is ASCII A-Z/a-z/0-9/-/_ only, no padding, no CR/LF. Reject impossible length and require decode then unpadded re-encode equals the supplied value. Bound encoded length before decoding/allocation.

Decode strict UTF8 JSON. Use managed bounded streaming parsing; reject BOM, invalid UTF8/Unicode, duplicate/unknown/missing fields, wrong types, trailing bytes and noncanonical numbers. Existing CanonicalJson.encode over the parsed exact typed object defines J(data): compare all decoded bytes with that bounded canonical rendering. Whitespace, alternate member order or escapes are not accepted as a second wire encoding. This transport JSON is distinct from CanonicalValueCodec's typed binary hashing; do not hash base64 or JSON bytes as logicalRequestHash.
