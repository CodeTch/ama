### T5SR02 — Important: one failed abort permanently skips the rest of Worker shutdown

**Primary final location:** `backend/worker/src/main/java/ama/worker/WorkerLoop.java:207`.

`close()` sets the global closed flag, stops scanners, and then calls `executions.forEach(Execution::cancel)` before shutting down heartbeats/workers. `Execution.cancel` at line 132 directly invokes the registered abort with no exception isolation. If one abort throws, iteration and `close()` stop immediately: remaining sources are not signalled, heartbeat and worker executors are not shut down, and the bounded join is never reached. A second close returns at line 205 because the flag is already true, so it cannot finish the skipped cleanup.

This is a reachable exceptional transport path, not only an arbitrary hostile callback. `TranscriptImportRuntime.java:91` catches `IOException` only, while `RangeReader.close` invokes `S3Objects.release`; `backend/adapters/src/main/java/ama/storage/s3/S3Objects.java:105` converts a failed body close into an unchecked storage-unavailable exception. The new generic contextual API also permits an abort action to fail. A backend close failure must deny success, but cannot abandon the other owned execution resources.

The same exception propagates through `backend/worker/src/main/java/ama/worker/TranscriptWorkerRuntimeProvider.java:40`: runtime `closed` is set before `loop.close()`, and definitions are only closed afterward, so the owned backend cleanup is skipped and also cannot be retried. This violates the adopted bounded shutdown/resource ownership/error-path contract.

**Required fix:** make cancellation best-effort across every execution, always shut down/join owned executors and always attempt backend close in finally-style cleanup. Preserve the first error or a bounded aggregate after cleanup, preserve interruption, and make repeated close safe even after a partial failure. Abort callbacks must remain outside the execution monitor.

**Focused proof:** run two active contextual preparations, make the first registered close/abort throw and the second record its cancellation, then close. Assert the second action still runs, no post-close writer/quarantine occurs, every executor reaches its required bounded termination, and backend close is attempted once despite the first error. Also cover repeated close after the failed first cleanup. No suite rerun was performed here.
