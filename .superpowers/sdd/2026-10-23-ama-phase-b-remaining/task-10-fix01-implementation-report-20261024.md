## I1 — ordinary deferred failure protocol

`MinutesDeferredPreparation.java:9–17` is the common check used by all six final receipt branches in saved/adopt/body/set/restore, review, settings and decision commands. Ordinary errors are explicitly named: bounded budget exhaustion, actual `ARCHIVE_IO_UNAVAILABLE`, and the listed revision/current-target/editor-intent/business-readiness/sequence conflicts. Generic `PROFILE_UNAVAILABLE`, `PROVENANCE_UNAVAILABLE`, `CAPABILITY_UNAVAILABLE`, fingerprint failures, access denial, programming exceptions and cancellation do not qualify merely because they represent 503/unavailability. ## I2 — complete bounded prospective accounting

`MinutesDomainCapacity.java:14–37` accounts by primary key for these row families: generation_input, durable_task, task_attempt, external_operation, external_execution and generation_candidate. The existing independent limits remain independent: durable tasks <= min(256, registered tasks); generation inputs <= min(256, registered revisionNodes); attempts, operations, executions and candidate declarations <= 256. These are the existing consumer capacities, not new product quotas. In particular tasks=2 is not reinterpreted as an attempt limit of 2.

For each family, prospective size is distinct occupied rows plus still-possible growth:

- task_attempt: actual retained rows + sum(max_attempts - attempt) for READY/RUNNING tasks + the genuine prospective producer's maxAttempts. Actual attempt rows are checked against the task counter and distinct range. Terminal history contributes its actual rows only. RECONCILING cannot be claimed by JdbcTaskQueue (only READY and expired RUNNING can be claimed); it contributes actual attempts, with no invented future ordinary claims. All currently supported producers retain their original maxAttempts=3.
- durable_task: distinct actual merged tasks + one only for a genuinely new producer. generation_input similarly adds the new input only if absent.
- each minutes operation/execution/candidate: actual declared rows + one missing future row per nonterminal minutes task; a newly admitted minutes producer reserves one of each. Existing rows consume that reservation rather than being counted again. Terminal rows are retained when declared, without reserving nonexistent future effects. The total retained generation task bound also bounds its one-candidate history; selection can add its existing decided candidate without creating another producer footprint.
- imported source tasks add only their actual local task/attempt growth, never a fictitious external operation/execution/candidate. Other producer kinds are not guessed into this rule.

Under minutes, that fixes the same producer: the retry path can only encounter the already existing producer and cannot create a different task/execution; a changed producer is rejected by the domain gate. This is not a statement that generic Task7 or future Task11 tasks have one execution.
