## 8. Definitive-zero-effect retry and explicit supersession extension

### 8.1 Why a new confined operation is necessary

Existing retryAfterZeroEffect checks old.spec businessVersion/cancelEpoch/input/fingerprint equality and operation logical key/hash equality. Changing destination changes logical fingerprint even with SAME final/business key; editing after safe failure changes r/final/key. Passing either to old retry is incompatible. Merely mutating publication current projection first would corrupt old task validation. This design adds a publication-only capability-confined method, leaves old retry behavior unchanged, and makes this an explicit independent review gate.

Marked-round replacement uses existing external tables and immutable per-execution request_manifest; all acceptances additionally require the prospective immutable publication_submission binding in §8.5, including rounds which never acquire an execution. For a changed final/key, accept a new task for the SAME publication UUID; a NEW external_operation and first execution are created only by the later genuine committed marker. Preserve every old task/attempt/execution/final/request/receipt. Operation request_hash is documented as current-binding projection only on this new reviewed path, not historical truth. No update to historical execution manifests/hashes/proofs. Original operation fields/old behavior remain for all other task types.

All old/new task policies in preparation must distinguish historical receipt-only closure from new current-effect eligibility; they must not demand that an old completed task match the new mutable publication projection merely to record its fact. This split stays private to publication and does not relax ordinary task validation. If pinned actual Task7 policy cannot verify old logical facts from a complete original manifest and attempt/final association, supersession MUST fail unavailable; root receives a concrete schema/protocol gap before implementation, never infers missing columns. New protocol manifests are mandatory from first Task11 publication; legacy/incomplete publication histories are not eligible for supersession or backfill.
