# Shared identity session time

Session tokens and CSRF values remain generated by the server after verified CAS identity authentication. Each request resolves the current token, identity status, role assignments, revocation and generation in the shared database. Session validity never comes from a process authorization cache or a caller-provided clock.

V042 adds the nullable `enterprise_identity.session_time_floor`. Genuine issuance and resolution advance this identity-local value to the greatest of its previous value and the current database UTC time while holding the identity lock. The stored floor is a previously observed database time, not a cached permission or a new grant. NULL legacy values are first advanced from database time; arbitrary historical session timestamps and client timestamps never initialize it.

The current session is checked under a locking read against that same observed time. Its token must still bind the initially discovered identity; the identity must be ACTIVE, its generation must match, the session must be unrevoked, issuance must not be in the future, and expiry must be strictly later. Advancing on observations also prevents a session already observed expired from becoming valid again after a wall-clock backstep. Existing lifecycle and revocation locks retain identity-before-session order.

The change addresses a measured local database backstep: a newly signed-in test identity was rejected while its issued timestamp was 449743 microseconds ahead of the database's new wall-clock value. It does not remove the future-session check or apply an arbitrary skew allowance. Deterministic integration tests use connection-local MySQL timestamps; they never change host/container time, rewrite shared historical sessions, or relax authorization checks. The tests also verify JVM/database skew, backwards time, expiry resurrection, future-dated rows, revocation, generations and committed revocation inside an older repeatable-read view.
