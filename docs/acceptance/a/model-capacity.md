# A-03 模型协议与实时容量验收

日期：2026-10-21。状态：**PENDING_REAL_ENVIRONMENT**。公司接口尚未核验；本次只运行本机 loopback HTTP 假服务。未访问公司模型地址，未外传音频或凭证。假服务仅验证探针的线缆协议、校验、故障和指标行为，不是真实模型、应用双机或容量验收。

## 可用方案

交付 `tools/probes/model_probe.py` 的 Python 3 标准库 API/CLI，覆盖 VAD、SPK、ASR、embed、punc、LLM 六种文档协议。采用显式地址、授权引用、Host/鉴权配置及有界并发，完整 WAV/Base64 与毫秒区间均按文档发送/解释。ASR 的 tokens 仅作为可选实测字段记录，不把缺 tokens 当响应失败，不保存 token/文本内容。未知平台参数不静默发送。

以独立完整 2 秒 WAV 的短窗口 HTTP 作为**待联合验证候选**；较长窗口和重叠上下文也分别提交完整 WAV，不假定有流式协议、稳定结果标志、实时实名或跨窗口说话人一致性。punc/LLM 分别测量，不能把纠错延迟隐藏在“已识别”后。没有可选 tokens 时仅有片段级定位；SPK 编号不能作为真实姓名或授权依据。

本地协议测试覆盖 429、500、302、缺 text、非法 JSON/字段/区间、迟到回复、断链、并发、排队、封口等待和固定速率到达。时延包含失败，并对未知完成与未发送项标记删失；超时不释放未知服务端额度，不自动重试。默认 1 次、3 秒 socket 等待、10 秒准入预算，显式并发 1 起步，最多 100 并发/1000 请求/批。它是受限探针，尚不支持代理、mTLS、跨进程额度或正式长稳压测。

## 需要的平台能力

模型平台需提供获准测试的隔离环境、地址与版本、授权引用和受控凭证、Host/证书要求、配额及配额协调方式、网络连通性，以及接口支持的 WAV 时长与最大尺寸。需确认实际错误体/429/Retry-After、超时后查询或取消、安全截止、并发和 RPS 限额、模型服务时间及队列指标。只有客户端断开而没有取消证据时旧请求仍算未知工作。

需确认 ASR tokens 是否提供及其毫秒语义，是否有真正流式与稳定结果标记，在线说话人能力与声纹模型/维度兼容性；没有能力时明确片段定位/匿名占位降级。需提供含合法评估音频与人工参考的授权样本集，并由平台和业务共同冻结重复词保留、数字/术语、交叠等质量判定。

## 后续授权实验（本次未运行）

1. 单路确认全部协议与认证，再以 1/10/50/100 场递增。2 秒窗口对应计划到达间隔分别约 2000/200/40/20ms；先用短批次确认限额，不能一次直接压满。单路低频的长样本跨度需减少 repeats 使计划跨度落在本探针预算内。
2. 每级比较独立 2 秒、较长窗口、重叠上下文与静音边界。记录实际提交的音频秒数、窗口/重叠长度、音频版本引用、模型版本、请求分布、原始指标、限流/错误/超时/未发和未知在途。重叠样本由授权样本准备流程产生；探针不截断整份长录音冒充可行。
3. 配置 `arrival_interval_ms=20` 表示 offered 50/s；并发上限由平台配额明确批准。按速率×服务时间＋余量估算在途（50/s×1s≈50），同时观察排队及失败。若 timeout/NETWORK_ERROR，停止该批新准入，确认服务端遗留工作后再决定下一批；若持续429、积压、超预算或质量不达标，不升级负载。
4. 将探针的删失标记和错误一并汇总，不能仅报告有效响应的分位数。识别文本/人工质量在受控授权工作台核对，指标日志不存原文或 tokens。记录重复词误删、数字/术语错误、交叠丢失和跨窗口一致性。
5. 真实模型短批次可行后另做应用层 100 场＋300 在线的 2 小时/8 小时长稳、实际浏览器片段结束到临时/稳定文本时延及双机故障演练。当前工具的 ≤1000 请求短批次、单进程额度和 socket I/O 等待不是该验收替代品。预算只限制准入，已发调用要收尾；socket 等待不保证抵御持续慢速分段响应或 DNS 阻塞的墙钟上限。
