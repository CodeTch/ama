# B06.2 controlled archive consumer guide

This delivery qualifies immutable local configuration releases and authorized processing metadata recovery. It composes the reviewed batch v1 helper, archive source/publisher and processing facts reader with S1. It does not activate a production importer, task policy, provider, HTTP API or worker. The original prepared plan remains a historical PREPARED document; root's activation/adoption record governs execution status.

## Explicit deployment inputs and publication

Consumers supply an absolute protected archive root, exact original index SHA256, explicit default processing `Ref`, `IndexBudget` and `ArchiveReadBudget`. The index SHA is a deployment trust anchor; a digest alone does not authenticate its publisher. There is no `latest`, `CURRENT`, automatic discovery, version alias or runtime publisher registration. The new default chooses only new drafts. Historical inputs always use their unchanged persisted manifest's exact type/version/SHA references.

The explicit offline `ControlledArchiveReleaseWriter.publish(root, previousIndexSha, appended, indexBudget, readBudget, cancelled)` returns the new exact index SHA. First publication uses null predecessor. Root must already exist; publication validates predecessors, all old mappings and all old/new raw objects and dependencies. It writes its own staging release, forces files/directories and atomically moves the complete release into `releases/<indexSHA>/`. Existing releases/identities are never overwritten or removed. Failed partial publication retains the previous complete release; this qualification does not prove power-loss/HA behavior or protection against a malicious privileged administrator. No GC/TTL is supplied: retain every old release/object referenced by persisted inputs.

Objects are `releases/<indexSHA>/objects/<rawSHA>.json`; raw SHA covers exact canonical JSON bytes. Strict index grammar is `ama.config-index.v1` with generation, predecessor SHA and uniquely sorted entries. Immutable `(artifactType, exact version)` mappings include raw SHA and byte length. Opening a pinned release validates the continuous predecessor chain, unchanged prior entries and every selected-release object, including unselected historical objects. Missing history, links/nonregular files, replacement, unknown schemas, wrong SHA/size, remapping or incomplete dependency graphs fail closed. A protected filesystem supporting `SecureDirectoryStream`, directory force and atomic publication is required; unsupported capabilities are unavailable.

## Processing read and verification sequence

1. Open `new ControlledConfigArchiveSource().open(root, exactIndexSha, indexBudget, readBudget, cancelled)` outside a DB transaction. A snapshot retains immutable metadata, not trusted in-memory raw archives. Each `loadClosure(roots, budget, reservedManifestBytes, cancelled)` reacquires and verifies fresh bounded transport bytes.
2. For a new draft, call standalone `new JdbcProcessingFactsReader(source).readBatch(actor, meetingId, batchId, budget, cancelled)`. It checks current ACTIVE identity and owner EDIT access, locks current subject/meeting and returns detached complete batch/member/four-field ContentFile facts. Compute/verify explicit `ama.input-batch.v1` with `BatchFingerprint`; this helper does not identify or reinterpret legacy hash profiles.
3. Build exact canonical IMPORT/TXT/EMPTY manifest bytes using the real IDs/fixed fence and explicit archived processing/parser/codec/confirmation refs. Load its exact closure with manifest bytes reserved, then call `ConfigBindings.computeProcessing` outside all DB transactions. Draft computation has no own stored input/task/output placeholder.
4. A later real write transaction must reacquire authentic access, recheck current fence and all immutable facts used by the draft, then persist exact manifest/fingerprint and enqueue a full immutable TaskSpec through the domain's reviewed policy/preparation protocol. This delivery demonstrates that composition only through a registered TEST policy. The standalone reader cannot join this transaction or supply a write capability. Do not place filesystem reads, strict JSON parsing or S1 hashing in the write transaction. Outbox flush happens once at the outer transaction's end; a commit ACK follows the transaction method's successful return.
5. For recovery, call standalone `readStored(actor, meetingId, inputId, budget, cancelled)`. It returns the complete original input/batch/members/files, every actual matching queued TaskSpec and task ID, all owning transcript revisions and actual producer tasks. Empty owning revisions are an explicit complete empty set. Current meeting revision never replaces old saved task fences.
6. After the reader's transaction has ended, take the exact original `config_manifest` from its FullRow. `new ProcessingManifestRefs(new StrictProcessingManifestReader()).roots(originalBytes, budget, cancelled)` discovers strict bounded refs only. Load that closure from the pinned snapshot, then call `ConfigBindings.verifyProcessing(storedInput, detachedFacts, rawArchives, budget, cancelled)`. Discovery, a typed DTO or successful snapshot open cannot mint an S1 success binding. Missing old bytes never selects current defaults.

The reader owns its DataSource-local transactions and rejects ambient ones. It bounds identity display names and manifest LONGTEXT by exact UTF8 byte, Unicode scalar and UTF16 code-unit lengths before materialization; subsequent bounded streaming rechecks those dimensions. Ordered current reads and remaining+1 limits reject excessive facts instead of truncating. Same-meeting membership/task/producer consistency remains validated from complete real facts. A read supplies no ongoing write authority; later writes need fresh authentic gate/fence checks. Identity status is read from DB, never trusted from `Actor.status`.

## Bounds, cancellation and failures

Controlled `IndexBudget` is `(4194304,4096,67108864,128)`. The qualification `ArchiveReadBudget` is `(65536,1048576,16,32,8,200000,32,255,65536,262144,1048576,65536,32,250000,500000)` in its actual record field order. These are explicit technical qualification bounds, not production quotas/defaults. Objects are at most65536 bytes; transport plus manifest reservation is limited before allocation. S1's owned acquisition and closure/JSON/fact accounting remain independent cumulative checks. Processing root.1/root.2 pin the same parser/canonical budgets described in the prepared plan; changing operational limits may reject, never truncate or rewrite accepted bytes.

`source.open`, `Snapshot.loadClosure` and `publisher.publish` install cooperative30-second monotonic checks around bounded local I/O. They do not preempt an operating-system read. Standalone `StrictConfigIndexReader.read` and `ProcessingManifestRefs.roots` enforce finite budgets and the caller predicate only; they do not install a timer. The JDBC reader uses bounded queries and a five-second JDBC query timeout; no universal driver blocking/cancellation guarantee is claimed. Cancellation/interruption fail closed; restore/retain interrupt semantics supplied by the adapters.

Errors expose typed code-only failures, without raw payload/path/provider diagnostics. Missing/mutated historical bytes or a wrong pinned index are `PROFILE_UNAVAILABLE`; resource/cancellation failures remain their corresponding bounded failure codes. No partial successful digest should be treated as acceptance after an exception. Do not repair old rows, rewrite manifests or substitute defaults to suppress errors.
