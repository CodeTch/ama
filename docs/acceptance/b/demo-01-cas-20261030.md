# DEMO-01 CAS 联调记录 — 2026-10-30

本轮把本地与生产共用的身份入口切到 CAS 2.0：浏览器访问 `/auth/cas/login`，AMA 跳转到联调辅助项目的 `/cas/login`；CAS 返回一次性 `ST-*` Ticket 后，AMA 服务端使用固定的 `CAS_SERVICE_URL` 调用 `/cas/p3/serviceValidate`，严格解析 XML，按 CAS 用户属性同步本地身份，再签发 `__Host-AMA_SESSION` 会话。密码不经过 AMA API，也不进入 AMA 数据库。

联调辅助项目使用固定端口 `8792` 运行（`FIXED_PORTS=1`），配置了精确的 `CAS_ALLOWED_SERVICES`：

```text
http://127.0.0.1:5173/auth/cas/callback
http://127.0.0.1:5173/meetings
```

- `CasXmlTest`：5/5，通过 CAS 成功、失败响应、XXE/命名空间/嵌套元素边界。

- `CasControllerTest`：3/3，验证 CAS 跳转、Ticket 回调、Host-only Secure/HttpOnly Cookie、缺失 Ticket 拒绝和本地撤销后 CAS 登出。

本记录只覆盖 CAS 身份入口和 DEMO-01 的登录前置；文件服务、Worker、模型和知识库发布仍按 DEMO-02～04 接续，M1-Demo/B 仍不因本记录单独完成。

安全边界裁定：Ticket 只按固定的 `CAS_SERVICE_URL` 在服务端校验，CAS service URL 必须属于 `IDENTITY_ALLOWED_ORIGIN` 且回调路径固定为 `/auth/cas/callback`；联调辅助项目无白名单时 fail-closed。当前实现未增加额外的登录 initiation state，依赖 CAS 一次性 Ticket、固定 service 和 HTTPS/同源 Cookie 边界；若生产威胁模型要求防止被动登录 CSRF/会话替换，应在真实 CAS 资格阶段补充 state 绑定与专门验收。
