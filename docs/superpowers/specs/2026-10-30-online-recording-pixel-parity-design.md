# 在线录音界面像素复刻设计

## 意图

把在线录音页面按仓库中的原型 `designDocs/智能会议助手1021版.html` 做 1:1 视觉复刻，覆盖页面标题区、录音控制卡片、保存状态、已保存分段、实时转写空态、底部说明、信息与材料入口，以及录音中的暂停/中断/结束交互状态。现有真实录音能力和接口边界继续保留；服务未接入的部分只显示诚实的延期状态。

## 目标

- Vue 页面先以原型 `.acr-page` 为唯一骨架重建，DOM 顺序、文案、控件语义、间距、颜色、圆角、字体和响应式断点一致。
- 录音页的未开始、录音中、暂停、分段中断、保存失败、结束保存和实时转写空态均可通过测试夹具稳定渲染并验证。
- 开发阶段允许用伪数据演示完整页面交互；视觉验收后移除演示数据和临时入口，生产组件只从真实状态机与接口读取数据。
- 现有会议信息抽屉、背景材料入口、浏览器录音和上传流程不被破坏。

## 非目标与反目标

- 不新增原型中没有的卡片、按钮、提示、业务流程或品牌装饰。
- 不把录音、实时 ASR、材料处理或服务端保存伪装成已经接入。
- 不重写全站样式，不改动会议列表、会议工作台或后端接口。
- 不保留开发阶段的假接口、演示数据或绕过登录/权限的生产开关。

## 约束

- 所有修改、测试和验证在 `/home/tanren/ama` 的 `main` 分支进行，不建立 worktree。
- 原型 HTML 是视觉权威；附件临时路径在当前环境不可读，因此不对附件做猜测性扩展。
- 现有工作树含其他未提交改动，只修改本设计涉及的文件并按路径精确暂存。
- 测试使用 Vue SSR/组件测试和 Playwright 视觉检查；视觉验证至少覆盖 1440×900 与 1024×768，动画按 reduced-motion 固定。

## 方案与取舍

1. **原型结构回填**：沿用 `RecordingPage.vue` 和真实录音 composable，逐项对齐原型模板及最终级联 CSS。改动集中且保留现有业务边界。
2. **只做 CSS 覆盖**：改动较小，但无法可靠修正原型与当前 DOM 在控件顺序、状态文案和条件渲染上的差异，像素差异会被结构问题掩盖。
3. **整页重写演示页（采用）**：先按原型重建页面，用测试/开发伪数据覆盖录音、暂停、继续、中断、结束和转写展示，快速完成像素与交互确认；验收收口时删除伪数据和演示入口，把同一模板接回真实录音状态与接口逻辑。

## 实现决定

- 先复制原型在线录音区块的结构和状态交互到 Vue 页面，演示阶段只在页面测试夹具中注入伪数据，不写入业务持久化。
- 视觉验收结束后删除演示分支、固定文案和伪数据适配器，保留模板、真实事件处理和真实接口边界。
- 优先修改 `RecordingPage.vue`、录音相关共享样式和对应测试；不改原型源文件。
- 完成后运行录音单测、前端类型检查、构建和视觉/e2e 检查；最终报告只声明有证据支持的结果。
