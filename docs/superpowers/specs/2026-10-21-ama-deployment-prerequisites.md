# 智能会议助手部署前置条件与验收证据

日期：2026-10-21；版本：0.2，增加服务器本地文件系统 / S3 双存储后端的部署准备清单。

用户已明确：**虚拟化平台和隔离接口由其向运维确认，先列为部署前置条件，继续细化整体架构。** 本清单不要求现在提供凭证或立刻执行故障操作。

配套文件：[整体架构](2026-10-21-ama-architecture-design.md) · [需求对应与差异](2026-10-21-ama-requirements-matrix.md)。

## 1. 适用范围和当前状态

- 数据库以 `database.mode=private-ha|enterprise-platform` 选择两台内私有 MySQL 或公司 MySQL；文件以 `storage.type=local|s3` 独立选择本地文件系统或 S3。
- local：两台 VM 内提供活动文件服务和同步文件卷，不安装 S3 服务。应用双活，文件服务单活动；即使 MySQL 外置，文件 HA 仍由本项目与运维负责。
- s3：使用私有或公司 S3；私有组件在两台内并受集群管理，公司服务由平台负责 HA。应用入口、网络、身份和接口前置条件始终适用。
- 所有组合均使用公司现有模型、知识库、统一登录和人员目录。
- 两台规格、操作系统及容量目标已由用户给出；磁盘、网卡、宿主拓扑、软件订阅和接口能力尚未取得运维证据。不能把“有两台 VM”当作已经具备高可用。

责任方是职能角色，后续由项目负责人映射到具体人员。当前状态分为“用户已确认”“待运维提供”“待平台提供”“待联合验证”；没有证据的条件不能标记完成。

## 2. 两台内私有数据组件的基础设施

条件按实际组件适用：使用私有 MySQL、本地文件系统或私有 S3 时均要验证相应同步卷与隔离链路；仅使用公司 MySQL＋公司 S3 时，不部署这些私有数据组件。local 的专属条件为 PR-15，私有 S3 为 PR-10，私有数据库为 PR-09。

| PR-10 | 私有 S3 产品资格 / 待联合验证 | SeaweedFS 候选固定版本/许可证；S3 契约测试；对象数据、索引、Filer MySQL 元数据、Master 状态都在恢复清单；响应成功前落盘语义及断电恢复有实测证据 | 存储运维＋开发 / 私有 S3 定型、durable ACK 资格 |
| PR-11 | 资源与容量 / 待运维提供及压测 | 磁盘容量/IOPS/延迟、vCPU 是否超分、内存保证、网络带宽；按单节点故障后承载 100 场实时＋300 在线测试；同步复制、重同步、导出和备份成本计入 | 运维＋开发 / 容量验收 |
| PR-12 | 安装、镜像与时间 / 待运维提供 | 内网镜像/软件源、镜像摘要、漏洞扫描、NTP、DNS、CA、证书续期、Podman/systemd 版本及 SELinux 策略；不以关闭 SELinux/防火墙作为默认方案 | 系统运维＋安全 / 环境部署 |
| PR-13 | 备份和恢复目的地 / 待运维确认 | 数据保留、备份周期、binlog 保留、恢复点与恢复时限、加密及恢复演练；仅双机内备份须承认共同故障边界；外部企业备份若获准则配置接入 | 数据库＋存储＋安全 / 生产上线 |
| PR-14 | 告警与值守 / 待运维确认 | 告警接收渠道、等级、值班归属；磁盘满、复制失步、隔离失败、模型积压、发布对账异常均可观测；日志容量及最小敏感信息规则 | 运维＋开发 / 生产上线 |
| PR-15 | 本地文件后端 / 待联合验证，仅 local 适用 | 受保护根目录和卷身份、专用账号、SELinux 标签、内部服务身份/地址、空间及 inode 配额；文件/目录同步、原子发布、受保护上传暂存、路径逃逸防护、Range 续读、挂载丢失拒写及切换后完整性实测；local 无 S3 配置即可运行 | 系统运维＋安全＋开发 / 本地文件定型、durable ACK 与自动恢复验收 |

PR-01、PR-02、PR-07 及按组件适用的 PR-09/PR-10/PR-15 是私有自动恢复路线的关键资格条件。local 不要求通过私有 S3 产品资格，但仍须验证磁盘持久化和自动接管。当前可以继续领域设计、适配器设计和页面细化，业务实施仍按架构评审流程推进；不能在这些条件未验证时宣称私有 HA 可上线。若条件最终不能满足，需重新评审私有路线，不能擅自改为人工切换或不安全自动提升。

网络与磁盘不按一个孤立带宽数字批准：100 路原始 PCM 输入约 25.6Mbps，但同步复制、索引写、模型请求、归档、回听、备份和节点重建会额外消耗资源。以单节点和重同步期间的 NFR 实测作为最终依据。

local 与私有 S3 都必须证明落盘和接管语义。local 要验证文件及相关目录同步、暂存/正式文件的崩溃边界；私有 S3 不能仅凭普通 PUT/GET 就接受 RPO=0 目标。资格不符时应在定型前调整实现，不把弱确认命名为 durable ACK，也不未经确认自动改用另一后端。

## 3. 公司平台模式

下表按实际接入项适用：公司数据库适用 PL-01；公司 S3 适用 PL-02；PL-03/04 仅针对实际使用的公司服务。公司 MySQL＋local 仍须完成 PR-15 和本地 HA 相关条件，不能因数据库外置而豁免文件的自动恢复验证。

| 编号 | 条件 / 当前状态 | 所需证据与通过标准 | 责任方 / 阻塞阶段 |
| --- | --- | --- | --- |
| PL-01 | 公司 MySQL / 待平台提供 | 版本、写入口、TLS/CA、最小权限 schema/账号、连接额度、字符集/排序规则、事务和 SKIP LOCKED 能力、维护窗口、备份及故障切换行为 | 数据库平台 / 数据库联调 |
| PL-02 | 公司 S3 / 待平台提供 | Endpoint/Region/寻址、Bucket、签名算法、TLS、凭证、对象限额、multipart/Range/校验和/分页/删除语义、持久化及一致性保证、服务 SLA | 对象存储平台 / 文件联调 |
| PL-03 | 网络与限额 / 待平台提供 | 两台应用到实际选用 MySQL/S3 的链路、允许端口、连接和请求速率配额；S3 以约 50 PUT/s 小对象负载测试，并纳入视频大文件、20 路回听和并发处理 | 平台＋网络 / 性能验收 |
| PL-04 | 故障责任与观测 / 待平台提供 | 外部服务 RTO/RPO、故障通知、限流/维护错误、支持渠道及 trace 对接；应用恢复测试须覆盖平台入口切换和长连接断开 | 平台运维 / HA 验收 |
| PL-05 | 入口 HA / 待运维确认 | 可用企业负载均衡的两后端健康检查与 WSS/SSE/Range 配置；若无，则两 VM 内建立受控入口 HA，其网络/隔离要求仍需验证 | 网络运维 / 应用入口验收 |

数据库来源和两种文件后端不应分叉业务逻辑。后端 ID 的配置含义保持稳定，不能将一个已有 ID 从 local 改成 s3 并继续沿用旧路径。默认后端只决定新会话写入；历史文件按原后端读取/删除。在 local 与 s3 间迁移须复制、校验、更新位置并保留回滚窗口；进行中的录音/上传固定原后端，不因改配置而中途转移。

## 5. 自动恢复演练必须留下的证据

演练计划需在隔离测试环境具体化后由环境责任方安排。每项记录软件/配置版本、负载、故障注入方式、时间线、唯一写入证明、数据核验、恢复结果和原始日志；通过标准引用整体架构 NFR，不只记录“页面还能打开”。

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| HA-01 | 单个 API / 实时进程被终止 | 健康摘流、客户端重连、未 ACK 分片补传；旧 writerEpoch 失效，不重复写入 |
| HA-02 | Worker 退出，外部请求仍在执行 | 租约可回收；旧结果不能覆盖；外部副作用对账，模型额度不因超时被反复超卖 |
| HA-03 | 活动数据 VM 被断电或卡死 | 真正隔离完成先于数据提升；健康副本启动；记录 RTO 及所有已确认分片/提交的核验 |
| HA-04 | 节点间业务/复制网络分区 | 不能出现双 Primary 或双写；已选定的隔离仲裁和防相互隔离策略符合预期 |
| HA-05 | fencing 接口不可达或返回失败 | 不在旧写入方状态不明时强制提升；告警可见，客户端不会收到虚假保存成功 |
| HA-06 | 副本落后、卷不健康或同步未完成 | 不能把旧副本当最新提升；已有数据按承诺边界核验，不静默回滚 |
| HA-07 | 旧节点重新加入 | 先作为备用重同步，禁止双挂载、不自动切回；满载时重同步受限且可观测 |
| HA-08 | 磁盘写满/故障、MySQL/所选文件服务短暂错误 | 返回明确未保存/待重试；缓存有界；不删除历史或放宽持久化要求 |
| HA-09 | 知识库成功但响应丢失 | 稳定业务键查回原文档，不重复发布；未知态禁止重新编辑后二次发布 |
| HA-10 | 撤权、撤回/废止发生于回听或下载中 | 新访问拒绝；现有流在约定检查窗口内终止；已下载字节边界记录清楚 |
| HA-11 | 协调恢复点的数据库及文件恢复 | DB 版本、材料、音频、纪要和导出引用对应；local 与 s3 分别记录孤儿/缺失文件处理；公司数据库＋local 也验证一致性 |
| HA-12 | 单台接管后持续满载、随后恢复第二台 | 100 场实时＋总计 300 在线达到约定目标；故障期间保存缺口、识别积压和追平过程单独统计 |
| HA-13 | local 写入中断、目录同步失败、挂载丢失 | 没有半文件被登记成功；不写到系统盘同名目录；所有 durable ACK 文件切换后可读且哈希一致；未确认上传能从受保护暂存续传 |
| HA-14 | 更换默认后端或迁移中断 | 历史读取和删除仍按记录路由；进行中会话不混用后端；复制未校验不得更新位置；迁移重试/回滚不误删仍被引用的文件 |

RPO=0 仅是对正常同步、落盘链路已资格验证时的已确认数据提出的目标。未上传数据、未收到 ACK 的数据、两个故障域同时失效不纳入相同保证。断开复制后继续单副本写入期间必须显式显示降级，不能继续宣传同等级的双副本保障。

## 6. 上线前交付包

1. 数据库来源与 local / s3 的组合部署说明、版本/镜像摘要清单、配置模板、服务启动/停止职责、密钥引用方式；local 不含强制 S3 配置。
2. 应用入口、同步网络、管理网络、磁盘和外部依赖拓扑；全部持久化路径及权限清单。
3. local / s3 共同及各自特有契约、模型/SSO/知识库测试报告；各实际支持部署组合的容量、故障、安全和视觉验收报告。
4. 数据库和文件后端迁移、回滚边界、数据备份恢复、文件/对象完整性校验、删除清理和发布对账操作手册。
5. 值班告警、故障归因、自动恢复失败时的应急流程；禁止操作及人工介入审计规则。
