## 2. 选定的设计方向

建议采用 **四模块治理工作台 + 个人申请跟踪 + 主链路接入**。

只调整颜色、间距不能解决申请未入队、语料未消费和配置未接入的问题；完全重建后台又会丢掉已有权限、幂等、审计和恢复能力。保留这些基础设施，将混在一个页面内的表单拆为业务列表、详情与独立操作，是本次建议的实施方式。

不增加与本次业务无关的大屏。管理首页默认进入语料治理，优先显示待处理事项；四个入口固定为「语料治理」「声纹治理」「质量评测」「系统配置」。历史和审计在各资源详情中查看，另提供仅限治理资源的审计检索入口。

| 用户 | 主入口 | 可执行行为 |

## 4. 语料治理

### 4.1 提交与个人跟踪

- 恢复原型的六类反馈：人名纠错、部门纠错、产品纠错、金融术语纠错、产品别名、术语读音。
- 结构化保存 `originalValue`、`suggestedValue`、`feedbackType`、`note`，以及会议/转写版本、片段和来源范围。复用核查期间工作区已补充的六类提交表单、接口、联合查询和 V069 字段，不另建同义字段；完成端到端字段往返与兼容验证。会议 ID、版本、段 ID 自动传递，不让普通用户手输。
- 保留当前旧类别和原始 comment。旧数据不能可靠拆分时明确显示「历史非结构化反馈」，禁止靠正则推断真实原值或默默批准全局使用。
- 个人反馈页保留原型七列，统一展示语料和声纹申请；状态数量、筛选与游标分页由同一后端查询计算。
- 待审核可撤回；需要补充时追加说明并重新进入待审。已经通过的反馈撤回后停止新使用，但不删除历史审核事实。

### 4.2 审核与生效

- 管理列表：类型、原值/建议值、提交人、允许披露的来源摘要、提交时间、审核状态、使用状态、操作。
- 支持类型、状态、时间及关键词筛选；默认待审。分页大小默认 20，支持 50；服务端限制单页最大 100，并返回总数或准确状态计数和 nextCursor。
- 详情展示结构化差异、明确提交的最小上下文、版本有效性、补充说明与审核时间线。来源会议只有在当前管理员另有会议访问权时才能跳转全文。
- 审核结论：通过、驳回、需要补充；驳回与补充必须填原因，通过记录审核说明。不同管理员对同一旧修订的操作返回冲突。
- 「审核状态」和「使用状态」分开：已通过不等于永远有效。使用状态包括待生效、有效、本人撤回、审核撤销、来源失效、缺少来源绑定。
- 通过操作创建不可变批准修订，并原子推进有效语料版本；不要求用户到另一个页面完成隐藏的第二次发布。版本冲突需要重新核对。

### 4.3 接入实际处理

批准语料不能止于 `/operations/corpus` 列表。新转写/纠错任务读取经过用途和当前有效性检查的语料快照，记录快照 ID 和条目修订；只把必要实体/别名作为纠错上下文传入已有模型协议，输出仍是可核对候选。

当前 ASR 二进制协议没有热词参数，不自行添加不存在的服务端参数。本期先实现已有纠错接口可承载的受控实体上下文。ASR 热词增强只有在适配器明确声明支持后才可开启。

撤回、源失效、主体停用后，新调用不再携带该条目；在途任务在调用/落地前重新验证授权有效性，失效则去掉相关条目或明确失败。已有确认稿、发布稿保持历史快照；治理更新不重写历史会议。

## 5. 声纹治理

### 5.1 两类入口复用同一资源

1. 本人登记：本人授权、用途、期限、样本校验、提交审核。
2. 会议内申请：命名与登记独立保存；指定主体、源版本和片段，服务端核对该主体的有效授权，再从受控原录音提取合格片段。没有主体授权时显示「待本人授权」，不能把负责人勾选当成本人同意。没有原录音时禁止提交样本并解释原因。

内部人员通过稳定企业 ID 关联；外部姓名只作为会议命名，未建立可核验的外部主体授权渠道时，不允许进入实名声纹库。不能因样本提交失败回滚已经成功的会议命名。

### 5.2 列表、审核与历史

- 工作台分「待处理申请」「有效声纹」「已失效」视图；个人侧展示本人的用途与有效期。
- 展示姓名/部门、提交人、来源、有效语音时长、实际样本校验结果、授权期限、审核状态、使用状态、最近处理时间。
- 详情显示授权事实、样本来源与哈希、模型版本、质量校验项目、审核历史。普通接口不返回向量。默认不长期保存新上传的原始样本；会议来源音频继续按原会议权限和保留规则管理。
- 申请流程：待本人授权 → 待审核 → 已通过 / 已驳回 / 需要补充；补充形成新样本版本并重新审核。
- 资源有效性独立计算：有效 / 已撤销 / 已过期 / 主体停用 / 模型不兼容。过期不能继续在页面上仅显示「已通过」。
- 撤销或过期立即停止匹配并清理在线向量，保留授权与审核审计元数据。历史审核意见不能被一列 `review_reason` 覆盖丢失。

### 5.3 主链路匹配

从分离后的同一说话人合格片段提取向量，不能把混合多人整段向量当作某一个人的身份。任务绑定声纹模型/维度/阈值版本，并在产生候选时重新检查声纹有效性。候选包括人员、分数、来源版本和需人工确认标志。

当前语音处理配置使用 `harness-fixture-embedding-v1`，治理默认使用 `harness-embed-v1`。不能简单改名宣称兼容，应统一受控模型目录和指纹，并验证已有向量与实际模型兼容；不兼容的旧样本需要重新登记/评测。匹配结果不自动写会议名单、ACL 或已确认的人员命名。

## 6. 质量评测

### 6.1 三个清晰入口

「数据集」「评测任务」「报告对比」，主按钮为「新建评测」。数据集创建独立弹窗或页面，支持查看样本、删除未提交样本、校验文件和参考标注。保存后版本不可变，需要修改时复制为新版本。

样本使用文件服务/受控样本资源 ID，避免将整批 WAV Base64 塞入浏览器恢复日志。初期保留每版本最多 50 条的执行上限，并由服务端能力返回；超出时明确分版本导入。评测音频规范与登记音频规范分开，不把 3～30 秒登记限制套到所有评测输入。

### 6.2 指标和证据

| 类型 | 正确的输入与评测依据 | 报告必须展示 |
| --- | --- | --- |
| ASR | 音频 + 参考转写 | CER、参考字符数、替换/删除/插入数、失败样本 |
| 说话人分离 | 音频 + 标注时间区间/说话人 | DER 及漏检、误检、混淆；不能以人数相同代替分离正确 |
| 声纹 | 同人/异人配对和真实标签 | 正负样本数、混淆矩阵、FAR/FRR、阈值；可选阈值扫描；门槛只基于声纹分组 |
| 企业实体 | 原文 + 实体/归一参考 | 人名/部门/产品/术语各类准确率或 P/R/F1、错误明细 |
| 纪要 | 会议依据 + 评审标注 | 事实一致、行动项完整、来源支持等分项与人工意见；文本相似度只能标为辅助值 |
| 证据关系 | 结果与已标注来源对应关系 | 覆盖率、回链正确率、失效来源与错误定位 |

所有报告保留实际模型/提示词版本、数据集版本、配置快照、机器输出、参考答案、每样本结果、耗时与错误。当前固定 `harness-embed-v1` 不能充当 ASR 和纪要模型的统一版本证据。

失败/超时计入总样本数；执行完成、质量达标、人工复核是不同状态。混合类型不显示可掩盖某类失败的一个总平均分。未定义该类型的验收规则时显示「仅观察，不可作为发布证据」。具体质量阈值随候选配置在评测前冻结，不能根据结果事后修改通过标准。

### 6.3 运行与恢复

任务列表显示排队、执行、完成、取消、失败，详细报告显示已处理/总数。可自动刷新进度，切换页面后仍可查询；明确失败的样本以新重试运行记录重试，保留原失败证据。新旧版本在同一数据集上比较，不把不同样本集合的分数直接相减。

继续沿用持久任务/租约和实时优先策略；样本之间重查资源配额，不能仅在整场评测启动前检查一次录音是否繁忙。邮件对账不应被长评测整批阻塞。

## 7. 系统配置

- 展示当前生效版本、适用范围、具体参数、审批/发布人、时间、关联评测与变更原因。
- 候选配置只能选择已安装模型、已注册提示词及允许的治理策略；服务地址、凭证、执行命令不在业务表单中输入。
- 流程：编辑草稿 → 选择数据集评测 → 查看差异和证据 → 另一管理员审批 → 发布。修改候选配置会使旧评测/审批失效。
- 配置发布需要逐类满足事先冻结的发布门槛；声纹阈值必须以声纹样本报告独立达标，不能用其他样本高分补足。
- 配置发布接入现有归档及处理/生成配置选择，统一一个生效指针；治理表不能成为与实际运行配置无关的第二套设置。
- 新任务使用新快照；在途任务保留原快照，但授权撤销仍即时重验。回滚展示差异、目标版本及影响范围，创建新修订，不改历史。
- 审计可追踪候选、评测、审批、发布、回滚与失败。初期只管理本次四模块相关配置，知识库组织权限和基础设施运维另循现有职责。

## 8. 页面视觉与交互规范

### 8.1 视觉方向

继承现有 `#111849` 深蓝、`#FF6B1A` 橙、`#F6F6F3` 暖灰及白色面板。保持 56px 顶栏、页面最大宽度 1600px、外边距 24px、标题 26px、正文 14px、说明 12～13px、14px 面板圆角、9px 按钮圆角。橙色集中用于选中导航和当前主操作；避免所有卡片、数字和图标争抢注意力。

管理页结构：标题和说明 → 右侧当前页操作 → 四模块导航 → 紧凑待办摘要 → 筛选/列表 → 详情与操作。列表首页展示真实统计：待审核、待补充、已生效、需处理异常；没有数据时显示空态，不放固定准确率。

长表单移入弹窗/抽屉，页面保留审核对象和任务列表。列表旁的简要详情在桌面采用 320～380px 侧栏；完整审核抽屉宽度 560～640px，表单弹窗宽度 560px；复杂报告使用整页。禁止将数据集编辑、评测提交、报告、发布、回滚全部堆在一张长卡片里。

### 8.2 可用性要求

- 中文状态配合语义色：待审橙、有效绿、补充/过期琥珀、驳回/失败红、撤回灰。状态文字不能仅靠颜色传达。
- 人员显示名称和部门；编号、模型哈希、错误码放详情中的技术信息区。必要时复制稳定 ID，不以原始 ID 代替整列姓名。
- 每次审核/撤回/发布都有独立目标摘要和独立原因输入；不共用跨标签的一个 `reason`。
- tab、筛选、页码和选中对象进入 URL；刷新恢复同一上下文。列表、详情、统计分别加载，一个模块失败不清空其他模块。
- 错误、空态、无权限、尚未接入、有内容但过期均分别呈现；未知写结果保留原请求，不伪造成功、不让用户反复新建请求。
- 主操作受理后回读当前资源；审核拒绝后可编辑重试，网络未知只恢复原操作。草稿离开提醒和焦点管理沿用已有对话框模式。
- 正式验收覆盖 1440×900、1024×768。窄视口重排工具栏，表格在自身容器内滚动，页面不横向溢出；保留键盘操作与清晰焦点。

### 8.3 预览的定位

配套交互设计预览提供四个模块切换、列表筛选和详情查看。示例姓名、数量、配置版本和状态均为设计样例，不是当前数据库结果；预览不调用业务 API。它用于批准新的治理页面基线，不是已完成功能的演示。

## 9. 验收时必须完成的业务闭环

1. 会议纠错卡片 → 结构化反馈 → 本人跟踪 → 管理审核 → 新任务使用有效语料 → 撤回后停止新使用。
2. 会议命名 → 主体授权核验 → 合格样本申请 → 审核/补充 → 个人跟踪 → 新会议候选匹配 → 撤销/过期后停止匹配。
3. 数据集版本 → 对应实际模型评测 → 分类型报告 → 人工复核 → 候选配置独立审批 → 发布 → 新任务生效 → 回滚。
4. 上述流程逐个验证刷新恢复、重复点击、丢失响应、旧修订冲突、失去角色、来源撤回/删除；管理员审核权不增加会议全文权限。
5. 界面截图与本次评审通过的基线比较；后端与模型接入采用真实测试链路。harness 只能证明受控联调，不能据此宣称真实准确率达标。
