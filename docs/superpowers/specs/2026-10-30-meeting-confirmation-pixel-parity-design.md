# 会议确认界面像素复刻设计

## 意图

将现有 `/meeting/:id/confirm` 界面复刻为 `designDocs/智能会议助手1021版.html` 中的“最终确认”页面，并保持附件截图体现的工作台壳层视觉：顶部导航、会议标题区、步骤条、双栏卡片、确认检查区和固定底部操作栏。页面仍然使用现有 Vue 路由、会议信息编辑器、纪要数据和发布状态模型。

## 目标

- 确认页在现有工作台中呈现与原型一致的标题、间距、颜色、字体、卡片边界和固定操作栏。
- 左侧显示可编辑的会议信息，包含会议名称、会议日期、会议分类、摘要和参会人；右侧显示已保存纪要预览。
- 确认检查展示最终确认阻断项、候选/任务计数和必需审阅项，并支持返回纪要编辑及最终确认操作。
- 开发态可使用伪数据验证空数据、校验阻断、成功确认和页面跳转；伪数据不进入生产接口路径，验证后移除。
- 保持现有接口调用、权限校验、恢复命令和发布流程行为不变。

## 非目标

- 不新增知识库发布页面设计，不改变发布接口或发布页布局。
- 不改动会议列表、转写编辑、纪要编辑及后端契约。
- 不增加原型中不存在的字段、按钮、提示或装饰。

## 反目标

- 不以静态截图替代可操作的确认流程。
- 不把伪数据或演示文案写入真实会议信息、纪要或发布接口。
- 不通过新建平行确认路由造成现有状态模型分裂。

## 约束

- 所有修改在 `/home/tanren/ama` 的 `main` 分支完成，不创建或使用 worktree。
- 以 `designDocs/智能会议助手1021版.html` 的 `acFinalPage` 与现有 `prototype.css` 作为视觉基准。
- 继续使用 Vue 3、TypeScript、Vite、现有 CSS token 和 Playwright/Vitest 测试体系。
- 接口服务暂不接入时仅使用开发态伪数据；完成验证后删除伪数据分支，恢复纯净接口逻辑。

## 方案比较与选择

### 方案一：在现有 `PublicationPanel` 确认分支原位复刻（采用）

保留 `usePublication`、`MeetingInfoEditor`、`MinutesWorkspace` 和 `/meeting/:id/confirm` 路由，仅重组 `PublicationPanel.vue` 的确认模板与局部样式。这样能直接复用权限、最终确认命令、恢复状态和纪要数据，视觉改动集中且不会产生第二套流程。

### 方案二：新建独立 `MeetingConfirmationPage.vue`

将原型确认页拆为独立页面，再从 `MeetingDetail` 接入。像素控制清晰，但会重复会议信息编辑和发布准备逻辑，后续需要合并状态与样式，增加回归风险。

### 方案三：独立静态演示页

只复刻原型并使用本地状态，不接入工作台。实现最快，但确认结果无法进入现有纪要发布流程，也无法满足项目级复刻要求。

选择方案一，因为项目已经具备确认路由和接口边界，当前差异集中在呈现层；该方案可以在不改变业务契约的情况下达到视觉和交互目标。

## 交互与实现决策

- `confirm` 阶段继续由 `PublicationPanel` 渲染；状态由 `usePublication` 提供。
- 信息区未最终确认时嵌入 `MeetingInfoEditor`，完成最终确认后显示只读快照。
- 纪要预览只读取 `savedMinutes.body`，无纪要时显示原型一致的空状态。
- 确认检查区使用现有 readiness 数据映射业务文案；阻断时主按钮保持禁用，允许返回纪要编辑。
- 底部 dock 固定在工作台内容底部，保持原型操作顺序和按钮文案。
- 伪数据只用于开发态测试夹具或组件测试，不在运行时覆盖真实接口返回。
