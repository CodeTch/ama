# 我的会议非语音服务设计

## 意图

把当前 `/meetings` 入口及其可达工作台接成真实可回读的非语音业务链。页面已经展示了会议列表、详情、信息抽屉、专题入口、文本导入、背景材料、文本转写、纪要、审阅、最终确认、发布、会议库和反馈等操作；其中一部分仍由 `FuturePanels` 或延期文案占位。用户选择本次覆盖全部非语音页面资源，因此每个可见的非语音增删改查、确认、归组、移除、重试、审核和发布操作都必须经过现有 AMA API/领域服务并能在刷新、重新进入和权限变化后读回真实事实。

## 范围

### 本次目标

- **身份与页面入口**：CAS 登录、匿名/错误/退出、会话撤销、当前身份和权限边界。
- **我的会议**：负责/参与列表、搜索、状态/类别/日期筛选、分页、专题入口、创建、详情读取、信息编辑、企业/外部参会人草稿保存与确认、删除/撤回的领域语义。
- **文本导入与材料**：TXT/Office 文本导入队列、草稿保存/恢复/放弃、背景材料本地上传或知识库版本选择、移除、重试和版本绑定。
- **文本转写**：文本稿读取、编辑、替换、标记、保存、历史/来源查看、确认和冲突恢复。
- **纪要与审阅**：模板读取/创建/编辑/删除（按已有领域规则）、生成受理、候选读取/采用/保留/拒绝/处置、正文与要素编辑、来源审阅、敏感信息排除、行动项负责人和日期保存。
- **最终确认与发布**：最终确认/冻结、冲突恢复、目的地库/目录选择、发布受理、状态查回、失败重试、正式文档只读下载与会议库导航。
- **反馈与专题**：语料反馈创建/读取/补充/审核状态变更或撤销；个人专题创建、编辑、搜索、单项/批量归组、移除和删除。
- **真实验证**：前端单测、API/适配器测试、MySQL 持久化回读、CAS harness 浏览器联调、权限负例、版本冲突、重复请求、错误恢复和两个视口的页面状态证据。

### 明确延期

录音开始/暂停/继续/结束、音视频上传/转码、音频播放与波形定位、ASR、说话人分离/声纹识别，以及依赖音频证据的自动纠错。本轮只保留原型结构、延期/不可用状态和无副作用断言；不得申请麦克风、创建媒体任务或伪造成功结果。

## 反目标

- 不用前端数组、静态 fixture、截图或直接 SQL 写业务结果冒充服务成功。
- 不把 harness 当生产业务实现；只在 AMA 真实请求证明兼容缺口时对固定端口 harness 做最小同步修复。
- 不修改原型 HTML，不为了通过像素差异而放宽遮罩或改变参考图。
- 不创建或使用 `.worktrees`，不切换 `/home/tanren/ama` 的 `main` 分支。

## 现状与缺口

现有代码已经提供会议列表筛选/分页、会议创建、信息与名单命令、导入/上传/材料/转写/纪要/发布 API facade 及大量后端领域服务；`FuturePanels.vue` 中仍有专题、删除、模板、局部生成、背景材料等静态占位，部分页面虽然已有 API facade 但交互没有完整接线。后端 OpenAPI 和数据库已包含多数领域契约，但专题、会议删除和若干模板/反馈写入要以当前迁移与服务边界核实，不能凭按钮推断已完成。

## 方案与取舍

### 方案 A：只补页面交互

改动快，但刷新后丢失、无法验证权限/冲突/幂等/审计，与“真实 API + 持久化回读”要求冲突，弃用。

### 方案 B：按领域补齐所有现有非语音契约（采用）

保留 Vue 组件、`shared/api` facade、Spring controller/service/repository 和现有 CAS/任务/文件适配器；先为每个占位或半接线动作写失败测试，再接入其已批准的真实接口，必要时补最小契约/迁移。按“会议 → 导入/材料 → 转写 → 纪要/审阅 → 最终确认/发布 → 专题/反馈”的顺序逐域交付，每个域都必须有成功、取消、权限拒绝、冲突/重复和刷新回读证据。它覆盖用户选择的范围，同时避免重写已具备契约的后端。

### 方案 C：重写为单一通用 CRUD 服务

可以减少表面 API 数量，但会丢失当前领域的 revision、任务、文件、外部提供方、冻结和发布语义，无法满足已冻结的 OpenAPI/数据库约束，弃用。

## 共同业务规则

- 所有写请求都从当前 ACTIVE CAS 身份开始，按领域需要携带 owner/member ACL、CSRF、Origin、幂等键和 revision/access-revision token。
- 服务端事务先锁身份和 subject/meeting 根，再验证同会议、同版本、同权限和外部结果；失败回滚，不留下半条草稿、授权、文件引用、任务或 outbox。
- 删除采用领域规定的软删/撤回/移除语义：会议根使用 `lifecycle` 与 cancel epoch，专题只允许删除空专题，材料解除会议关联而不删除共享知识库文件，已发布结果冻结为只读。
- 未知 ACK 只能重试原键/查回原结果，不能生成新键绕过；403/404/409/503 必须在 UI 显示真实错误和可执行恢复动作。
- 列表、详情和回读使用 `private, no-store`，任何当前用户不能读取的历史/草稿/外部结果都不能由另一个 endpoint 泄露。

## 页面与服务分层

1. **登录与首页**：CAS callback、会话刷新/退出；`/api/v1/meetings` 负责授权列表与筛选，会议创建/删除/信息/名单命令负责写入。
2. **会议工作台**：workspace/navigation 读取决定权限与阶段；导入 draft、uploads、materials、transcript 端点驱动文件/文本链路。
3. **纪要与审阅**：minutes current/editor-intent/commands、generation/templates/candidates、inspection/reviews、敏感信息与 action-owner 服务驱动可编辑正文和要素。
4. **确认与发布**：final-confirmations、publications、destination libraries/folders、document read 端点驱动冻结、发布和只读文档。
5. **专题与反馈**：新增或接通 topic、meeting-topic grouping、feedback 领域接口；个人专题与反馈不扩大会议 ACL。
6. **语音页**：保持结构和延期态，加入 `getUserMedia` 未调用、无媒体请求/任务/文件写入断言。

## 交付与验证

- 每个领域先新增最小失败测试，再实现 API facade、UI 状态和后端缺口；测试必须观察到功能缺失导致的失败后才能写生产代码。
- Web：`web/tests/unit` 覆盖请求 schema、command 状态、组件取消/错误/恢复；新增或扩展 Playwright E2E 覆盖 CAS 登录→会议→文本导入→材料→转写→纪要→确认→发布→专题/反馈→退出。
- Java：controller wire、core service、adapter/repository、migration/integration 测试覆盖成功、403、409、重复 key、撤权、过期版本、失败回滚和持久化读回。
- 联调：固定 harness HTTP `8792`、SMTP `2525`，保存非敏感请求/状态日志、harness revision、AMA source hash、fixture、视口和命令；遇到兼容缺口只做最小兄弟项目 patch 并跑双方定向回归。
- 像素：原型保持不变，在 1440×900 和 1024×768、DPR 1、同一 Chromium/字体/时区下，为空/非空/错误/弹窗/抽屉/固定底栏保存 reference/actual/diff；任何 `UNTESTED`、`OPEN` 或未经解释的延期项都不计为完成。

## 需要实现者决定的细节

沿用已存在的 OpenAPI、数据库迁移、`shared/api` 响应校验和领域服务；只有当某个可见操作没有对应契约时，才新增最小路径、schema、迁移和服务。删除、专题和反馈的精确状态机/表结构必须先从当前代码与迁移核对，再以失败测试固定，不能由前端文案推断。

## 默认验收边界

若运行前没有新的环境约束，使用仓库现有 `account1` 可重复场景作为 CAS/数据库 fixture，覆盖负责人、已确认成员、非成员、撤权用户和平台管理员。知识库、目录、行动负责人和反馈等外部能力优先使用当前受控 provider；provider 缺失时页面只呈现真实不可用/失败状态，并保留请求与错误证据。发布验收优先验证受理/状态/权限和受控 provider 的正式文档字节；若环境没有文档 provider，则明确登记为环境阻塞，不把 URL 或静态文本当成正式文档成功。
