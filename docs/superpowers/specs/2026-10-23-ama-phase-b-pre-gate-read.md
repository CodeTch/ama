For known-meeting valid recognized operations, graph/config/provider failures wait for the single final genuine READ gate and required same-handle EDIT.

A fixed internal map of exact final core selector record TYPES supplies the existing B03 permission floor independently of provider availability: FileRegistry.CurrentReadRequest READ; ProcessingSourceReader.HistoryRequest and WorkerRequest additional EDIT. This is a permission requirement only, no graph/source/task/scope/open authority. No caller action/boolean/overridden method/provider result can lower it. Current requests always retain strict current-WORKING semantics; copied historical IDs cannot select another operation. A real configured authorizeRead can restrict further; no absent provider is constructed or substituted.

Only Prepared proceeds with complete authentic locked graph, all sources, all tasks before attempts, once-only finalization, successful commit and private outside-transaction open. Fatal aborts after authorization even if a legacy reference would otherwise qualify. Genuine current Ineligible permits only an independently valid unchanged legacy reference after its own original checks/commit. Legacy-only construction/download has no new complete budget/protocol prerequisite. New planned reads against missing/legacy/ambiguous support remain recognized and fail safely after the floor checks, with no complete downstream acquisition/open.

Prospective tests in the exact R2 and original/R1 reviews remain implementation gates: all roles and selector types across provider failures, changed/foreign graph/preparation, exact reference sets/overflow, cancellation, narrow legacy fallback, no second gate or hash under roots, finalizer/commit-before-open and live-worker/history differences.
