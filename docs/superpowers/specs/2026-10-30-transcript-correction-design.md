# 转写校正界面像素复刻设计

## 意图

把原型中的“转写校正”会议工作台复刻到现有 Vue 页面：保留会议头部、五步流程、左侧媒体与说话人区、右侧转写稿区及固定底部确认操作，让 1440×900 和 1024×768 视口下的结构、尺寸、间距、颜色、文案和可达交互与原型一致。

## 目标

- 以 `docs/acceptance/a/prototype/*/original-transcript-page.png` 和原型 HTML 最终覆盖样式为视觉基准。
- 复用现有 `MeetingDetail.vue`、`MeetingProgress.vue`、`TranscriptEditor.vue`、`TranscriptForm.vue`、`TranscriptPlayer.vue`，不新增第二套生产工作台。
- 在本地开发模式下允许用明确的演示数据呈现长转写、说话人、播放器和待确认数量，支持搜索、待确认筛选、标记切换、片段编辑、批量替换、播放控制和底部确认按钮的交互演示。
- 真实接口路径保持现有契约和权限边界；伪数据开关默认关闭，完成视觉开发后可移除，不写入生产接口逻辑。

## 非目标与反目标

- 不扩展纪要、发布、专题、反馈或会议库页面。
- 不伪造真实音频、ASR、声纹或实体纠错成功；无真实媒体时必须显示原型对应的不可用/延期状态。
- 不为了追求截图而嵌入原型 HTML、截图或复制一套独立路由。

## 约束

- 所有工作在 `/home/tanren/ama` 的 `main` 分支完成，不创建 worktree。
- 视觉基准使用仓库内不可变原型图，应用使用现有字体栈和 token。
- 外部接口若需联调，使用 `ama-integration-harness` 固定端口；harness 仅用于调试，不作为业务权威。
- 伪数据只存在于本地开发边界，清理后默认回到接口读取。

## 构建方案

1. **在现有工作台上最小修正（采用）**：修正现有工作台的布局和控件样式，补齐演示所需的受控本地数据适配。优点是保留接口契约、权限、草稿恢复和既有测试；改动集中，后续联调不需要迁移页面。
2. **新增独立演示路由**：像素控制直接，但会重复工作台结构和交互，形成与真实页面分叉的维护负担。
3. **只重写转写卡片**：改动最小，但无法覆盖原型的会议头、流程条、左栏和固定底栏，不能满足整页 1:1。

采用方案 1，因为原型页面与现有工作台是一一对应的，且当前组件已经承载了编辑、搜索、标记、保存、冲突恢复和确认边界。

## 实现要点

- 将页面内容区调整为原型的固定头部与可滚动工作区，保留 300px 左栏和弹性转写列；在窄视口按原型堆叠。
- 对齐会议标题/状态、五步流程、长转写说明条、播放器卡、说话人卡、转写工具栏、连续段落和固定确认条的几何与视觉 token。
- 让演示段落包含原型所需的姓名、时间、文本和标记；API 数据缺少说话人或媒体时仍走真实空态，不从 UI 猜造业务事实。
- 交互改动只作用于现有组件事件：输入搜索、待确认筛选、播放/定位、标记、片段编辑/替换、保存和确认；所有临时演示状态集中在开发开关内。

## 验证

- `npm run typecheck`、`npm run build`、相关 transcript 单元测试。
- 使用 Playwright 在 1440×900 和 1024×768 捕获转写工作台，对照原型图检查主结构、固定底栏、滚动和交互状态。
- 开发开关关闭后确认源码不包含伪数据注入路径，默认请求仍由现有 API client 发出。
