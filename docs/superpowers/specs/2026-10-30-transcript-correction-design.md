# 转写校正界面像素复刻设计

## 意图

把原型中的“转写校正”会议工作台复刻到现有 Vue 页面：保留会议头部、五步流程、左侧媒体与说话人区、右侧转写稿区及固定底部确认操作，让 1440×900 和 1024×768 视口下的结构、尺寸、间距、颜色、文案和可达交互与原型一致。

## 目标

- 以 `docs/acceptance/a/prototype/*/original-transcript-page.png` 和原型 HTML 最终覆盖样式为视觉基准。
- 新增一个本地独立演示路由 `/transcript-correction-demo`，按附件呈现“未命名会议 / 转写待处理 / 空转写正文”状态。
- 演示页提供附件中可见控件的最小交互：返回、流程步骤、重新读取、历史展开和服务未接入提示；伪数据只属于演示路由和测试。
- 真实 `MeetingDetail.vue`、`TranscriptEditor.vue`、`TranscriptForm.vue`、`TranscriptPlayer.vue` 保持现有接口契约和权限边界，不注入演示数据。

## 非目标与反目标

- 不扩展纪要、发布、专题、反馈或会议库页面。
- 不伪造真实音频、ASR、声纹或实体纠错成功；无真实媒体时必须显示原型对应的不可用/延期状态。
- 不为了追求截图而嵌入原型 HTML 或截图；独立演示路由只复刻目标空态，不扩展长转写、实体纠错或其它页面设计。

## 约束

- 所有工作在 `/home/tanren/ama` 的 `main` 分支完成，不创建 worktree。
- 视觉基准使用仓库内不可变原型图，应用使用现有字体栈和 token。
- 外部接口若需联调，使用 `ama-integration-harness` 固定端口；harness 仅用于调试，不作为业务权威。
- 伪数据只存在于本地开发边界，清理后默认回到接口读取。

## 构建方案

1. **在现有工作台上最小修正**：修正现有工作台的布局和控件样式，补齐演示所需的受控本地数据适配。优点是保留接口契约、权限、草稿恢复和既有测试；改动集中，后续联调不需要迁移页面。
2. **新增独立演示路由（采用）**：以只读演示组件承载附件空态，伪数据不进入真实工作台和 API client，像素控制最直接，也便于接口未接入时独立验收。代价是存在一套明确隔离的演示视图，不能把它当作真实接口页面。
3. **只重写转写卡片**：改动最小，但无法覆盖原型的会议头、流程条、左栏和固定底栏，不能满足整页 1:1。

采用方案 2，因为附件是未命名会议的空转写状态，真实接口尚未接入；独立演示页能完整复刻该视觉状态，又不会把伪业务事实混入真实工作台。

## 实现要点

- 新建演示组件复用现有 `tokens.css`、`prototype.css` 和 `parity.css` 的页面 token，不嵌入原型 HTML。
- 对齐会议标题/状态、五步流程、播放器空卡、说话人空卡、转写正文空卡和历史折叠的几何与视觉 token。
- 交互只覆盖附件可见控件；“编辑会议信息”“保存”“更多”以诚实的未接入提示响应，不伪造保存结果。
- 真实工作台保持原样，伪数据仅从演示组件和 Playwright fixture 可达。

## 验证

- `npm run typecheck`、`npm run build`、相关 transcript 单元测试。
- 使用 Playwright 在 1440×900 和 1024×768 捕获转写工作台，对照原型图检查主结构、固定底栏、滚动和交互状态。
- 开发开关关闭后确认源码不包含伪数据注入路径，默认请求仍由现有 API client 发出。
