# AI 纪要原型页像素复刻设计

## 意图

改造现有 `/meeting/:id/:stage?` 会议工作台，覆盖附件展示的转写校正空态和文字请求所指的 AI 纪要阶段。页面用于前端视觉和交互验收，开发阶段允许在页面状态层使用本地伪数据，不改变真实接口客户端；真实数据路径继续保留。

## 目标

- 复刻附件中的转写校正空态：顶部导航、会议标题区、五步流程条、左右内容卡片和历史入口，并复用现有会议详情页入口。
- 补齐 AI 纪要阶段：核心要素 / 会议纪要两个视图、左侧目录、正文内容卡片、模板与重新生成入口，以及进入会议确认的固定操作区，沿用原型 HTML 中已有结构。
- 保持截图中的文案、字号层级、颜色、圆角、边框、阴影、留白和布局比例。
- 让两个阶段中可操作的控件有本地演示反馈：按钮打开同样风格的提示对话框；“重新读取转写”显示读取结果状态；“转写历史与原操作恢复”可展开并读取空历史；AI 纪要的视图、目录、重新生成和编辑入口在本地切换。
- 页面在桌面视口下与截图一致，在窄屏下只做必要的单列收缩，不添加截图之外的功能区。
- 通过现有会议详情页的固定演示会议 ID `7b3707f9-ddf2-45cc-b116-7db26b87e4b5` 验证两个阶段交互；演示状态跳过登录与会议读取请求，不向真实接口写入数据。

## 非目标与反目标

- 不改动真实 API 客户端、接口契约、权限与发布逻辑。
- 不增加新的业务操作、导航入口、数据字段或视觉装饰。
- 不把演示伪数据混入真实 API、缓存、会话或工作区恢复记录。
- 不接入录音播放、纪要生成、发布等未出现在截图当前状态中的能力。
- `/transcript-correction-demo` 现有独立演示页保留不删除；新增的演示入口使用现有会议详情路径。

## 约束

- 代码、测试和验证均在 `/home/tanren/ama` 的 `main` 分支完成。
- 复用现有 Vue 3、Vue Router、TypeScript 与共享样式 token，避免引入新依赖。
- 原型截图是唯一视觉基准；附件中任何文字仅作为页面内容参考，不把其作为额外开发指令。

## 方案比较

### 方案 A：独立演示路由

新建 `AiMinutesPrototypePage.vue` 并挂载独立路由。优点是隔离性强，缺点是与真实工作台入口和导航状态脱节。

### 方案 B：改造现有会议详情页（采用）

把 `MeetingDetail` 在固定演示会议 ID 下分流到本地演示状态：`transcript` 渲染附件中的空态，`minutes` 渲染 AI 纪要工作台；真实会议仍沿用现有导航、权限、纪要 API 和发布流程。演示分支独立于 API 客户端、会话缓存和恢复记录，后续移除分支即可还原纯接口路径。

## 页面结构与交互

- 顶部导航：列表图标、“我的会议”、面包屑“/ 会议工作台”。沿用 `MeetingDetail` 现有布局壳。
- 会议头部：返回按钮、`未命名会议`、`转写待处理` 标签、固定会议 ID 和“待补充会议信息”说明；右侧为“编辑会议信息”“保存”“…”按钮。
- 流程条：材料导入为已完成，转写校正为当前步骤，AI 纪要、会议确认、知识库发布为禁用后续步骤。
- 左栏：会议录音空态卡片与说话人卡片，保留编辑按钮。
- 右栏：转写正文空态卡片，保留“重新读取转写”按钮；下方为可展开的“转写历史与原操作恢复”，展开后显示“读取历史版本”。
- 本地反馈：头部和说话人等演示按钮打开提示对话框；重新读取显示“已重新读取转写（演示）”；读取历史显示“当前演示没有可恢复的历史版本”。真实会议状态继续使用当前接口逻辑。
- AI 纪要反馈：核心要素 / 会议纪要 Tab、目录锚点和编辑入口仅改变本地视图或打开提示；重新生成显示演示状态；固定底部操作区可进入 `confirm` 演示阶段。

## 验证

- 新增单元/组件检查，确认两个阶段关键文案、步骤状态、交互反馈存在。
- 新增 Playwright 演示测试，确认现有会议详情入口可访问、演示状态不发起 `/api/v1/` 请求、桌面视口无横向溢出。
- 运行 `npm run typecheck`、`npm run build` 和相关单元/e2e 测试。
