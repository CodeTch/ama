# AMA B 阶段后续范围设计：逐页像素复刻、非语音功能实装与 CAS 联调

## 当前裁定

本设计是 2026-10-30 对 B 阶段后续工作的补充和收敛入口。它保留已有 B 阶段源码、测试和受控本地链路证据，但重新定义后续页面与功能验收范围。旧计划中“页面先做、功能以后补”“不做整页像素比对”以及把录音/音视频作为本轮必做功能的表述，均由本设计覆盖；旧文档中的历史结果不改写。

当前总门仍为 `NOT ACCEPTED`。只有本设计规定的非语音页面像素、真实 CRUD、CAS harness 联调和回归全部达到要求，才可以关闭本轮 B 后续工作。

## 意图

把 B 阶段剩余工作收敛为一条可复核的交付线：以原型最终渲染为唯一视觉基准，逐页完成 1:1 像素级前端实现；对页面上可见的非语音增删改查动作接通 AMA 的真实 API、事务和持久化；使用并行开发的 `ama-integration-harness` 完成 CAS 和相关接口的浏览器联调、错误验证与兼容修复。

这样可以继续交付可操作的会议产品页面，同时明确语音能力的延后边界，避免静态占位或 harness 假成功被误记为产品完成。

## 目标

- 原型中所有可达页面、弹窗、抽屉、提示层、展开/折叠、滚动区域、固定底栏和只读状态完成同环境逐页像素比较。
- 除语音相关能力外，页面上出现的创建、读取、修改、删除、确认、归组、移除、重试、审核和发布动作均由真实 AMA 接口完成，并在刷新、重新登录和权限变化后保持正确结果。
- 所有受 CAS 身份保护的 B 页面 API（会议、信息、名单、文本导入、材料、转写、纪要、反馈、专题和发布）在浏览器联调时使用固定端口的 `ama-integration-harness` 建立真实会话；涉及材料/导入页面的跨项目请求也必须经过同一联调边界，失败状态如实呈现。
- 任何由实际请求暴露的 harness 兼容缺口都有最小同步修复、兄弟项目回归和 AMA 侧证据；固定端口与 harness 的模拟器定位保持不变。
- 每个页面和功能都能追溯到页面矩阵、API/存储映射、测试命令和截图/日志证据。

## 明确延期的语音范围

本轮不实装需要麦克风、音频或视频处理能力的业务功能：实时识别、录音开始/暂停/继续/结束、音视频上传与转码、音频播放/波形/时间定位、ASR、说话人分离或声纹识别、依赖音频证据的自动纠错和说话人绑定。语音页面仍须完成原型布局、文案、静态状态和不可用/延期状态的像素复刻；延期状态必须可解释，不能伪造成功、任务或媒体结果。

文本文件导入、文本转写稿的人工编辑/保存/确认、纪要文本和其他不依赖音频输入的 CRUD 仍属于本轮范围。若某个说话人字段只能由音频识别产生，则延期；若它只是已存在文本标签的人工改名，必须按非语音 CRUD 实装并持久化。

## 非目标

- 不把 `ama-integration-harness` 当作生产接口、业务规则或真实企业 CAS 的权威实现。
- 不改变 harness 固定端口设计：HTTP `8792`、SMTP `2525`；不重建第二套模拟器启动方式。
- 不把真实企业模型、真实企业知识库、生产 S3、双 MySQL、双活或容量资格提前伪装成 B 后续已通过。
- 不修改原型 HTML 以消除差异，不使用静态截图、前端 mock、直接 SQL 写业务结果或宽松遮罩掩盖失败。
- 不在本轮实现延期的录音、ASR、音视频处理和依赖音频的说话人能力。

## 方案与取舍

### 方案 A：继续沿用旧 Demo 分段，只补页面外观

改动小，但无法满足用户要求的“全部非语音 CRUD 实装”，也会让多个旧计划继续对像素门槛和语音范围给出相互冲突的结论，不采用。

### 方案 B：新增当前总计划，旧计划保留为历史并指向它（采用）

新增一份当前设计和实施计划，统一页面矩阵、非语音 CRUD、语音延期和 CAS harness 边界；旧计划、旧验收证据保留原文，在顶部标明本设计覆盖的范围。这样既能保留审计时间线，也只保留一个当前执行入口。

### 方案 C：重写全部历史计划和验收记录

可以减少阅读时的旧文字，但会破坏已经产出的证据边界和时间线，无法区分历史通过范围与当前新增要求，不采用。

## 运行与联调边界

- 主项目在 `/home/tanren/ama` 的 `main` 分支工作，不创建或使用 `.worktrees`。
- 兄弟项目在 Windows/WSL 视角为 `\\wsl.localhost\Ubuntu-24.04\home\tanren\ama-integration-harness`，Linux 路径为 `/home/tanren/ama-integration-harness`。
- harness 使用固定 HTTP `127.0.0.1:8792` 和 SMTP `127.0.0.1:2525` 启动；AMA 的 Web/API/管理端口可以按本轮空闲端口配置，但 CAS 回调必须加入 harness 的精确白名单。
- AMA 的产品契约、权限、状态机、幂等、修订令牌、CSRF、文件字节校验和持久化由 AMA 源码与本设计决定。harness 只提供可重复的 CAS、材料或外部平台模拟响应。
- 只有在 AMA 真实请求、响应状态和日志证明存在兼容缺口时，才在 harness 增加最小接口或修复；同步增加 harness 定向测试和 AMA 回归，保留兄弟项目已有脏改动，不重置、不清理、不改端口。
- 联调报告记录请求方法、路径、状态、关键非敏感字段、失败原因、ticket/版本是否一次性消费和页面错误；不得记录密码、TGT、ST、Bearer 或私钥。

## 页面和功能分层

页面矩阵按以下顺序建立，每个条目都要登记原型入口、稳定 fixture、截图状态、可见操作、AMA API、持久化事实、权限和负例：

1. 登录、会议列表、搜索/筛选、分页、专题入口、创建和删除确认。
2. 会议详情、会议信息抽屉、日期/分类、企业与外部参会人、名单保存/确认/撤回。
3. 文本导入弹窗、主文件顺序、背景材料选择/移除/重试、草稿恢复、文本转写稿编辑/替换/确认。
4. 纪要模板、生成候选、正文和要素编辑、来源审阅、行动负责人、最终确认和冻结。
5. 发布目的地、发布状态、未知回查、正式文档只读、成员/非成员/撤权结果。
6. 专题/归组、会议知识库、个人模板、局部生成和反馈页面中所有可达的非语音状态。
7. 录音、音视频、播放和 ASR 页面：只做同样的结构/文案/延期状态像素复刻，不执行语音业务。

## CRUD 证明规则

“有按钮”不等于“功能已实装”。每个非语音可见动作必须满足以下闭环：

1. 浏览器触发真实 AMA 请求，带当前会话、CSRF、owner/meeting scope、幂等键和 revision token（适用时）。
2. API 返回符合契约的成功或失败状态；成功由业务事务和真实存储产生，失败不留下部分写入。
3. 刷新、重新进入、重新登录或使用另一权限身份读取时，结果与服务端事实一致。
4. 删除遵循领域规则（软删、撤回或不可变只读时按正式状态表达），并保留审计、授权和 outbox 副作用；不能用前端数组删除冒充删除。
5. 每项至少有正常、取消/关闭、权限拒绝、冲突或重复请求、失败恢复中的适用证据；不适用的异常要写明理由。

## 通过门槛

本轮 B 后续必须同时满足：

- 页面矩阵中所有非语音页面/状态在 1440×900 与 1024×768、DPR 1、同一 Chromium/字体/语言/时区下，reference/actual/diff 的精确像素比较通过；语音页面的静态与延期状态同样通过。
- 页面上所有非语音 CRUD 行为有真实 AMA API、MySQL/文件/受控提供方持久化和刷新回读证据；不存在仅前端状态、静态假成功或未接线按钮。
- 固定端口 harness 的 CAS 登录、登出、ticket 单次消费、service 白名单、身份同步、过期/错误/拒绝路径和相关材料请求有真实浏览器证据；AMA 与 harness 定向回归均通过。
- 前端类型检查、构建、相关 Web 单测；API/适配器/契约测试；本地应用启动器和导入联调脚本均通过。任何未执行、零测试、跳过或仅静态构建的结果都不能计为通过。
- 延期语音范围在矩阵中标记 `DEFERRED_VOICE`，不计入本轮语音功能完成数，也不允许它阻塞非语音 CRUD；但其页面的视觉和延期状态必须通过，且不能写成整体功能完成。
- 任一 `OPEN`、`FAIL`、`UNTESTED` 或未经解释的 `DEFERRED` 仍存在时，总状态保持 `NOT ACCEPTED`。
