# AMA 导入会议页与 CAS Harness 联调设计

## 意图

打通当前 AMA 项目的“导入会议”页面与 `/home/tanren/ama-integration-harness` 的 CAS 联调环境，验证从企业 CAS 登录到导入页真实请求链路，并修复影响启动、会话、会议创建、上传/草稿恢复、开始处理和背景材料读取的契约问题。harness 只承担可重复的外部平台模拟，不作为生产接口实现或产品行为权威。

## 目标

- AMA 主项目可以在本地启动，并把 CAS 请求发往固定的 `http://127.0.0.1:8792`。
- CAS 登录、一次性 ticket 校验、AMA 会话建立和登出回调使用精确回调地址，浏览器得到真实 HttpOnly 会话。
- 登录后的导入页可以创建会议、读取导入能力和草稿，上传真实 TXT 主文件，保存并刷新恢复，提交真实导入命令并看到受理状态。
- 导入页的背景材料入口能读取 harness 提供的知识库/文档页；失败、未授权、版本不一致时显示真实失败，不伪造成功。
- 为本轮发现的跨项目契约问题增加可重复回归，便于后续并行开发继续联调。

## 非目标与反目标

- 不把 harness 的种子数据、模拟模型输出或兼容端点当成真实企业接口的实现依据。
- 不改变 harness 的固定 HTTP/SMTP 端口设计（HTTP `8792`、SMTP `2525`）。
- 不扩展录音、生产模型质量、真实企业 CAS、真实知识库权限或导入页之外的产品范围。
- 不覆盖、重置或清理 harness 工作树中已有的并行开发改动。

## 约束

- AMA 使用现有 Vue/Spring/MySQL/Worker 和启动器；harness 使用现有 FastAPI/SQLite 服务。
- AMA 的本地 Web/API/管理端口可使用本轮专用空闲端口，CAS 回调必须加入 harness 的现有白名单；固定的 harness 端口不改。
- 所有写请求仍使用现有会话、CSRF、幂等键、owner/meeting scope、revision token 和真实文件字节校验。
- 验证优先使用现有单测、`tools/dev/local_login_smoke.mjs`、导入行为脚本和 API 请求日志；浏览器运行时不可用时保留明确的阻塞证据，不以静态构建代替联调成功。

## 现状根因

当前 `application.yml` 在文件顶部和末尾各声明一次顶层 `cas:`。Spring Boot 使用 SnakeYAML 的重复键拒绝策略加载配置，因此本地启动在读取配置阶段失败。修复应合并为一个 `cas:` 映射，保留 `enabled`、origin、登录/退出回调、身份属性、超时和会话时长配置，并让本地启动器提供最终值。

## 方案

考虑过三种路径：

1. 只修 AMA 并把 harness 当黑盒。实现简单，但不能验证材料端点等已经存在的跨项目契约。
2. 以 AMA 请求/响应校验为准，修 AMA 配置和联调回归；只在实际缺失时给 harness 增加最小兼容端点与测试，固定端口保持不变。本轮采用此方案，因为它能区分产品契约问题和模拟器问题。
3. 只做一次手工浏览器冒烟，不增加回归。无法防止同一配置或契约问题再次回归，因此不采用。

## 实施边界

- 主项目：合并 CAS 配置；新增配置加载回归测试；如联调暴露导入页/会话契约问题，按失败请求增加最小测试和修复。
- Harness：只为已被 AMA 真实请求证明缺失的路径、字段或错误响应增加契约测试和实现；保留固定端口和当前脏改动。
- 验证：先单测/类型检查/构建，再以固定 harness 启动主项目，记录 CAS 登录、会话、会议和导入请求的状态、关键响应字段、harness 请求日志以及失败原因。

## 完成判定

配置重复键回归通过；AMA 与固定端口 harness 均健康；真实登录建立会话；导入页创建会议后能完成至少一个有效 TXT 文件的真实上传、保存/恢复和导入受理；背景材料读取成功或在 harness 明确返回的失败状态下诚实呈现；AMA、harness 相关测试和构建均有新鲜输出作为证据。
