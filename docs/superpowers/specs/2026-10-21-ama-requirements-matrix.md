| CAP-07 | 模块一材料调整 / P0 | 取消不生效，明确应用后重新增强 | 材料修订与有效集合分离；旧人工稿保留，新结果待核对 |

| CAP-12 | 模块一名单与授权 / P0 | 草稿名单不授权；确认后才生效 | roster_revision 和 meeting_acl；新旧名单变更、同名人员、撤权测试 |

### 2.4 知识库发布与治理状态

| 编号 | 原文位置 / 优先级 | 必须保留的行为 | 架构归属及主要验收 |

| PUB-01 | 模块四发布配置 / P0 | 可发布库/目录搜索、选择、权限与信息检查 | 公司知识库适配器；不新建第二套知识库；版本与目录变更重验 |

| PUB-03 | 模块四发布执行 / P0 | 进度、成功反馈、跳转、失败重试 | publication/attempt/outbox；双击、节点切换、重复请求只形成一份有效发布 |
| PUB-04 | 模块四超时重试 / P0 | 响应未知先查询真实结果 | 外部业务幂等键＋查回；先成功后超时不能再建一份 |
| PUB-05 | 模块四成功态 / P0 | 成功后只读，不允许再次发布 | 本地与外部文档映射唯一，页面/API 同时限制 |
| PUB-06 | 模块四治理记录 / P0 | 撤回/废止原因、操作记录及状态展示 | authority 状态、同步任务、最小审计，管理权限范围明确 |
| PUB-07 | 模块四撤回/废止 / P0 | 普通回看、下载、检索和 AI 引用失效；不提供恢复 | 本地先阻断、外部对账；所有者也不得走普通接口绕过 |
| PUB-08 | 模块四知识库来源权限 / P0 | 发布和引用不得扩大原材料/录音权限 | 知识库正文 ACL 与会议原始材料 ACL 分开验证；不能仅隐藏按钮 |

## 3. 架构需求对应

| 编号 | 用户要求 | 设计落实及验收证据 |
| --- | --- | --- |
| ARC-01 | 100 场实时会议、每场一个采集端、300 在线 | 整体架构 NFR-01/05/10；应用模拟模型与真实模型负载分别报告 |
| ARC-02 | 两台 16 核 32GB RHEL 8.10 | 单台承载故障后负载的资源预算；独立核实磁盘、网卡和宿主隔离 |
| ARC-03 | MySQL 私有/公司平台；文件存储本地/S3 两种方式，S3 可私有或公司平台 | 数据库来源与文件后端独立配置；统一 FileStoragePort；支持组合的集成、迁移和恢复测试 |
| ARC-04 | 私有部署只用两台且自动恢复 | 应用双活；数据单写，同步卷＋集群隔离；禁止无隔离强制提升 |
| ARC-05 | 模型服务沿用现有平台 | 独立适配器；格式/错误/容量契约；未确认的 tokens、流式、实名不造数 |
| ARC-06 | 对接现有知识库 | 材料引用、版本锁定、发布、外部权限/治理状态同步；不自建知识库管理 |
| ARC-07 | 公司统一登录与人员目录，协议稍后提供 | identity adapter；稳定企业 ID、停用/撤权、映射；联调前冻结协议 |
| ARC-08 | 高响应、高稳定、高可用、高安全 | NFR-02…09 和分层验收；数字为建议目标，不能仅凭组件选型宣布达标 |
| ARC-09 | 运维隔离接口先列前置条件 | 部署前置 PR-01…PR-08；继续业务设计，不视为已取得自动切换能力 |
| ARC-10 | 本地文件也满足双机自动恢复要求 | 活动文件服务访问本地同步卷，备用不挂载；切换后按同一文件 ID 续读/续传；禁止将两份独立应用目录或异步复制当成已验证 HA |

## 4. 差异、缺口与建议决策

以下没有默认为全部已批准。已在原文明确的业务规则直接保留；确需补充的行为由产品/接口/运维责任方在对应阶段确认，不让无关模块一起等待。

| 编号 | 差异或缺口 | 本草案处理建议 | 决策方 / 最迟阶段 |
| --- | --- | --- | --- |
| D-01 | 转写需求描述右侧纠错建议区，原型最终渲染包含行内纠错 | 保留全部纠错能力；优先复刻最终视觉，详细 UI 规格确认布局，不从旧脚本推断生产行为 | 产品 / 转写 UI 规格 |
| D-02 | 导入页明确不再内嵌信息区，文档仍留旧折叠信息章节 | 按新入口规则使用统一信息抽屉，不恢复已取消的内嵌区域 | 产品 / 采集 UI 规格 |
| D-03 | 实际会议日期用于列表，但基础信息枚举未一致纳入日期 | 单独存业务日期，未知不填造；建议在信息抽屉增加可选日期编辑，待确认 | 产品 / 信息字段规格 |
| D-04 | 多主文件、音视频混合、转写与音频混合的组合规则未定 | 保留多段排序；按输入类型能力表逐项确定合法组合、格式、大小、时长，不预设任意混合均可合并 | 产品＋模型 / 文件接口冻结 |
| D-05 | 原文不设部分名称上限，但工程必须有请求/解析保护 | 不增加表单产品字数上限；设置可解释的技术资源限额并公开能力配置 | 产品＋安全 / 上传与输入规格 |
| D-06 | 自动保存、显式保存及保存指示在不同页面有差别 | 对每个编辑区域定义保存时机；纪要按原文自动保存并有离开提醒；确认和导出始终基于已保存版本 | 产品 / 编辑交互规格 |
| D-07 | 纠错零待处理才能确认；失败后的原文降级确认仍是待补充项 | 默认不绕过纠错前置；是否提供显式降级路径需产品批准及审计规则，不能静默跳过 | 产品 / 转写确认规格 |
| D-08 | 模块三泛称发布后修订，模块四明确发布后只读、禁止再发布/恢复 | 一期按具体发布规则只读；保留历史，不新增发布后修订工作流 | 产品 / 发布规格 |
| D-09 | “七类要素”与敏感/背景/关联材料目录同时出现 | 七类主体：概述、讨论、结论、行动、风险、待确认、分歧；其他为辅助目录，不遗漏内容 | 产品 / 要素 schema |
| D-10 | 邮件只有范围条目，没有收件人/正文/附件规则 | 建议受控链接邮件；接口、收件范围、模板、发送授权、幂等与结果未知处理均须补充 | 产品＋邮件平台 / 邮件规格 |
| D-11 | 模块六仅有标题，运营治理缺完整细则 | 保留反馈审核、声纹治理、评测、配置；单独细化角色、状态、数据用途、评测集与发布/回滚规则 | 产品＋安全 / 治理子项目 |
| D-12 | 模型接口没有已确认的流式协议、字级时间戳、吞吐及在线实名 | 先验证短窗口 HTTP；不能保证的定位/身份明确降级展示；实时目标不达标则提请调整模型能力 | 模型平台 / 实时可行性验收 |
| D-13 | 后台录音未覆盖所有浏览器、休眠和关闭行为 | 站内跳转保持；系统休眠/关闭不承诺继续；设备/浏览器限制在验收中列出 | 产品＋桌面运维 / 录音浏览器基线 |
| D-14 | 知识库幂等、撤回事件和权限同步接口尚未提供 | 采用稳定业务键查回、签名事件与对账；缺关键能力不得伪造发布/失效成功 | 知识库平台 / 发布联调 |
| D-15 | 外部人员、行动项负责人映射和声纹授权规则未完整 | 外部身份与企业账号分开；没有企业账号不获得系统访问；实名候选人工确认 | 产品＋安全 / 人员和声纹规格 |
| D-16 | 文档格式和 OCR 能力尚未冻结 | 建立支持矩阵；扫描件无 OCR 明确不可解析；来源定位须随解析保留 | 产品＋运维 / 材料解析规格 |
| D-17 | 历史不得自动清理，但临时数据、备份和删除保留规则不完整 | 区分业务历史与已校验无引用的中间产物；备份删除/审计保留单独确认 | 产品＋安全＋运维 / 删除与备份验收 |
| D-18 | 标题与会议名称在人工修改后的联动规则不明确 | 分开版本化；建议人工改过标题后不再自动覆盖，最终以已保存标题确认发布 | 产品 / 纪要编辑规格 |
| D-19 | 用户已明确新增本地文件系统，与早期仅 S3 要求不同 | 按最新要求支持 local / s3；数据库仍为 MySQL。文件后端与数据库来源独立；本地不要求部署 S3，自动恢复条件继续适用 | 支持范围已由用户确认；适配器及 HA 细节随本草案评审 |

## 5. 后续维护规则

每个详细规格、任务和验收用例引用本表编号。实现状态更新必须附代码位置和验证证据；仅有页面或模拟数据不算功能完成。需求变更记录影响的状态、权限、来源、历史、外部副作用及迁移方式。

一期 P0/P1 的具体交付顺序参见整体架构第 15 节；上述缺口在所属子项目启动前补齐，基础设施前置条件在部署/故障验收前补齐。整体架构评审不替代尚缺的业务细则，也不意味着当前可以宣称所有功能已确定。
