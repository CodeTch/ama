# D02 信息建议执行补充

继续使用阶段 D 总计划的明确采纳/拒绝接口。没有用户自动覆盖授权；不另外编造公司 LLM 接口。异步 MINUTES_GENERATE 的真实、已验证候选提供名称和概览建议：名称来自候选标题，摘要仅来自 OVERVIEW 要素，不把完整正文复制为摘要。生成时间、候选、输入指纹、确认转写版本随建议返回。分类没有可靠映射时提示待选择，匿名说话人不自动成为企业参会人。

- 候选成功写入的同一事务生成 NAME/SUMMARY 建议索引；不修改人工信息。
- 新的会议自有建议表记录 PENDING/ACCEPTED/REJECTED。旧候选索引回填只建立关联，读取仍需现有完整来源证明，不因回填而获得有效性。
- owner 专用列表/详情在现有来源门禁后获取建议；源确认版本过时不允许采纳。采纳仅更改选中的一个字段，保留其他已保存字段、名单草稿和原授权。
- decision 命令带 expectedRevisionToken、ACCEPT/REJECT、原幂等键；与根锁、来源版本重验、不可变信息版本、任务 fence、审计/outbox 同事务。重复原键返回原回执，不同请求冲突。拒绝不修改人工信息，也不隐式授予名单权限。
- 前端保存/重试使用持久原请求。存在未保存信息或未决保存时不直接发送采纳，保留草稿并提示先保存；迟到建议只更新建议区。
- 来源不可用、权限失效、超预算维持拒绝。清理表加入 D07 所有权顺序并验证不影响其他会议。

完成证据须包括实际 CAS、生成任务/候选来源、单字段采纳、拒绝、人工信息保留、失 ACK 原请求恢复、过期/外人拒绝、删除清理。该补充不是已完成声明。
