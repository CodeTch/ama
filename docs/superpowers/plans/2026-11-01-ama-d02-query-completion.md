# D-02 查询收口执行补充（2026-11-01）

沿用阶段 D 总计划与数据库设计的公共关系 F。用户已授权自主取舍、main 原地单代理执行；不创建分支或工作树，不把当前兄弟项目当公司接口权威。

当前缺口：分页先扫描后筛选，空页仍可有后续页；没有同条件 total/stageCounts/topicGroups；人员权限虽逐行核验，但不适合作为十万会议统计实现。

决定采用参数化公共 SQL 关系，绑定身份、当前确认名单 READ grant、生命周期/治理、当前投影及同一组筛选；分页与所有统计均使用此关系的同一数据库一致性视图。字面 LIKE 使用 = 转义，日期只读取实际 DATE。保留已有签名游标，升级游标 scope，旧游标明确拒绝。

外部依赖不能仅靠 SQL 中未到期缓存来猜授权：先在本地授权范围发现带已发布状态或任何保留知识引用的根，经过已有完整外部准备，再在最终事务以身份→根锁顺序重新验证完整来源依赖和当前 actor/pins/hash/deadline。明确拒绝项从公共关系排除；未知/预算耗尽整请求 503，不给出缺失项的假总数。普通未发布且无知识依赖会议使用索引关系，不逐条读取正文。结果页仍逐根核对现有 gate；若快照与当前根改变，整个请求重试而非拼接不一致统计。

执行顺序：
1. 真实 MySQL 测试先证明筛选发生在分页前、字面通配/大小写/日期/名单/权限统计一致。
2. 实现共用关系和有界外部准备，返回总数、阶段统计和专题统计；列表增加材料数量、允许动作及目的路由。
3. 同步 OpenAPI 和前端响应校验/展示，保留失效后端拒绝。
4. 专用容量数据集 10 万会议、1000 人、100 万片段，记录真实 EXPLAIN ANALYZE 和范围一致性，不混同真实模型/生产容量验收。
5. 补齐信息建议采纳/拒绝：仅显式采纳写入、版本冲突保护、人工已有值不被自动覆盖。

另有独立 D-03/D-04 局部生成缺口，保持 OPEN；不得因本查询完成而宣称 D 全部完成。
