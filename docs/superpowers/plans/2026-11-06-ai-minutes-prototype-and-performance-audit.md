## 4. 改造前性能基线

浏览器为 Chromium 145.0.7632.6。每次冷开使用新的已登录上下文，HTTP 缓存为空，服务和数据库处于运行状态。普通组和受限组使用相同的 1440×900 会议样本，含 9 条要素、18 条证据关系和 2 条敏感摘录。受限组通过 CDP 设定延迟 120 ms、下载 10 Mbps、上传 3 Mbps、CPU 4 倍降速。时间从文档导航起算，表中为毫秒，中位数后附最小至最大值。DOM 就绪按浏览器动画帧采样。

| 事件 | 本地常速，6 次 | 受限网络和 CPU，3 次 |
| --- | ---: | ---: |
| 首次内容绘制 FCP | 126（96–196） | 868（812–944） |
| 工作台外框可见 | 447（349–1,310） | 1,338（1,313–1,474） |
| 最大内容绘制 LCP | 354（268–1,224） | 1,160（1,104–1,280） |
| 首条真实核心要素可读 | **2,594（2,130–3,298）** | **3,136（3,100–3,594）** |
| 当前页敏感摘录全部就绪 | 8,269（7,313–8,981） | 8,758（8,401–10,476） |
| 当前页要素的来源徽标全部从占位变成确定标签 | **12,454（11,113–14,032）** | **13,246（13,182–15,779）** |
| 从导航到上述内容加载完成的 CLS | 0 | 0 |

### 如何定义「0 秒级」

建议把「按下就有反馈」「读到真实内容」「写入或模型已完成」设为三个独立验收点。网络传输、鉴权、持久化和推理都有耗时。页面能给出的承诺，是在下一帧作出正确反馈、有效缓存命中时立即呈现，并保持控件位置稳定。以下为建议交付门槛，均待实施后验证。

| 指标 | 建议门槛 | 测量方式 |
| --- | --- | --- |
| Tab、目录、来源／版本抽屉首次反馈 | 常速 P95 ≤50 ms，受限场景 P95 ≤100 ms；所有可操作控件 100 ms 内提供按下／待处理状态 | 捕获输入事件及次帧，另记录目标内容到达时间；用 Event Timing 和帧截图交叉验证。 |
| 已授权、同版本热切换 | 现有正文／要素 P95 ≤100 ms；已有标签不退回占位，模板不反复禁用 | 实际按钮往返至少 100 次，记录每次请求、焦点、scrollTop、占位出现次数。变更／撤权场景单列。 |
