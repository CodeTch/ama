## 2. 不可降低的可靠性底线

1. 服务端鉴权、会议隔离、成员已保存内容边界、撤权与身份切换清理；管理员不能绕过。
2. 保存事务原子性、版本冲突和草稿保留；迟到结果不能覆盖人工编辑；原命令 ACK 与当前观察分离。
3. 幂等与原 key/body 恢复；发布未知只查回、不盲目重发；零副作用重试须满足真实条件；成功发布保持只读。
4. 文件持久化、上传续传、最终化约束、原后端路由、失败回滚和任务租约/恢复。
5. genuine authority/同源 holder、统一锁序、完整集合与读取前累计预算、取消/超时；不得改成无界读取后再截断。
6. 真实 MySQL 并发/事务、真实 HTTP/存储与必要浏览器/应用重启证据仍需取得；mock、编译和源码审查不得替代。
7. 原始失败、历史 UNKNOWN、已有资格限制、不可变迁移与证据不回写、不假关闭。历史事实与当前缺陷分别判断。

## 4. 验证合并与回归频率

### 4.1 三档执行

| 变更类型 | 开发中 | 功能批次结束 |
| --- | --- | --- |
| 文档、文案、普通样式且无行为变更 | 内容/链接或受影响页面检查；有编译影响时类型/构建检查 | 自查即可；不写镜像式测试，不新建冻结包或强制独立审查 |
| 常规业务与页面接入 | 有行为变化时补行为测试并确认真实失败原因，运行受影响测试 | 相关回归、类型检查、可演示前构建；集中独立审查和对应页面操作验证 |
| 权限、事务、迁移、任务、文件、发布、公共预算/锁协议 | 定向行为回归，必要设计增量与高风险源码审查 | 真实 DB/HTTP/存储/故障测试，覆盖受影响消费者；未通过不能启用相关高风险路径 |

默认一次审查不是次数上限：实质缺陷必须修复并复审。复审聚焦修复及受影响依赖；范围未扩大时不重开无关部分。

### 4.2 各层负责什么

| 层级 | 必须承担的证明 | 可合并部分 |
| --- | --- | --- |
| 单元/组件 | 组合逻辑、状态转移、原 key/body、冲突/草稿/身份边界、预算计算 | 共用逻辑在最接近实现的层充分覆盖，不把每种组合复制到浏览器 |
| 真实 MySQL | 回滚/CAS/锁序/竞态、撤权、完整集合、读取前预算和不转移正文；B3 必要饱和/共存与 F5 新源码原子性等未完义务 | 同一已审版本、合法资源批次合并相关场景，逐项保留断言/结果，不用单元替代 |
| HTTP/真实适配器 | 鉴权/契约/状态码、直接写入负例、幂等/副作用、持久化及应用重启恢复 | 四身份和写入保护矩阵主要在此覆盖；存储无关业务异常不在每个后端重复穷举 |
| HTTPS 浏览器 | 实际全流程、刷新/sessionStorage、双标签、IME/editor-intent、撤权/角色切换、响应丢失与恢复 | local/S3 各一条真实完整主流程；浏览器特有异常在代表后端充分覆盖，另一后端做受影响差异/冒烟；共享路径或差异无法证明一致时扩大覆盖 |
| 视觉 | B 检查布局可用、内容/错误可见、按钮可操作、适用视口无关键遮挡 | 三视口全面像素级收口后移 D-08；原基准保留，不以更新基准掩盖回归 |

- local/S3 的上传、读取、续传、中断/恢复、最终化、历史路由等差异分别验证；一端通过不能替代另一端。
- 四真实身份的服务端负例全部保留；浏览器保留每种身份代表性的可见性/拒绝/切换验证，不做“所有身份×所有异常×所有存储”的无差别组合。
- 发布响应丢失、UNKNOWN、原结果回读、应用/Worker/provider 重启、关键崩溃边界、撤权和冻结仍属 B。深入矩阵可放真实 HTTP/DB 层，浏览器验证代表路径。主机/存储故障资格才后移 F。
- 快速全套回归保留，在完整业务批次/集成时合理运行；只改前端不默认重跑未受影响 Java/DB 测试。公共协议变化则扩大回归。
- 同版本、同相关依赖/配置/测试条件且无新失败或疑虑时复用证据。源码、测试、schema、依赖、装配或相关环境变化时，重新判断受影响证明并复验。
- 不因换审查者、写交接或时间经过而全量重跑；有时效条件的生产环境证据仍按条件刷新。
- B-L5 对最终组合版本做一次适用集成回归和全分支审查。修复后跑受影响场景与必要回归；已有覆盖相同最终版本的有效结果不机械重复。

## 5. 证据、环境与审查简化

- 每个功能批次一份简短记录：范围/风险、版本（commit 或包含未提交更改的 patch/清单）、命令/环境、实际计数/失败、审查结论、待办与证据链接。
- 不按微小步骤复制完整源码。沿用基线，以增量清单记录改变的源码/测试/依赖/配置；相关 artifact/JAR 必须与测试版本准确绑定，测试期间被测源码稳定。
- 不改既有不可变封存包/日志。新证据使用新且归属明确的目录，继续使用已有 output-root/custody 工具；不覆盖旧报告，不假设环境变量能改输出位置。
- 新常规测试优先可重复隔离夹具；特殊历史现场保留为专门调查证据。不把改造所有旧测试工具作为 B 前置工程，阻塞必需测试时才做最小工具修复。
- 一份真实环境计划可以包含多个相关场景，合并资源前置检查和收尾；明确所有者、允许操作、时间/请求/容量边界及逐场景结果。授权必须实际覆盖该批次，旧单次 release 不能推断为可复用。
- retained DB/Docker/env/provider/SQLite 和已消费窗口仍禁止擅自访问或重跑。当前无新 runtime release；需要时先形成具体资源计划并按既有权限取得相应授权，本计划不绕过授权。
- 历史失败分为当前缺陷、待真实验证、历史未知/限制、非阻塞维护。已复现的数据丢失/越权/重复副作用/核心流程缺陷必须关闭；非复现旧失败保留触发条件，不无限追查。
- 历史 UNKNOWN 不等于修复完成，也不自动阻塞无依赖的新场景；必须证明当前流程安全隔离且不盲目重发。仍影响当前安全或必需验收时继续阻塞。

1. 从根 `DEVELOPMENT_HANDOFF.md` 定位开发树，读取本计划、`RESUME_LATEST.md`、`current-state.json`。
2. 核对现场 branch/HEAD 和本批差异；不默认扫描上千份历史文件，不重建树或重开已采用切片。
3. 恢复同一 reviewer，按 B-L1 完成信息编辑闭环；沿用批准设计，不再询问是否执行。
4. 开发中定向验证，完整批次集中审查；高风险变更按第 4 节升级。
5. 推进不依赖缺失环境的源码工作；真实环境按第 5 节合法批次安排，不把源码通过标为 runtime 通过。
