# D07：未发布会议删除与可恢复清理

本计划接续阶段 D 主计划；用户已要求持续完成 D、由单 agent 自主决定，在 `/home/tanren/ama` 的 main 执行。使用现有授权，不创建工作树。公司服务统一通过固定端口的兄弟 harness 验证。长测完成归档检查前不部署或迁移主库。

## 设计约束

1. 删除请求持有当前身份、会议根及主体 fence，拒绝正在录音/暂停、发布中/发布结果未知、曾成功发布、治理不正常的会议。采用原键和原版本重试协议，成功受理返回稳定 deletionTaskId；立即不可访问，cancelEpoch 单调推进。
2. 清理使用独立的持久任务主体，不能放在已经 tombstone 的 MEETING 主体上冒充可执行任务。任务按已删除会议及受管清单运行，不因发起人后来停用而遗留在线正文。
3. 清单只从数据库里的 backendId/namespace/objectKey/上传 token/生成意图取值，不接收用户路径；关联到知识库的原文件不在本地清理范围。失败、不明确的远程状态不能认定为已清理。
4. 先建立永久不可再附加的逻辑墓碑，再清理存储。现有 delete(key) 仅删除当前数据、不能阻止迟到 PUT，因此增加 local key retirement：同步永久标记、删除字节、同步目录；重试幂等，跨进程重启不能重新写入。上传还要 discardUpload 清掉分片。旧适配器默认拒绝；S3 专项保留到 F。
5. 先封禁/取消、再固定有界清单、逐项退休，最后在事务中清除在线业务正文和派生索引。保留最少任务/删除审计/恢复抑制标识，不将仍在清理或有未知项的任务显示为 complete。
6. 原始幂等删除回执保持可恢复；清理状态读取只允许原所有者或明确的审计入口，管理员无普通内容权限。前端明确区分立即不可访问与后台清理完成。
