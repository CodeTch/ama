# 产品决定与平台缺口台账

日期：2026-10-21。来源：[需求对应与差异 §4](../superpowers/specs/2026-10-21-ama-requirements-matrix.md)、[总体计划 §5](../superpowers/plans/2026-10-21-ama-delivery-plan.md)、[用户已确认的产品补充规格 v0.2](../superpowers/specs/2026-10-21-ama-product-supplement.md)。本表 `D-*` 指差异编号，任务列 `D-*` 指实施任务编号，两者不可混用。

三类：`adopted`（已采纳，不重新询问已批准范围）、`product-specification`（需产品补充规格）、`platform-evidence`（需平台/运维真实证据）。分类指出首要收口路径；产品规格仍可能需要平台配合，平台项目仍可能需要产品审阅降级行为。已采纳只表示规则已确认，**不表示代码、平台联调或部署已验证**。离线输入无法更改这些来源决定。

完整采纳为 D-01/02/03/08/09/18/19/20/21。用户已明确批准补充规格的编辑和输入、受控链接邮件、保守治理三组规则；D-04/06/10/11/15 的已批准部分作为执行基线，不再重复请求确认，仅表内列出的真实缺口保持 pending。下列待定字段不能以空白占位或实现者默认值替代规格。责任方在受影响字段的实现/接口冻结/验收前形成可审阅记录，附版本、批准人及受控证据引用；受控测试角色和合成数据只能验证开发行为，不能替代企业角色映射或安全审批。

## 专项收口内容

- 输入组合 D-04/05：已批准单批按顺序合并多个音视频、单批处理多个纯转写文档，同一批次不混合两类。只继续收口格式、大小、时长能力矩阵和技术资源预算；未证明的格式不宣称支持，不增加产品名称字数上限。
- 保存 D-06：转写显式保存、纪要显式保存及自动保存、失败/冲突保留草稿、确认/导出只用已保存版本均已批准；`perEditorSaveTiming` 仅指纪要自动保存的具体触发时机，`saveIndicator` 和 `leaveReminder` 仅指保存指示及离开提醒的交互细节。
- 邮件 D-10：收件范围、禁止外部邮箱、只发绑定已保存版本的受控链接、无正文/附件、发送前重验权限和发布/撤回状态，以及 UNKNOWN 先查回且不得盲目重发均已批准。剩余发件授权、模板和业务消息键技术细则待落实；公司协议、发件授权、查回/去重与限额能力仍由 INT-07 提供企业实证，本任务不发送真实邮件。
- 治理 D-11/15/17：候选/审核/生效记录、用途授权与撤销、审核权不隐含正文读取权、身份候选不授予访问、配置独立审批/回滚及仅允许定义配置键已批准。继续收口真实企业角色及外部人员/负责人映射、允许用途、评测数据集和保留/删除策略；不重开已批准治理框架。未落实上述前置条件前，不启用全局数据复用、真实声纹登记或自动清理；撤销记录不自行设置产品保留上限，历史成果不自动清理。
- 日期 D-03：UTC 存储与 Asia/Shanghai 会议日期过滤沿用原基线；负责人在统一信息抽屉编辑可选实际会议日期已批准，未知值保持空，各视图依原需求/原型显示空态或“--”，不以创建日期替代。
- 降级确认 D-07：纠错零待处理是当前前置。是否开放失败后原文降级、明确批准及审计原因尚待产品决定，不能静默绕过。
- OCR D-16：格式/扫描件/现有 OCR 服务可用性、来源位置和失败展示需能力矩阵；没有 OCR 时明确不可解析，不假造文字。
- 人工标题 D-18：标题与会议名分开版本化、按已保存标题发布沿用原基线；人工标题不被 AI 或会议改名自动覆盖、重新联动仅由用户显式操作已批准。

离线探针的 B–F `implementation=may-continue` 只允许在已批准框架内推进不依赖缺口的独立工作；`decisionGates` 保留待定字段对应任务，`externalGates` 与 `qualification=pending` 保留企业联调/安全/运维实证要求。B00 仍暂停未审查 schema 和最终阶段验收，此次无数据库同步不表示 B 或 B00 已验收。产品规则批准不能使任何 INT/PR/PL 项或 `integrationVerified` 变绿。

每次收口保留原差异编号、具体字段答案、责任方、批准版本/受控引用、受影响任务、实现验证/平台联调/部署验收三类证据。后续专项规格不能把未取得接口改成 verified，也不能重开已采纳范围或修改原始需求/原型。
