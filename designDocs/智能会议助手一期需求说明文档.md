# 功能模块一：会议采集

### 1\. 功能目标与范围

本模块包括文件采集、在线录音及实时转写、材料准备、知识库材料引用、基础信息编辑。支持用户通过离线导入或在线录音采集会议内容，准备增强转写和纪要生成所需材料。

> 会议名称、参会人、会议分类、会议摘要可立即填写，也可在最终确认时补齐，这些基础信息不作为启动处理的前置条件。

### 2\. 核心业务规则

- 基础信息仅包含会议名称、参会人、会议分类、会议摘要，允许立即填写或后补，不作为启动处理的前置条件。基础信息未填写或未确认，不阻断增强转写。可在最终确认环节检查、补齐，发布时后端再次校验。
- 参与正式处理的背景材料及相关文档须在启动处理前完成导入或关联，允许为空。
- 在线录音无需预填信息，结束后自动关联原录音，无需重复上传。
- 材料来源支持本地上传与知识库引用，可混合使用，处理时锁定版本。
- 采集时间和录音时长属于系统元数据，不冒充实际会议发生时间，列表时间筛选使用后端提供的实际会议发生时间。

### 3\. 用户与权限

| **角色**          | **权限**                                                   |
|-------------------|------------------------------------------------------------|
| 会议负责人/创建人 | 创建草稿、上传文件、录音、准备材料、编辑信息、确认名单、启动处理 |
| 已确认参会人      | 按会议授权只读回看，不编辑采集文件、基础信息或名单           |
| AI候选/匿名说话人 | 不产生账号访问权限                                         |
| 平台管理员        | 按管理权限处理任务异常，不默认成为参会人                    |

所有读写、文件引用及授权均由后端校验。

### 4\. 主流程与状态

| **链路** | **页面及状态流转**                                                                                                                                                                 |
|----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 离线导入 | 我的会议 → 导入会议弹窗 → 添加主文件及可选背景材料 → 保存并返回列表或开始处理；保存后列表新增会议采集记录，未填写名称时使用第一个主文件名，开始处理则关闭弹窗并直接进入当前会议处理页 |
| 在线录音 | 开始录音 → 麦克风授权 → 录音与实时转写 → 结束确认中的开始处理 → 保存并自动关联录音 → 进入统一处理页；文件或材料未就绪时显示阻断原因，满足条件后再提交                                |
| 信息填写 | 在线录音、处理、转写及后续成果页面通过会议信息入口打开同一抽屉，可独立保存。                                                                                                           |
| 材料变更 | 开始处理时锁定材料快照；处理后通过调整背景材料打开独立弹窗，取消丢弃本次修改，明确应用后重新增强并进入候选核对链路                                                                    |



基础信息编辑与主流程并行。

|--------------|---------------------------------------------------------|--------------------|

### 5\. P01：导入会议/材料准备页

#### 5.1 页面目标与入口

| **区域** | **页面结构与交互**                                                                              |
|----------|-------------------------------------------------------------------------------------------------|
| 入口     | 我的会议中的导入会议打开弹窗；草稿会议可从列表继续导入，不先填写基础信息                          |
| 标题     | 标题“导入会议”，其下8px展示“采集会议内容”，右上角可关闭                                           |
| 主体     | 上方为会议主文件，下方为会议背景材料及相关文档；不再嵌入原先的可折叠基础信息区                    |
| 底部     | 保存并返回列表、开始处理及具体阻断原因；操作区保持可见，窄屏按钮不裁切                             |
| 布局调整 | 主文件导入框相较原演示区域高度缩小约1/3；正常文件信息由三行收敛为两行，异常及上传进度仍需清楚显示 |

#### 5.2 主文件区域

展示文件名、类型、大小、上传进度、校验状态及可用时长。

- 支持文件选择和拖拽。
- 上传绑定已创建的会议草稿ID。
- 开始处理前可移除、更换。
- 未命名时暂用文件名；在线会议暂用“在线会议＋采集时间”。
- 在线主文件自动关联，展示保存状态，不提供重复上传步骤。
- 支持多段会议录音导入，文件逐段展示上传及校验状态，并关联同一会议；不得只保留第一段。视频导入是否支持仍待确认。各段播放及转写来源须可追溯；跨段顺序、时间轴及说话人关联细节待补充。

**异常处理**

上传失败可重试或更换，保留草稿及其他材料。断网或离开时提示未完成状态；按技术支持范围恢复分片，必要时要求重新选择原文件。

**接口需求**

需要草稿创建/查询、上传凭证、分片上传、完成确认、校验、重试及移除接口，返回各段文件ID、状态、大小和时长，支持同一会议关联多段主录音。

#### 5.3 背景材料及相关文档区域

背景材料可为空，不设置“无补充材料”或“本次材料已准备完成”等用户勾选项，也不增加替代确认。点击“开始处理”即提交当前材料集合。

| **区域** | **页面结构及交互**                                                                          |
|----------|---------------------------------------------------------------------------------------------|
| 标题行   | 左侧“会议背景材料及相关文档（选填）”，右侧同层级并列“上传本地文件”“从知识库选择”；窄屏自然换行  |
| 无材料   | 紧凑虚线拖拽区：“可拖入背景材料，也可从知识库选择；无材料可直接开始处理。”                      |
| 有材料   | 以统一文件列表为主体，拖拽区缩为轻量继续添加入口，两个添加按钮始终保留                        |
| 文件列表 | 本地文件及知识库引用混合展示，含名称、类型、来源、状态及操作；本地含大小、进度，引用含知识库及版本 |
| 辅助说明 | “补充材料有助于识别专业术语和生成纪要；未添加时，将基于会议录音或转写内容处理。”               |

**添加与状态**

- 本地支持选择多个文件及拖拽，保留格式提示；生产格式、大小和数量等限制仍待补充，不擅自确定。
- 上传中显示进度，校验中显示状态；添加失败展示具体原因及“重试/移除”，缺少本地文件时可重新选择并重试。
- 成功显示“已添加”，不等于已解析或已参与增强。解析状态单独展示。
- 移除知识库材料只解除会议关联，不删除源文件。更新引用版本须用户明确执行，不静默改用最新版。
- 上传、失败、重试、页面刷新及列表重绘保留其他文件、材料引用和会议信息输入；未保存信息作为独立输入草稿恢复，并检测版本冲突，不自动确认或授权。

**启动后的变更与异常**

- 任务使用提交时锁定的文件集合及引用版本；之后增删材料或更新引用只形成待应用版本，不改变当前任务或已有成果。
- 完成当前任务后，通过“应用材料并重新增强”明确应用；保留原有影响说明、确认与候选采用链路，无需手动声明准备状态。
- 移除全部背景材料后，可以明确提交空集合并重新增强。已有人工转写、纪要及历史保留，不静默覆盖。
- 材料解析失败明确本次未参与增强，支持重试解析或明确不使用；失败材料不作为生成依据，基础转写可继续。

**接口需求**

需要后端接口：查询当前材料集合、文件状态和引用版本；本地上传/校验/重试、移除关联；材料修订及待应用状态；提交时校验并锁定材料快照（允许空集合）；重新增强、版本冲突、幂等、任务状态与审计。返回文件及集合版本、可用性和逐项失败原因，不再提供用户手动准备确认接口。

#### 5.4 “从知识库选择材料”弹窗

从材料标题行打开。参考截图的通栏搜索、左右双栏、底部操作结构，沿用本系统橙色规范，不复制整库授权或默认使用全部知识库的规则。选择的是具体文件。

| **区域**   | **功能与交互**                                                                                        |
|------------|-------------------------------------------------------------------------------------------------------|
| 标题       | “从知识库选择材料”，右上角关闭                                                                         |
| 通栏搜索   | “搜索知识库或文件”，可清空；全部范围跨库检索，指定库范围检索该库；库名匹配与文件名匹配明确区分，不自动选择 |
| 左侧知识库 | “全部知识库”及当前有权限的库，含图标、名称、必要说明和进入指示；当前项高亮，仅用于浏览筛选，不设置整库勾选  |
| 右侧文件   | 文件级复选框、图标/类型、名称、引用版本、库名和更新时间；跨库结果必须显示来源                              |
| 已选反馈   | “已选N个文件”、查看已选、清空选择；已选清单核对名称、库名、版本，支持取消单项                               |
| 底部动作   | 取消、添加所选文件；未选禁用，提交中防重复，失败保留上下文                                                |
| 说明       | “仅添加所选文件作为会议材料，不扩大知识库或源文件访问权限。”                                            |

**选择与浏览**

- 支持跨库累计多选，切换库、搜索、清空搜索、分页或分批加载均保留已选集合；不扩大到未加载文件。生产分页容量不在本模块确定。
- 同一文件同一版本不得重复添加；已关联条目标为“已添加”，不能重复选择。长名称可查看完整内容。
- 两栏独立滚动，搜索和底部动作保持可见；快速连续搜索只展示最新请求结果。
- 窄屏可重排或以知识库范围切换配合文件列表展示，仍保留搜索、跨库选择和来源，按钮不裁切，弹窗可关闭。
- 不提供知识库、文件夹的创建、编辑、删除或授权操作。

**提交、取消及异常**

- 添加前复核每个文件的权限、状态、所属库、引用版本及重复关联。有效文件直接引用，无需下载再上传。
- 无权限、撤回、废止、不可用或版本变化明确展示对应文件及原因；不静默添加、丢弃选择或替换版本。
- 本次关联全部校验通过后提交；部分选择失效时不写入任何新增关联，保留有效与失效选择供核对、取消或明确重新选择。
- 关联成功关闭弹窗，文件进入材料统一列表并显示知识库、引用版本和“已添加”。提交失败保留搜索、范围及选择，支持重试。
- 取消/关闭不改变会议已关联材料，未提交选择不写入会议材料；刷新时可恢复独立的选择草稿，明确取消后丢弃该草稿。
- 分别显示库加载、文件加载、空库空文件列表、无搜索结果、查询失败、关联失败及权限变化状态。
- 处理启动时锁定文件ID及版本；后续源文件更新不静默改变任务和成果。引用不扩大参会人或其他用户的源文件权限，源文件预览独立校验。

**接口需求**

需要后端接口：有权限知识库列表查询接口；全库/指定库名称和文件搜索及分页，返回文件ID、名称、类型、库、版本、更新时间和状态；当前会议已关联文件及版本；批量权限/状态/版本复核、去重；批量关联及逐文件结果；引用快照和解除关联。并发或重试不得重复关联，不通过查询或添加扩大权限。

#### 5.5 可折叠会议信息区域

标题为“会议信息（可稍后填写）”。

展开后复用P03字段和操作，不要求先展开或填完才能处理。人工填写后，迟到的AI建议只进入建议区。

#### 5.6 底部操作与离开恢复

| **操作**       | **交互**                                                         |
|----------------|------------------------------------------------------------------|
| 保存并返回列表 | 保存成功后返回；失败保留页面和输入                                |
| 开始处理       | 自动校验并提交当前文件与引用范围，背景材料可空，不校验基础信息必填 |

开始处理条件：

1. 主文件上传或录音保存完成，服务端校验通过。
2. 所有已添加的主文件和材料上传、校验完成，无待处理失败项。
3. 知识库引用仍可用，当前用户有源文件权限，所选版本有效；背景材料可以为空。

未满足时按钮不可点击，旁边显示具体原因，如“还有2个文件正在上传”“还有1个文件正在校验”“有文件添加失败，请重试或移除”。点击时后端再次校验并锁定当前文件集合及引用版本，允许空材料集合，无额外材料准备确认弹窗。提交中防重复，失败保留输入和关联，可重试。

提交成功进入功能二处理页。重复点击和网络重试须幂等。用户可离开，服务端任务继续，返回恢复结果。

#### 5.7 页面验收要点

- 仅主文件、空背景材料、不填信息，可直接启动处理，无额外确认。
- 本地和知识库材料可混合使用，无重复关联。
- 启动前的文件变更自动更新可用性；启动后的材料变更仅待应用，不静默改写当前任务或人工稿。
- 两栏导航、搜索、跨库选择、已选核对、去重及失败重试保持一致；取消不关联文件。
- 主文件缺失、上传/校验中、添加失败、权限或版本失效均阻断；重试成功或移除后恢复。
- 移除最后一份材料可提交空集合；在线录音适用同一规则，旧准备标记不产生隐藏阻断。
- 桌面及窄屏入口可发现、可操作，列表重绘和刷新不丢草稿。
- 失败文件不能绕过校验。
- 返回列表及重进能恢复草稿。
- 处理启动不直接触发未确认转写的纪要生成。

### 6\. P02：在线录音页

#### 6.1 页面目标与入口

点击“开始录音”直接进入，不预填会议信息。页面包含录音状态与时长、操作按钮、实时转写、保存状态及异常提示。

#### 6.2 录音控制区域

| **操作** | **交互逻辑**                                    |
|----------|-------------------------------------------------|
| 开始     | 申请麦克风权限；拒绝后提供授权引导及改为导入入口 |
| 暂停     | 保留同一会议及录音会话，暂停时间不计入有效时长   |

# 功能模块二：会议增强转写

### 1\. 功能目标与范围

将导入或在线录制的会议内容转为可回听、可核对、可修订、可确认的会议转写，为纪要生成提供明确依据。本模块包含原始与增强转写、音文联动、文字校正、说话人管理、实体纠错、片段标记、版本及确认、语料和声纹反馈入口、参会人只读回看。语料及声纹审核维护归属平台运营与治理，纪要生成及编辑归属模块三。

### 2\. 核心业务规则

- 用户确认会议转写后才能生成AI纪要，后端必须校验。参会人只读，不可修改或确认。
- 四类基础信息未填写或未确认，不阻断增强、校正和转写确认。
- 正式增强使用采集模块确认的主文件、材料集合及版本，包括本地上传和知识库引用。
- 在线实时转写不等同于正式增强结果或确认稿。
- 增强仅做识别校正及受控实体纠错，不补写未出现的数字、观点、承诺或结论。
- 人工内容不被迟到结果或重新增强静默覆盖。
- 允许匿名；说话人关联不自动授予参会权限。
- 转写确认形成快照，纪要绑定具体确认版本。
- 确认后实质修改形成待确认稿，保留旧快照及已有纪要。
- 本会议修改与全局语料更新分离，全局语料及声纹须独立审核

### 3\. 用户与权限

| **角色**          | **权限**                                                 |
|-------------------|----------------------------------------------------------|
| 会议负责人/创建人 | 校正、说话人管理、纠错、确认、生成纪要、反馈                  |
| 已确认参会人      | 按会议授权回听原录音、只读查看转写及纪要                  |
| 平台管理人员      | 在治理模块处理反馈、声纹和审计；不默认获得任意会议访问权限 |

### 4\. 主流程与状态

文件上传校验通过（背景材料可空） → 开始处理并锁定材料快照 → 原始识别/转写解析 → 增强转写 → 用户校正 → 确认转写 → 提交AI纪要生成任务。离开页面不自动取消任务，返回恢复最新进度。

| **维度** | **状态示例**                      | **说明**         |
|----------|-----------------------------------|------------------|
| 处理任务 | 待处理、处理中、成功、失败、已取消    | 系统任务状态     |
| 转写稿   | 待校正、校正中、已确认、确认后有修改 | 内容核对状态     |
| 保存     | 保存中、已保存、保存失败            | 修改是否持久化   |
| 纪要衔接 | 尚未生成、生成中、生成失败、已生成   | 不与转写确认混同 |

增强成功不等于确认；纪要失败不撤销有效确认。

##### 6.5.2 逐段阅读与编辑

##### 6.5.5 片段标记

每段“关键、结论、争议、重点生成”，可多选及取消。保存并纳入快照，不改原文或代表真实性验证；重点生成仅供参考。确认后修改影响生成的标记需再确认。

##### 6.5.6 重新增强

版本/材料入口提示待应用材料，明确启动后产生新版本，保留人工稿和快照。用户明确采用，不自动切换；采用后重新核对确认。迟到结果不覆盖当前稿。

| 人工修改 | 弹窗输入保存         |
| 恢复原文 | 撤销本项并回到待处理 |

建议绑定片段和文本位置；上下文变更后旧建议失效或再核对，不覆盖人工值。增强不补写未出现信息。

##### 6.6.3 批量处理

区顶部批量接受/拒绝，确认展示范围数量及候选处理方式，区分全部待处理与筛选结果。反馈成功失败数量，失败项可重试。

##### 6.6.4 语料反馈

卡片弹窗填写原值、建议、类型、可选说明并携带片段来源，进入审核可跟踪；不自动更新全局，失败不影响会议校正。

接口：建议、定位、单条/批量处理、候选人工值、恢复及失效检验、反馈及状态。

#### 6.7 验收

查看与操作版本一致；原始音文不变；身份不隐式授权；保存失败不丢输入；旧建议不覆盖人工值；增强保留人工稿；匿名和缺基础信息不阻断确认。

### 7\. P03：转写确认弹窗及纪要衔接

#### 7.1 入口与结构

工作台主按钮打开：版本 → 检查结果 → 生成说明 → 返回校正/确认并生成。

#### 7.2 检查与定位

| **检查**     | **不通过处理**   |
|--------------|------------------|
| 有有效正文   | 提示无可确认内容 |
| 修改已保存   | 返回保存/重试    |
| 纠错全部处理 | 数量及定位       |
| 版本有效     | 获取新版本并核对 |
| 有权限       | 阻止并说明       |

匿名和基础信息不全不阻断。取消原型中带着待处理纠错完成校正的路径。

#### 7.3 提交结果

后端校验、保存快照、绑定版本提交纪要任务；成功进入生成页。确认失败保留稿不生成；确认成功而提交失败明确分别展示并重试生成；执行失败保留确认无需重复。重复请求幂等。

#### 7.4 确认后修改

实质修改生成待确认稿，旧纪要仍绑定旧快照并提示新稿；新稿再确认后明确生成新纪要，不覆盖人工编辑。最终确认/发布校验引用版本，不将旧纪要标为基于最新转写。已发布修订由发布模块定义。

#### 7.5 接口及验收

需要确认校验、快照、幂等纪要提交及版本关系接口。未确认请求后端拒绝；确认与生成失败分别恢复；新稿不污染历史；最终环节可校验引用。

# 功能模块三：会议纪要生成

### 1\. 功能目标与范围

基于已确认会议转写及本次有效材料，生成可核对、可编辑、可追溯的AI纪要。核心要素用于核对讨论、结论、行动项及依据；完整文本按模板形成成段纪要，支持直接编辑并交接最终确认。包含生成进度、要素核对、敏感排除、模板选择与新增、正文与行动项编辑、局部及全文重新生成、来源查看、版本比较与恢复。最终确认及发布完整流程归属功能四。

### 2\. 核心业务规则

- 只有当前有效会议转写已确认后才能生成纪要，服务端再次校验；保存工作稿不等于确认转写
- 生成任务绑定确认转写、主文件、有效材料及知识库引用、模板和敏感排除范围，不静默采用后续材料或迟到结果
- 名称、会议日期、分类、摘要和参会名单允许后补，不阻断生成及编辑，最终确认时按模块一校验
- 核心要素是基于会议文件和背景材料的归纳总结，不要求照搬原文；背景材料只能作为明确标注的补充依据，不冒充会议发言、会议决定或明确任务
- 排除操作仅在“敏感信息”模块提供，默认不勾选，支持逐段排除及全部排除；其他六类要素不展示排除复选框
- 勾选表示对应内容不参与下一次会议纪要生成，不删除录音、转写或要素，也不直接改写已经保存的纪要正文
- 重新生成先产生候选，明确采用后更新当前正文；生成成功即取消“内容有变更，需重新生成”提示，无需等待采用，但未采用候选仍不能作为当前有效成果或用于最终确认
- 生成失败保留提示、设置及正文；生成后再调整要素、模板或排除范围，提示重新出现，旧候选不能覆盖新改动
- 会议纪要正文可编辑并显式保存，复制位于下载之前，下载为当前已保存标题及正文的UTF-8 Markdown文件
- 参会人只读查看有权访问的有效成果，不能编辑、生成、修改排除设置或采用候选；新转写不自动重写旧纪要，发布后按绑定成果只读

### 3\. 用户与权限

| **角色**          | **权限**                                               |
|-------------------|--------------------------------------------------------|
| 会议负责人/创建人 | 生成、核对、编辑、排除设置、使用新增模板、来源查看、比较恢复 |
| 已确认参会人      | 按授权只读查看                                         |
| 平台管理人员      | 按治理权限处理异常，不默认获得任意会议内容              |

用户新增模板仅创建者个人可见，不提供共享或其他人管理入口。内置模板仍按系统提供。服务端校验所有权限。

### 4\. 主流程与状态

确认转写 → 首次生成 → 核对核心要素及来源 → 按需调整敏感排除或模板 → 重新生成并核对候选 → 查看／编辑并保存会议纪要 → 进入会议确认。无需逐项展开全部要素，无调整时可直接核对已有正文。

| **状态维度** | **页面反馈与结果**                                                                                                       |
|--------------|--------------------------------------------------------------------------------------------------------------------------|
| 会议状态     | 正在生成、编辑或核对且尚未最终确认时为纪要待处理；任务失败时为纪要生成失败，有效确认转写及已有成果保留；最终确认后进入待发布 |
| 首次生成     | 尚无有效纪要时显示生成进度或失败区域，成功后进入工作台；未确认的新转写不能直接作为生成依据                                 |
| 工作稿       | 当前AI稿、已保存人工稿、未保存正文草稿及待核对候选分别处理；未保存输入和候选不替代当前有效正文                              |
| 内容有变更   | 核心要素、模板或排除设置变化时，在会议纪要模块标题后显示“内容有变更，需重新生成”；核心要素页不再显示原整段提醒               |
| 已重新生成   | 对当前改动生成成功后立即隐藏标题提醒，刷新及切Tab后保持正确；提示消失仅表示已生成，不表示候选已采用或可最终确认             |
| 保存与确认   | 保存中、已保存、保存失败独立反馈；候选未处理、设置尚未应用或依据失效仍需解决，不能靠隐藏提醒绕过最终确认                      |



### 5\. P01：纪要生成状态页

#### 5.1 目标与入口

承接功能二确认转写并生成纪要。首次无结果展示本页；已有稿重新生成在工作台提示进度，保留旧稿。

#### 5.2 区域与交互

| **区域** | **功能及反馈**                          |
|----------|-----------------------------------------|
| 顶部     | 名称/临时名称、信息入口，编辑不打断任务   |
| 生成依据 | 确认转写、材料集合版本，可查看，不静默更换 |
| 进度     | 真实阶段，无可靠进度不显示百分比         |
| 异常     | 原因及重试，不重复确认未变化的转写       |
| 结果     | 完成进入工作台                          |

首次默认AI生成模板，敏感排除复选框默认均不勾选；未勾选不排除对应内容。生成成功形成可查看版本后，已授权参会人即可查看最新版本，无需等待最终确认或发布。

#### 5.3 异常与恢复

离开任务继续，返回查询；提交失败与执行失败区分；重试复用有效确认并幂等。新转写出现时当前任务仍绑定旧版并提示。旧任务不覆盖更新稿；结果或来源关系未保存完整不提示可最终确认。

#### 5.4 接口及验收

需要任务提交查询重试、依据、结果和来源保存、版本权限校验。验收未确认拒绝、返回恢复、失败重试、正确关联依据、不重复生成。

### 6\. P02：AI纪要工作台

#### 6.1 整体结构

| **区域** | **功能**                          |
|----------|-----------------------------------|
| 顶部     | 标题、版本、保存、信息、比较、最终确认 |

| 文本视图 | 模板工具栏、成段正文编辑、复制      |

切换保留阅读位置及已保存内容，未保存输入按保存离开规则处理。

#### 6.2 顶部操作区

展示标题、版本、保存状态及修改人。临时名称不阻断编辑；修改纪要标题同步两视图。纪要标题默认与会议名称相同，用户可以编辑。已有人工编辑标题不得被后续AI建议或名称更新静默覆盖；编辑后名称与标题是否再次联动待明确。新转写/待应用材料显示提示。保存失败、生成中或设置未应用不能直接提交有效成果。最终确认进入功能四。

接口：稿件状态、依据关系、权限、标题保存、确认前置条件。

#### 6.3 核心要素：目录

| **目录**       | **内容**                |
|----------------|-------------------------|
| 敏感信息       | 识别及排除              |
| 会议概述       | 范围及主要内容          |

| 待确认项       | 不完整、需核实           |
| 未达成一致事项 | 分歧与各方观点          |
| 背景补充       | 材料知识背景，不冒充发言 |
| 关联材料       | 使用文件及版本          |

点目录定位，无内容显示未提取，不编造填充。

#### 6.4 核心要素：敏感信息

展示公司内部核心经营数据、政治敏感信息两类，含数量、摘录、来源定位，标注AI识别请人工核对。复选框为“排除……”并提示“勾选表示排除，生成的会议纪要中将不会包含对应信息。原录音和会议转写保留”。

勾选/取消保存设置，提示尚未应用；明确重生成后应用，不能隐藏段落冒充生成。要素相关内容保留供负责人及有权参会人查看，并标注排除，不输出正式正文；两类用户均可见敏感摘录，排除设置不改变原音文或核心要素的既有会议访问权限。排除涉及结论行动提示完整性影响。局部全文生成均应用；人工重新加入被排除内容提示冲突，最终确认前处理。原型关键词模拟不可作为实际识别实现。

#### 6.5 核心要素：内容核对编辑

每条正文、来源、证据、编辑入口，结论行动标记。编辑保存成修订记录，失败保留；刷新不丢输入。修改后原来源关系保留但需核对是否支持新表述，不支持不得标证据充分。发言、材料、知识背景、模型整理、依据不足分别标注，模型整理不新增事实。

接口：条目查询保存、来源、修改记录及冲突。

#### 6.6 核心要素：行动项

展示任务、负责人、截止及依据，负责人/截止打开弹窗。

| **字段** | **规则**                                                                   |
|----------|----------------------------------------------------------------------------|
| 内容     | 当前任务，正文按条目编辑                                                    |
| 负责人   | 企业人员选择，不以AI猜测认定                                                |
| 截止     | 有日期时展示并校验；没有截止日期时不展示截止字段，也不以缺少日期阻断最终确认 |
| 依据     | 查看来源                                                                   |

未明确负责人不编造，外部负责人如何选择与确认仍待补充；无截止日期时不展示，不强制补齐，也不编造日期。修改行动项负责人不授予参会权限。

接口：行动保存、人员、字段校验来源。

区域按钮打开要求弹窗，明确影响范围及人工修改。仅生成该区域候选，其他区域不变；查看后明确采用，旧稿保留。失败保留要求重试。使用确认转写、锁定材料及排除设置。采用新要素后完整文本待更新，不覆盖人工正文。

接口：局部任务、候选采用、历史，携带区域版本。

#### 6.8 完整文本：模板工具栏

同一行：模板下拉 → 新增模板 → 重新生成 → 设置提示。内置AI生成（默认）、正式会议纪要、简明总结。

选择只更新待应用设置，区分正文当前模板；不可用保留正文提示选择，不静默替代。新增弹窗名称、段落主题、保存并使用；每行主题1—8个、名称去重；成功选中仍需生成应用，失败保留，不承诺每主题都有内容。模板由后端持久化，新增模板仅创建者个人可见，后端查询和直接访问均校验创建者身份。

接口：列表详情版本、创建校验、可见范围、绑定版本

#### 6.9 完整文本：正文编辑与复制

完整文本成段呈现，支持直接修改、增加、删除文字段落，形成最终确认用人工修订稿，不改原始转写。

| **操作/场景** | **交互**                                        |
|---------------|-------------------------------------------------|
| 编辑          | 直接改正文及段落                                |
| 自动保存      | 保存中/成功/失败，失败保留重试                   |
| 切Tab或离开   | 未保存提示保存并离开/放弃修改/继续编辑，不丢输入 |
| 复制          | 复制当前编辑内容，失败提供手动复制               |
| 重生成        | 新候选比较明确采用，不覆盖当前人工稿             |
| 最终确认      | 保存成功，提交当前完整文本版本                   |

记录修改人时间版本，可比较恢复。正文不自动反向覆盖要素，涉及结论行动提示一致性核对。人工加入排除信息提示冲突，最终确认前处理。迟到AI和模板切换不覆盖输入或人工值。最终确认后编辑使确认失效；发布后按发布修订流程。

接口：正文查询保存、冲突、历史、敏感检查、确认版本绑定。验收持久化、失败不丢、重生成保留人工、最终确认使用已保存正文。

#### 6.10 完整文本：全文重生成

确认转写材料模板排除参数及人工稿影响，产生新候选，旧稿可看；成功比较明确采用，期间新编辑则提示冲突。失败保留旧稿重试；采用形成新版本并清除已应用提示。未确认新转写不可使用。

接口：任务、候选、比较采用、参数快照并发。

| Word      | 版本、段落章节                      |
| 知识库    | 库、文件ID、引用版摘录               |
| 模型/不足 | 无直接依据，不冒充结论              |

无录音/时间戳以确认片段为会议证据，不强制音频。

#### 7.2 权限异常

源文件独立校验权限，会议授权不扩大知识库权限。失效无权无法定位具体提示，不虚构摘录；重要结论需会议依据，背景不能证明会议已决定。

#### 7.3 接口验收

来源关系、引用快照、媒体文件定位、源权限状态。验收准确定位追溯、不越权、不冒充。

### 8\. P04：版本比较与恢复

#### 8.1 入口展示

顶部比较/时间线显示AI、人工、确认记录。选择两版本比较真实标题、要素、正文、行动、设置差异，不固定演示。

#### 8.2 恢复

先预览内容依据；形成新修订不删历史；依据不可用提示。排除不同需重检不绕规则；恢复使最终确认失效。已发布由功能四定义。

#### 8.3 接口验收

快照差异、预览恢复、依据权限并发校验。验收可追溯、不覆盖别人新稿、正文设置引用完整恢复。

### 9\. P05：最终确认成果交接

#### 9.1 入口检查

顶部进入最终确认，检查保存、无进行中的待采用生成、设置已应用、来源已保存、转写纪要关系有效。信息不足可进入补齐，不回采集。

#### 9.2 交接内容

完整纪要版本、结论行动风险待确认分歧、来源不足、敏感模板、基础信息及授权。待确认可明确保留，不自动升正式结论。最终阻断由功能四细化。

#### 9.3 接口验收

成果检查、问题定位、版本关系。未保存过期不能确认，信息就地补，进入不等于发布。

### 10\. P06：参会人只读纪要视图

复用功能二回看右侧纪要Tab，显示可查看正文及草稿/确认状态；无结果显示状态，不提供生成。无编辑、敏感设置调整、模板操作或恢复入口。支持下载当前可查看纪要的Markdown、PDF、Word文件，服务端校验访问权限与版本。已授权参会人从纪要生成成功后即可查看最新生成或已保存修订版本；未保存输入、失败结果及尚未被负责人采纳的重生成候选不作为当前版本。敏感核心要素与摘录允许负责人及参会人查看，完整正文按当前版本已应用的排除设置展示；发布后查看固定发布版本。原录音转写规则不变。

接口：只读版本选择、权限内容加载。

### 11\. 公共要求及待定事项

服务端权限、幂等、保存任务分离、并发历史审计；结果不覆盖人工；信息后补不改正文。

| **事项**     | **已确认结论/剩余边界**                                                             |
|--------------|-------------------------------------------------------------------------------------|
| 双视图关系   | 要素核对、正文发布，变更提示同步，不双向静默覆盖；同步细节待明确                        |
| 首次敏感设置 | 已确认默认不勾选；负责人及参会人均可见敏感核心要素                                   |
| 模板范围     | 已确认新增模板仅个人可见                                                            |
| 行动缺字段   | 无截止日期不展示、不阻断确认已明确；外部负责人处理待补充                              |
| 人工结论证据 | 补充调整依据或降待确认的操作待定                                                    |
| 参会人版本   | 已确认生成后即可查看最新有效版本；未保存输入、未采纳候选不替代当前稿，发布后固定发布版 |
| 标题关系     | 默认相同、用户可编辑已确认；编辑后的再次联动规则待明确，不静默覆盖人工标题             |

完整文本编辑已确认纳入正式范围，不属于待定事项。本模块为需求说明，不表示HTML已同步实现。

# 功能模块四：会议发布

## 1\. 功能目标与范围

将经过用户最终确认的会议纪要发布到指定知识库，形成可查看、可追溯的正式知识文档。发布对象为用户核对并确认的成果快照，包括已保存的完整纪要正文、会议基础信息、确认转写版本及来源关系。

本模块包含最终确认及信息补齐、发布位置与标签配置、权限范围确认、正式文档预览、发布任务及失败重试、正式文档查看与来源追溯，以及撤回、废止和发布记录的衔接。

知识库、文件夹和权限配置的维护归属功能模块六；会议列表入口及筛选归属功能模块五。

一期不支持发布成功后修改再发布，不支持替换正式文档或新增发布版本。撤回或废止后不提供恢复发布或重新发布入口，历史确认版与发布版保留。发布失败重试属于完成尚未成功的发布，不属于修改后再发布。

## 2\. 角色与权限

| **角色**         | **可操作范围**                                      |
|------------------|-----------------------------------------------------|
| 会议负责人       | 补齐信息、最终确认、配置发布位置、预览、发布及失败重试  |
| 已确认参会人     | 按会议授权只读回看，不确认或发布                     |
| 知识库纪要查看者 | 按目标知识库权限查看正式文档                        |
| 知识空间管理员   | 按管理范围查询发布记录，撤回或废止正式文档           |
| 平台管理员       | 按授权查询任务异常与审计记录，不默认拥有内容发布权限 |

会议操作权限和知识库发布权限分别校验。会议负责人具备目标知识库发布权限时，才能向该库发布；前端入口控制不能代替后端权限校验。

## 3\. 核心业务规则

- 未确认会议转写不能生成纪要；未完成有效最终确认不能发布
- 基础信息允许此前暂不填写，在最终确认页就地补齐
- 最终确认使用已保存的完整文本版本，不使用临时编辑内容或重新生成文本代替
- 最终确认形成快照，绑定基础信息、参会名单、转写、纪要、材料及来源版本
- 最终确认后、首次发布成功前允许返回修改；修改成果或基础信息使当前确认失效，必须重新确认
- 发布文档继承目标知识库权限，不在发布页另设文档权限
- 知识文档发布不扩大原录音、会议转写及知识库源文件的访问权限
- 发布失败保留内容和配置；内容未变且确认仍有效时，无需重复最终确认
- 重复点击、刷新和重试不能生成重复知识文档
- 已发布正文读取发布快照，不随会议草稿或企业语料更新而变化
- 待确认事项、分歧及依据不足保留其性质，不因发布变成正式结论
- 一期发布成功后成果只读，不提供修改后再发布；撤回、废止后不提供恢复或重新发布
- 知识库与文件夹为联动的发布位置选择，在同一区域操作，不拆成独立配置区域

## 4\. 页面与交互链路

最终确认 → 联动选择发布位置及配置标签 → 正式文档预览 → 提交发布 → 查询进度与结果 → 查看正式文档。

| **页面**             | **主要用途**                                 | **后续去向**          |
|----------------------|----------------------------------------------|-----------------------|
| P01：最终确认页       | 补齐信息、核对成果、检查发布前条件             | 发布配置页            |
| P02：发布配置页       | 联动选择知识库与文件夹，配置标签，确认访问范围 | 预览/发布任务         |
| P03：正式文档预览弹窗 | 核对即将发布的正文与信息                     | 返回发布配置          |
| P04：发布进度与结果页 | 查询进度、处理失败、查看发布结果               | 正式文档详情          |
| P05：正式文档详情页   | 阅读发布版、查看来源和版本信息                | 原始证据              |
| P06：发布与撤回记录页 | 查询历史及执行撤回、废止                      | 文档详情/治理确认弹窗 |

## 5\. P01：最终确认页

### 5.1 入口与页面结构

从纪要页点击“最终确认”进入。基础信息尚未补齐时也允许进入本页处理，进入页面不等于完成确认。

| **区域**   | **展示与操作**                                                  |
|------------|-----------------------------------------------------------------|
| 会议信息区 | 会议名称、参会人、会议分类、会议摘要，支持就地补充和修改            |
| 成果核对区 | 完整纪要正文预览，以及结论、行动项、风险、待确认事项、分歧和背景引用 |
| 检查清单区 | 每项显示通过/未通过、具体原因及“去处理”入口                      |
| 底部操作区 | 返回编辑、最终确认并继续发布                                     |

参会人沿用功能一的企业人员选择与名单确认逻辑。AI候选不自动成为正式名单，也不自动获得会议权限。

### 5.2 会议信息补齐

- 展示已填写内容与AI建议，用户可修改或逐项采纳，不要求返回采集页重新填写。
- 临时显示名称不能代替最终所需正式信息；AI建议仍须由用户核对。
- 校验失败定位对应字段，保留其他已输入内容。
- 名称必填且不限制最大长度；分类单选必填、字典后续补充；摘要可空且不限制最大长度；参会名单允许为空并提示添加后对方才可查看记录。沿用统一规则，不新增其他必填项。

### 5.3 检查清单及问题处理

| **检查项**                       | **未通过时的处理**           |
|----------------------------------|------------------------------|
| 基础信息符合最终确认要求         | 定位本页对应字段             |
| 当前使用已确认的会议转写         | 返回转写确认位置             |
| 实体纠错无未处理项               | 定位人名、产品、术语等待处理项 |
| 当前纪要及人工正文保存成功       | 返回编辑页处理保存问题       |
| 纪要与确认转写、材料版本匹配      | 提示版本变化，返回处理        |
| 重要结论具有会议依据             | 打开对应结论及来源           |
| 行动项负责人、截止信息符合规则    | 定位对应行动项               |
| 知识背景未冒充会议结论           | 定位相关内容                 |
| 敏感排除设置已应用且无待处理冲突 | 返回敏感设置或正文冲突位置   |
| 无尚在生成或等待采用的候选结果   | 返回生成结果处理位置         |
| 来源关系已保存完整               | 提示失败关系并提供重试       |
| 当前用户具有最终确认权限         | 禁止提交并说明原因           |

纯转写文件输入没有录音时，允许以已确认转写片段作为会议依据，不强制补充音频。待确认事项和未达成一致内容可以保留发布，但须明确标注。行动项无截止日期时不展示、不强制补齐；外部负责人的处理方式承接模块三待补充规则。

### 5.4 最终确认操作及异常

点击后由后端重新检查当前版本、权限和必要条件，通过后生成确认快照及确认编号，再进入发布配置页。

- 防止重复提交；确认失败保留内容，展示具体原因。
- 其他会话已修改内容时提示版本冲突，不确认旧页面数据。
- 确认后、首次发布成功前发生实质修改，保留历史确认记录，但当前稿需重新确认。
- 发布成功后不提供编辑或重新确认并再发布的入口。

### 5.5 后端接口需求与验收

需要后端接口：检查清单查询、基础信息保存、名单确认、成果版本校验、最终确认快照创建及查询。

验收重点：信息可就地补齐；问题准确定位；未保存、过期或无权限的成果不能确认；直接调用接口不能绕过校验。

## 6\. P02：发布配置页

### 6.1 入口与页面结构

最终确认成功后进入；已确认未发布或发布失败的会议可再次进入。

页面按“发布位置 → 发布信息及权限说明 → 预览与发布操作”组织。知识库和文件夹为联动选择，不强行划分为两个独立配置区域。

| **区域**             | **展示与操作**                                               |
|----------------------|--------------------------------------------------------------|
| 发布位置区           | 选择知识库，并在同一区域展示该库文件夹树；显示完整选中路径     |
| 发布信息及权限说明区 | 文档标题、标签、来源会议、确认编号、来源关系状态及知识库可见范围 |
| 操作区               | 正式文档预览、发布到知识库/重试发布                           |

### 6.2 联动选择发布位置

- 知识库选项显示名称、说明、访问范围及发布权限；无发布权限的库不可选并说明原因。
- 选择知识库后，在同一区域加载该库已有文件夹树，支持展开层级和选择文件夹。
- 选择文件夹后显示“知识库 / 文件夹 / 子文件夹”完整路径，后端使用稳定的库与文件夹ID关联，不仅凭名称匹配。
- 切换知识库时清除原文件夹选择，加载新库目录，避免路径错配。
- 未完成有效发布位置选择时，不能提交发布。
- 本页不提供新建、编辑或删除文件夹操作；文件夹继承知识库权限，不单独配置权限。
- 不提供推荐位置，由用户自行选择知识库及其文件夹；不基于AI推荐自动选择或提交。

### 6.3 发布信息与权限范围

文档标题应与最终确认内容保持一致，不能在发布页直接改标题后仍沿用旧确认。本页只读展示确认后的纪要标题；如需修改，返回纪要编辑并重新确认。纪要标题默认与会议名称相同，允许用户编辑，不因发布配置静默覆盖。

标签用于知识文档检索，不等同于会议分类；标签格式与数量限制由后端提供。发布配置按会议保存，不共用其他会议的临时选择。

明确显示目标知识库的可见范围，并说明文档继承库级权限，不另设文档权限。获得知识文档访问权限不代表同时获得原录音或引用材料访问权限。

### 6.4 异常处理

- 目录加载失败支持重试；加载期间不允许提交无效位置。
- 知识库或文件夹失效时，保留其他配置并提示重新选择。
- 发布权限变化时禁止提交，说明具体原因。
- 确认快照失效时返回最终确认。
- 配置加载或保存失败时保留当前输入并支持重试。

### 6.5 后端接口需求与验收

需要后端接口：可发布知识库、按库查询文件夹树、权限范围、按会议保存查询发布配置、发布前校验。接口可分别提供，但页面保持同一区域联动操作。

验收重点：切库清除旧文件夹；目录加载与选择一致；配置按会议保存；前后端校验权限和目录有效性；不会使用另一会议的配置。

## 7\. P03：正式文档预览弹窗

### 7.1 入口与展示内容

从发布配置页点击“正式文档预览”打开，展示确认后的纪要标题、会议信息、用户保存并最终确认的完整纪要正文、正式文档保留的来源标记及必要说明，以及目标知识库、文件夹和可见范围。

### 7.2 交互逻辑及异常

预览只读，支持滚动和关闭；关闭后保留发布配置。预览读取确认快照，不再次调用AI生成，不从正在变化的草稿拼接。发现问题时返回修改并重新确认，再预览发布。

预览加载失败提示重试，不将空白内容当作正式预览；确认失效时引导重新确认。

### 7.3 后端接口需求与验收

需要后端接口：基于确认编号生成正式预览内容及校验其有效性。

验收重点：预览、确认正文及最终发布正文一致；已排除敏感信息不出现在正式正文；预览失败不丢失配置。

## 8\. P04：发布进度与结果页

### 8.1 发布任务与进度展示

提交时再次校验发布权限、确认快照和目标位置，通过后创建发布任务。沿用原型阶段：校验确认版本、来源关系与发布权限 → 创建正式知识文档 → 写入发布记录及关联关系。

进度来自真实后端状态；没有准确百分比时只展示阶段及处理中状态，不模拟固定百分比。

### 8.2 发布中交互

- 提交后禁用重复发布按钮。
- 关闭弹窗或离开页面不取消已提交任务，返回或刷新后恢复任务状态。
- 任务始终绑定提交时的快照，不能混入后续修改；发布中禁止修改该次成果，避免与任务竞争。
- 内容确认状态与发布任务状态分别记录，不因任务异常丢失确认成果。

### 8.3 失败与重试

展示失败原因、保留的发布位置及是否可重试。

| **情况**               | **处理**                                   |
|------------------------|--------------------------------------------|
| 内容未变且确认有效     | 直接重试，无需重复最终确认                  |
| 权限或目录变化         | 重新配置有效位置后再提交                   |
| 未成功发布且成果已修改 | 重新最终确认后提交                         |
| 超时或结果未知         | 先查询任务状态，再决定重试，不直接创建新文档 |
| 文档已创建但响应丢失   | 恢复已有发布结果，不能再创建一份            |

实际系统不保留原型“首次强制失败”及“再次发布（幂等演示）”操作。后端仍须保证幂等。已经发布成功的会议不能通过失败重试接口绕过只读规则。

### 8.4 发布成功及结果页面

展示文档编号、发布版本、发布人、时间、目标路径、可见范围及处理记录。提供“查看正式纪要”和“返回会议”。记录关联确认版本及各次成功、失败、重试事件，不使用固定演示时间或数量。

成功后当前成果只读，不提供编辑、替换文档、新增发布版本或再次发布入口。文档后续被撤回或废止时，结果页显示最新状态及历史保留说明，不提供恢复或重发。

### 8.5 后端接口需求与验收

需要后端接口：发布任务创建、状态查询、幂等重试、正式文档写入、发布结果与历史查询。

验收重点：刷新不丢任务；失败不丢配置；重复请求不重复建文档；发布成功与文档实际可用状态一致；一期修订再发布限制在后端同样生效。

## 9\. P05：正式文档详情页

### 9.1 页面结构

| **区域**   | **内容**                                                   |
|------------|------------------------------------------------------------|
| 顶部       | 标题、正式文档编号、发布版本、时间、有效状态                   |
| 正文区     | 发布快照中的完整纪要，只读展示                              |
| 信息区     | 来源会议、确认人及时间、确认版本、发布位置、引用材料和证据状态 |
| 版本记录区 | 与当前发布版本有关的确认及发布记录，仅查询，不提供恢复发布   |
| 来源入口   | 访问原始证据                                               |

### 9.2 阅读与来源追溯

- 按目标知识库权限校验阅读权限；普通知识库查看者不能通过此页进入会议草稿编辑。
- 正文读取发布快照，不读取实时草稿，也不随企业语料更新变化。
- 来源入口分别校验原录音、会议内容及知识库源文件权限。
- 无权限、文件失效或无法定位时明确说明，不虚构来源内容。
- 证据数量和完整性显示真实结果，不固定显示“100%”。

### 9.3 后端接口需求与验收

需要后端接口：正式文档快照查询、知识库访问权限、版本记录、来源关系及源文件权限查询。

验收重点：发布正文稳定且只读；来源可追溯；文档权限不扩大会议或源文件权限；撤回、废止状态检查覆盖直接链接访问。

## 10\. P06：发布与撤回记录页及治理弹窗

本页延续原型能力，由知识空间管理员使用；具体管理权限及配置在模块六展开。

### 10.1 记录列表

展示知识文档、来源会议、知识库及路径、发布版本、发布人、时间、当前状态和操作。已发布文档可查看、撤回或标记废止；无治理权限时不提供对应操作，后端同样校验。

已撤回、已废止记录保留供授权治理人员查询，不提供恢复发布或重新发布。

### 10.2 撤回确认弹窗

点击“撤回”后展示确认弹窗，说明撤回后不再向普通知识库查看者提供该文档，历史确认版和发布版保留。取消不改变状态；确认成功后更新状态并追加审计记录。

失败保留原状态，支持查询结果或重试；结果未知时先查询，不能把前端超时视为未执行。

### 10.3 废止确认弹窗

点击“标记废止”后展示确认弹窗，说明文档将标记为失效，不再允许普通阅读、检索或AI引用。取消不改变状态；确认成功后更新状态及审计记录，失败处理同撤回。

废止后不能继续阅读，不参与检索或AI引用；列表、直接链接、下载及引用接口均检查失效状态。治理历史和审计记录保留供有权限人员查询，历史保留不代表允许普通访问正文。

撤回或废止后，该会议回看授权失效；会议详情、原录音、转写、核心要素、纪要及下载入口均不得继续提供回看，直接链接及后端请求也检查失效状态。保留治理记录与历史数据，不等同于删除会议，不提供恢复或重发。

### 10.4 后端接口需求与验收

需要后端接口：治理记录查询、撤回、废止、治理权限检查、状态传播与审计记录。

验收重点：权限受控；操作可追溯；历史保留；直接链接、列表和检索执行一致状态规则；不提供恢复或再发布接口入口。

## 11\. 公共要求及待定事项

权限、内容版本、确认快照和发布位置由服务端校验；发布任务与内容状态分离；配置、任务和历史可恢复查询；重复请求幂等；重要操作形成真实审计记录；源文件权限独立校验。

|------------------|-------------------------------------------------------------------------|

| 废止后的可见性   | 已确认不能阅读、检索或AI引用；授权治理人员可查记录，不提供普通正文访问     |
| 治理后的会议回看 | 已确认撤回/废止后回看授权失效，覆盖列表、直接链接、源文件及下载接口        |

# 功能模块五：会议列表管理

## 1\. 功能目标与范围

提供会议的统一查询与访问入口，支持管理自己负责的会议、查看参与过的会议，并根据当前状态继续处理或只读回看成果。

本模块包含我负责的与我参与的会议列表、搜索筛选排序分页、按状态进入会议、已发布会议只读详情、未发布会议删除，以及专题分组、专题维护、单场与批量归集。

录音、导入、转写校正、纪要编辑和发布操作沿用功能一至四，不在本模块另建处理链路。专题能力已确认保留在实际系统一期范围内。

## 2\. 角色与核心业务规则

| **场景**       | **规则**                                                                 |
|----------------|--------------------------------------------------------------------------|
| 我负责的       | 展示当前用户具有负责人权限的会议                                         |
| 我参与的       | 展示当前用户已被确认加入参会名单的会议，始终只读                          |
| 已发布会议     | 负责人也只能查看成果，不能编辑、重新生成或修改后再发布                     |
| 未发布会议     | 负责人进入当前处理环节，按该环节规则操作                                  |
| 发布中         | 查询发布任务，不编辑正在发布的成果                                        |
| 访问控制       | 列表、详情及操作接口均由后端校验，不能凭会议编号越权                       |
| 专题归集       | 只影响组织检索，不改变会议授权、成果正文、发布快照或发布位置                |
| 已发布专题调整 | 允许调整已发布会议的专题归属，但仅该会议负责人可以操作，包含单场与批量操作 |
| 删除限制       | 只有负责人可删除可删除状态的会议；曾发布成功的会议不能删除                |
| 状态路由       | 进入时按后端最新阶段与权限判断，不仅根据列表缓存；未完成会议继续原有链路   |

“未完成会议继续处理”仅适用于负责人。参会人不会因会议尚未发布而获得编辑权限。已发布会议专题调整是列表管理操作，不能借此修改成果；详情保持只读。

找到会议 → 根据最新状态继续处理或只读回看 → 返回列表并恢复查询上下文。

### 4.5 删除会议及确认弹窗

- 只有负责人可删除自己有权管理、尚未发布成功且满足删除状态规则的会议。
- 正在录音或暂停中的会议不可删除，先结束录音；发布成功的会议不可删除。
- 确认弹窗展示会议名称和删除影响。
- 成功后刷新列表、清理对应选择项；当前页为空时回到有效页码。

允许负责人主动删除仍在后台处理的未发布会议。确认弹窗明确将取消相关任务并删除会议及其全部关联数据，包括本会议上传/录制文件、草稿、转写、纪要和版本结果；成功后不可恢复。知识库引用仅删除本会议关联，不删除知识库源文件。后端负责完整清理并返回结果，不能只在列表隐藏；正在录音及发布中的删除限制仍保留。不自动清理历史数据；主动删除适用上述完整删除规则。

### 4.6 后端接口需求与验收

需要后端接口：按负责人/参会范围查询列表，按实际会议发生时间起止区间筛选，搜索筛选排序分页，查询当前阶段与可执行操作，删除及任务取消和全部关联数据清理。



## 5\. P02：专题分组视图及归集弹窗

### 5.1 入口与页面结构

从“我的会议”切换列表/专题分组视图。

展示专题名称、说明、会议数量及专题内会议条目，包含“未归入专题”分组。点击条目沿用P01状态路由。

专题仅一级，属于当前用户个人，不向其他用户共享专题；归集不扩大会议权限，统计与条目只包含当前用户有权访问的会议。专题与会议分类不同，不互相覆盖。

### 5.2 专题维护弹窗

- 新建：输入名称和说明；名称不能为空，校验失败保留输入。
- 修改：修改名称及说明，提交后同步列表与分组显示。
- 删除：仅空专题可删除；非空提示先调整会议归属；删除专题不删除会议。
- 专题仅个人可见、可维护；名称不设最大长度，在当前用户个人专题范围不可重名，由后端校验。失败保留输入与原状态，支持重试。

### 5.3 单场专题归集

负责人从列表专题字段打开归集选择，选择已有专题或移出专题，保存成功后刷新归属；失败保留原归属并说明原因。

已发布会议允许调整专题归属，但仅该会议负责人可以调整。参会人、普通知识库查看者及未获负责人权限的管理员不能借专题管理修改该会议归属。此操作不修改确认或发布快照，不使已发布成果进入可编辑状态。

### 5.4 批量归集

- 勾选会议后显示选择数量、“批量调整专题”和“取消选择”。
- 全选明确为当前页，不默认选择全部检索结果；切换筛选后避免隐藏选择导致误操作。
- 选择目标专题或移出专题后提交，逐场校验负责人权限及目标专题有效性。
- 已发布会议可参与批量调整，但每场均须由其负责人操作；不能以专题权限替代会议负责人权限。
- 部分失败展示成功、失败条目及原因，保留可再次处理的失败项。

### 5.5 视图与归集一致性

列表与分组使用一致搜索筛选范围，不因切换视图忽略条件。归集变化只更新组织信息和相应统计，不改正文、参会授权、确认成果或知识库发布位置；记录操作人、时间及归属变化。

### 5.6 后端接口需求与验收

需要后端接口：个人专题查询维护、单场归集、批量归集、分组统计、逐场负责人权限与并发校验、归属变更记录；名称不设产品最大长度，专题不可跨个人范围维护。

验收重点：专题不扩大权限；已发布归集仅负责人可改；列表分组结果一致；批量失败可识别；专题删除不删除会议；调整专题不改变发布成果。

保留全文复制，并提供Markdown、PDF、Word三种格式下载；下载内容与当前有权查看的纪要版本一致，已发布会议导出发布版。后端需要格式转换/文件生成、下载及版本和权限校验接口，撤回/废止后下载授权失效。

### 6.6 正式文档与来源入口及异常

“查看正式知识文档”进入功能四文档详情，独立校验目标知识库权限；会议访问权限不自动授予知识库访问权限。

查看材料或来源时分别校验源文件权限；无权限、失效或定位失败展示具体原因，不影响其他有权查看的成果。详情加载失败支持重试；无会议权限显示无权说明和返回列表，不显示内容片段。

### 6.7 后端接口需求与验收

需要后端接口：确认版转写内容、核心要素、完整纪要、原录音查询。



## 7\. P04：我参与的会议回看页

### 7.1 列表及入口

展示已确认加入名单的会议，包括名称、负责人、日期、时长、状态及成果可用情况。点击会议名称进入，回看包含原始录音、转写和纪要。

### 7.2 回看结构与版本规则

- 已发布会议复用P03只读结构，查看发布绑定的确认转写、核心要素和完整纪要。
- 未发布会议按功能二、三参会人只读规则展示，不进入负责人操作链路，不强制具有已发布成果。
- 未发布会议无确认转写时展示增强后转写；已有确认转写时优先确认版。
- 纪要未确认时显示默认版本，生成成功后即可查看最新有效版本，不提供生成或编辑入口。
- 发布前查看最新生成或已保存修订纪要，未保存内容及尚未采纳的候选不替代当前版本；发布后固定查看发布绑定版本。敏感核心要素对负责人和参会人均可见。
- 原录音回听权限及音文布局沿用既定规则；名单授权变化后后端重新校验。

### 7.3 后端接口需求与验收

需要后端接口：参会范围列表、最新可查看稿/发布绑定版本选择、会议及源文件权限校验、授权变化后的访问检查，以及Markdown/PDF/Word导出和下载。会议撤回或废止后，回看与下载授权一并失效。

验收重点：AI候选不授予权限；参会人全程只读；无成果显示真实状态；负责人操作不暴露给参会人；已发布与未发布转写版本规则分别生效。
