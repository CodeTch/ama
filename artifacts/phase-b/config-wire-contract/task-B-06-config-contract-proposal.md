# B06/B07 immutable configuration wire contract — proposed addendum
2026-10-22. READ-ONLY DESIGN; pending root full read and fresh independent technical review. Baseline brief: root 8da440d; coordinator reports V012 adopted at 5eb00d0f00af51ef95b24e9af209395c64e1e85b with unchanged B00-1.3 design. No peer implementation consumed.
This addendum supplies missing serialization/recovery rules only. Upon adoption it takes precedence solely for config/archive binding and the new TRANSCRIPTION_INPUT hash domain; B07 final proposal plus fix1 retain all confirmation/generation-v2/review-v2/final-v2 content projections, source-path restrictions and workflow gates. No DDL, column, business blob, attachment/file-reference kind, profile kind or production activation is added. The 15 generation profile kinds are unchanged.

## 1. Common grammar and two different hashes
All displayed object fields are REQUIRED and exactly enumerated; no unknown/duplicate key, omitted null, coercion, unrecognized enum, repair or defaults. Union alternatives have exactly their stated keys. Arrays are ordered except explicitly sorted sets. Null is permitted only where written. Primitive UUID/Hash/UInt and exact saved scalar strings follow B07 final §§1,4: lowercase nonzero UUID, lowercase 64-hex SHA256, raw unsigned decimal integer 0..Long.MAX_VALUE (no -0/exponent/fraction/quoted integer), Unicode scalars without normalization.
Version is an opaque nonempty 1..255 Unicode-scalar string without U+0000..001F/U+007F; compare exact UTF8 bytes. No trim/case folding, path interpretation, URL fetch, aliases, latest/default lookup or digest guessing. Max255 matches existing version columns and is not a user title/content limit. Slot and schema/contract identifiers below are fixed ASCII literals.
Transport JSON is strict UTF8, no BOM, malformed/overlong/truncated encoding or lone surrogate (including escaped strings/keys); exactly one object followed by EOF. Duplicate names are detected after unescaping. Reject all permissive Jackson ALLOW_* features, comments, extra roots and trailing invalid bytes. Use the adopted Jackson2 streaming Reader path with source-in-error disabled; do not write a JSON parser.
Canonical JSON writer J sorts object keys by unsigned UTF8 bytes, emits no insignificant whitespace/newline/BOM, plain decimal UInt, lowercase true/false/null, array order preserved. Strings escape quote/backslash as \"/\\ and every U+0000..001F as lowercase \u00xx; all other scalars are literal UTF8 (including slash and supplementary characters). This definition is independent of Jackson output defaults. Successful archive/manifest parsing requires raw bytes equal J(parsed typed value); different permitted JSON spellings are rejected as noncanonical, not silently rewritten.
ArchiveSHA=SHA256(exact complete J archive bytes), never the canonical binary digest or a header field. No archive contains its own SHA. A config ref carries that digest externally. ProcessingFingerprint=SHA256(CanonicalValueCodec({profile:"ama.transcription-input.v1",kind:"TRANSCRIPTION_INPUT",data:Manifest})); this is the sole added pure hash domain tag, not a persisted enum/kind. Existing six B07 domain tags and their projections remain unchanged.
For DB LONGTEXT manifest input, S2 supplies strict UTF8 of the exact retrieved scalar string; S1 rejects malformed Java UTF16 before encoding. Canonical persisted JSON rules make original bytes reproducible without inventing a new binary column.

## 2. Archive envelope, exact references and graph
```text
Ref = {artifactType:ArtifactType,version:Version,sha256:Hash}
Dependency = {slot:Slot,ref:Ref}
Archive = {archiveSchema:"ama.config-archive.v1",artifactType:ArtifactType,
           version:Version,definitionSchema:Schema,definition:Definition,
           dependencies:[Dependency]}
ArtifactType = PROCESSING_CONFIG | PARSER_CONFIG | PROMPT_CONFIG | MODEL_CONFIG | one of the 15 ProfileKinds
```
These are internal serialization discriminators, never new DB/file kinds. (artifactType,version) is the immutable archive identity; exactly one complete byte sequence may ever occupy it. Every dependency ref must match the target's parsed identity AND computed raw SHA. Required slots occur once, sort by ASCII slot; reject duplicate slots, extra slots, missing slots, duplicate archive identities even with equal bytes, and conflicting SHA demands for one identity.
The supplied graph is the exact reachable closure of requested roots, with no unused artifact. For a complete generation/review/final operation, requested roots are the union derived from all actually reached stored generation root pairs, processing manifests and selected review profile rows; unrelated caller-selected roots cannot justify extra artifacts. A DAG may share a dependency once; gray/black DFS or equivalent detects cycles over (type,version) before returning any binding. A same version under another type is not interchangeable. Each artifact must pass its known definitionSchema validator and all exact field/value/dependency rules; a syntactically valid arbitrary payload never establishes a profile.
Roots for processing have an expected full Ref in the manifest. Generation DB rows have only versions: resolve exactly PROMPT_CONFIG/prompt_version and MODEL_CONFIG/model_config_version from an authoritative immutable archive index; S1 receives requested identities plus raw bytes and computes root SHA itself. The original root SHA is bound by the recomputed saved generation fingerprint, which must match before final hashing. No mutable index can legitimately remap an old identity; detecting authoritative storage substitution is S2/ops' responsibility, not a caller boolean.
No archive stores meeting text, material bodies, model responses, credentials, private endpoint URLs, current storage paths or runtime host routing. Prompt instructions are configuration text only; fixture values must be synthetic. Config publication/storage integrity, approvals, retention and exact-version retrieval are later S2/ops responsibilities, independent of E03 governance and B04 business attachment kinds.

## 3. Processing archive definitions and complete minimum manifest
PARSER_CONFIG uses definitionSchema "ama.txt-parser-config.v1", version exactly "ama.strict-utf8-lines.v1", definition exactly {contract:"ama.strict-utf8-lines.v1"}, dependencies []. It selects the already reviewed parser, not a second implementation. Source SHA covers actual file bytes through EOF (including initial BOM/newlines); parsing accepts optional initial BOM, physical CR/LF/CRLF, skips String.isBlank lines without renumbering, preserves other text, rejects NUL, returns null speaker/times. Stable ID remains SHA256 of four UTF8 fields each prefixed by 4-byte big-endian byte length: profile, canonical file UUID, full source SHA, positive decimal physical line; first16 digest bytes with version8/variant10 bits. This is not confirmation or processing hashing.
PROCESSING_CONFIG uses definitionSchema "ama.import-txt-config.v1", arbitrary immutable Version, definition exactly {contract:"ama.import-txt.v1",manifestSchemaVersion:1,parseBudget:ParseBudget,canonicalBudget:CanonicalBudget}. Exact dependency slots: CANONICAL_CODEC, CONFIRMATION_HASH, PARSER_CONFIG; slot equals ref.artifactType. Codec/confirmation definitions follow §4; parser is the exact artifact above. No model, prompt or other dependency is allowed.
ParseBudget={maxSourceBytes:PositiveLong,maxUtf16CodeUnits:PositiveLong,maxSegments:PositiveInt}; limits apply per source file as the parser port specifies. CanonicalBudget={maxEncodedBytes:PositiveLong,maxDepth:PositiveInt,maxNodes:PositiveLong,maxStringBytes:PositiveLong,maxContainerEntries:PositiveLong}, exactly the adopted codec budget. All numeric bounds must fit Java target types; checked arithmetic, no saturation/truncation. These values are supplied/pinned technical resource protection, not chosen production limits.
```text
Manifest = {schemaVersion:1,profile:"ama.transcription-input.v1",meetingId:Uuid,inputId:Uuid,
 kind:"IMPORT",batch:{id:Uuid,kind:"TRANSCRIPT",files:[BatchFile]},
 sourceRevisionId:null,materials:{mode:"EMPTY",items:[]},
 configs:{processing:Ref,parser:Ref,model:null,prompt:null,
          profiles:[{kind:"CANONICAL_CODEC",ref:Ref},{kind:"CONFIRMATION_HASH",ref:Ref}]},
 base:{meetingRevision:UInt,subjectBusinessVersion:UInt,cancelEpoch:UInt},
 steps:[{ordinal:1,kind:"IMPORT_TXT",parentInput:null,priorOutput:null,
         source:{kind:"INPUT_BATCH",id:Uuid},config:Ref,parser:Ref,model:null,prompt:null}]}
BatchFile = {ordinal:PositiveUInt,fileId:Uuid,sha256:Hash,sizeBytes:UInt}
```
files is nonempty, distinct fileId and ordinal, ascending consecutive ordinal 1..N; complete immutable batch order, never request order after freezing. At least one nonblank parsed segment remains required by B06 before a saved valid transcript. Size zero is representable as a source fact, but empty source parsing fails NO_TEXT. This contract does not make empty files processable.
profiles is exactly the two displayed ASCII-kind-sorted refs, each matching its kind and the processing archive's corresponding dependency; parser matches PARSER_CONFIG dependency. The one step's config equals configs.processing and parser equals configs.parser; source.id equals batch.id. steps contains exactly this one initial step, ordinal1. All other alternatives are unsupported in manifest v1.
The manifest has no fingerprint/createdAt/actor/body/current title/config credentials. inputId participates intentionally; retries retain identical manifest bytes/ID/fence, new input IDs produce new fingerprints. Archive processing config never refers back to input/manifest/output, so there is no SHA self-reference.
Read/recovery agreement is exact: schemaVersion=transcription_input.manifest_schema_version=1; meetingId/id/batch.id/kind/sourceRevisionId map to the corresponding input row fields; materials EMPTY maps material_mode=EMPTY and material_snapshot_id=NULL. configs.processing.version=processing_config_version; parser.version=parser_version; model/prompt and their DB versions are all NULL. base.meetingRevision=base_revision; base.cancelEpoch=cancel_epoch. A '{}' row or test-manifest fixture does not satisfy any of these requirements.
Batch row id/meeting_id/kind must agree; the complete input_batch_file list must agree ordinal/file_id/sha256; file_object same meeting/id/full SHA/size must agree. sizeBytes equals file_object.size_bytes and sha256 equals file_object.sha256; both come from immutable file content metadata, not inferred from parser text, filename, ETag or storage route. input_batch.input_fingerprint is neither substituted for this full list nor claimed to have a newly defined algorithm here; B06 must separately own that batch hash before runtime writes.
Check input.input_fingerprint against the recomputed domain digest. Every supplied retry TaskSpec has input=(TRANSCRIPTION_INPUT,inputId), subject=(MEETING,meetingId), businessVersion=base.subjectBusinessVersion, cancelEpoch=base.cancelEpoch and matching fingerprint. A new input is computed before TaskSpec construction, not with a dummy digest. No replay may rebase the old manifest onto current meeting revision/subject epoch.
Producer revision processing_input_id, meeting_id, batch_id and input_fingerprint must match. Task-produced revisions additionally match actual producer_task_id→spec input/fence/fingerprint. Manual/mark/restore revisions inherit the concrete edited/restored input chain (producer task null), and confirmation hashes their actual saved content rather than original parser output. S2 verifies the actual edit/restore relation and all authoritative complete rows; S1 cannot invent an absent restored-from edge.
Excluded from processing digest: mutable meeting pointers/name/info/roster, storage location/backend route, status/error/createdAt/creator, task lease owner/attempt/priority/retry policy, live secrets and model service capacity. Included: all manifest fields, exact ordered file SHA/size, explicit EMPTY, profile/archive refs, parser and pinned budgets via processing archive SHA, fixed config/schema, base revision/businessVersion/epoch and every step field.

The table fixes its version to ContractLiteral; no caller-chosen replacement version or contract is accepted. This finite schema is a typed dispatch to the adopted semantics, not executable code, an arbitrary evidence map or a text assertion accepted without validation.
All these profile archives except CANONICAL_CODEC have exactly one dependency slot CANONICAL_CODEC to the same validated codec Ref. CANONICAL_CODEC has dependencies []. The root dependency set supplies other semantic profiles; there is no hidden transitive lookup.

## 5. Generation roots, safe semantic configuration and recovery
PROMPT_CONFIG: definitionSchema "ama.generation-prompt.v1", arbitrary immutable Version, definition={instructionText:ScalarString}; instructionText is exact nonempty configuration instructions, never expanded with meeting/material content. MODEL_CONFIG: definitionSchema "ama.generation-model.v1", arbitrary immutable Version, definition={protocolVersion:Version,modelIdentity:Version,credentialRef:Version|null,parameters:{temperatureMicros:UInt,maxOutputTokens:PositiveUInt,seed:UInt|null}}; temperatureMicros range0..2000000 denotes exact temperature/1000000, not a binary floating value. All listed model parameter fields are explicit; no provider defaults or unknown extra parameters. Actual supported provider/protocol/ranges require reviewed adapter qualification; a protocol needing other parameters requires a new schema, never omission into current runtime defaults.
Both roots have exactly the same 15 dependencies, each slot equals ProfileKind and ref.artifactType; ASCII sorted. They do not refer to one another. Every repeated Ref must be identical across roots and transitive codec references. This deliberately duplicates only small immutable refs, prevents two competing profile graphs, and avoids cycles. Differences reject PROFILE_UNAVAILABLE even if one root appears preferable.
credentialRef is a nonsecret opaque identity, not a credential value/version/endpoint. A ref's credential rotation retains semantic config identity and does not change fingerprint; changing modelIdentity/protocol/semantic parameter/instruction bytes requires a new immutable root version and SHA. Route relocation may change no semantic setting/model identity; otherwise it requires new config. Historical hashing needs no live credentials.
No concrete company endpoint/model identity/instructions/limits are supplied here. Synthetic test archives must identify themselves in fixture names/instructions and never install a production default. Parsing valid generation archives only permits pure consistency/hash tests; the documented company LLM contract covers text correction, not this minutes JSON/renderer protocol or quality/capacity/cancellation guarantees.
Generation recovery: resolve the two DB root versions→validate raw roots and complete common 15 graph→reconstruct adopted generation manifest including computed root SHA and exact profile refs→validate all fixed row/source/fence facts→recompute input_fingerprint. Any absent old fence/archive/fact is failure, not current-state repair. Historical TaskSpec businessVersion/epoch provide generation base fence because generation_input lacks those columns; require all tasks for the input agree, as adopted B07 requires.
Confirmation recovery: confirmation.revision_id→revision.processing_input_id→raw input.config_manifest + manifest_schema_version→full §3 manifest/row/archive verification→CONFIRMATION_HASH + CANONICAL_CODEC. Recompute exact ama.transcript-confirmation.v1 content: saved segmentId/ordinal/body/sourceFileId/sourceParagraph/startMs/endMs/speakerId and complete marks in KEY,CONCLUSION,DISPUTE,GENERATION_FOCUS order. Never invent parser timestamps/people or remove marks. generation root CONFIRMATION_HASH and codec Ref must equal this older owning chain, including SHA, not merely a matching version string.
Final recovery: final.minutes_revision_id→minutes_revision.generation_input_id→the exact generation root pair and verified saved generation fingerprint→FINAL_SOURCES and codec. Verify final snapshot references agree with that input; then apply unchanged fix1 complete occurrence projection. Manual minutes/restore inherit the old input; null legacy input fails PROFILE_UNAVAILABLE. Reviews independently resolve exact existing hash_profile to the matching REVIEW_HASH archive identity and verify raw codec dependency, not the final's current review config.
No archived profile can repair missing source provenance. fix1 unsupported ordinary local copied-element paths, ambiguous parser selection, altered suggestion input and unavailable D01 sources still fail before whole-graph digest. Recovery never guesses version from hash length, digest, latest template/model or current configuration.

## 6. Future variants, resource protection and pure seam
ASR/ENHANCE/multistep media and PINNED processing materials remain required later capabilities. They are NOT alternate successful v1 manifest shapes: unknown schema→PROFILE_UNAVAILABLE; a recognized unsupported processing kind/capability→CAPABILITY_UNAVAILABLE. No IMPORT sourceRevision/model/prompt/nonempty parent is silently interpreted as a future case.
Reserve the future design obligations, not an accepted wire variant: parentInput must be typed TRANSCRIPTION_INPUT plus exact ID/fingerprint; priorOutput must name an existing allowed typed output (saved TRANSCRIPT_REVISION or separately reviewed existing media output type), exact identity/hash and owning input/step; frozen step config and source revision/material graph must agree same meeting/batch. A saved prior transcript also maps source_revision_id. Each step freezes a NEW input only after prior output exists; reject future/self/descendant references/cycles. No invented parent IDs, new generic business blob/file kind or mutation of an earlier manifest; C01/C02/D01 must review full grammar/edges before enablement.
ArchiveReadBudget={maxArtifactBytes:long,maxTotalBytes:long,maxArtifacts:int,maxDependencies:long,maxGraphDepth:int,maxTokens:long,maxJsonDepth:int,maxNameUtf16:int,maxStringUtf16:int,maxStringUtf8Bytes:long,maxAggregateScalars:long,maxManifestBytes:long,maxBatchFiles:int,maxFactRows:long,maxFactEdges:long}. All >0; byte bounds <Long.MAX_VALUE; token/aggregate/dependency/fact counts apply cumulatively across manifest plus closure plus recursive historical inputs; no reset per node. Per-document artifact/manifest and UTF16/UTF8 limits additionally apply; checked sums and depth before recursion/allocation.
This external budget is bootstrap protection, not an archive dependency or business semantic input; no circular need to trust a budget before reading it. Pinned ParseBudget/CanonicalBudget/VALIDATION_BUDGET remain semantic configuration and cannot be replaced. A stricter operational budget may fail BUDGET_EXCEEDED but cannot change accepted result bytes or truncate. For success every pinned budget and external protective bound is met.
Cancel/interruption checks before byte reads, token/graph/row/hash loops and bounded sorting, after reads and before success. Count source reads with remaining+1 sentinel; consume complete EOF. Caller owns stream lifetime/deadline; decoder/reader never closes caller streams; blocking I/O cannot be made cancellable by a predicate alone. Take one defensive copy only after checking each supplied byte array length and cumulative byte budget; compute SHA, parse and canonical-byte compare on that same immutable copy, rejecting concurrent caller mutation by isolation. Memory bounded by capped input byte arrays, token buffers, retained nodes/rows and codec preflight; byte[] output additionally <=Integer.MAX_VALUE. No unbounded generic ObjectMapper tree, recursive fetch, dynamic class loading or remote resolver in S1.
Use existing safe failures: PROFILE_UNAVAILABLE for missing/unknown/conflicting archive/schema/identity/dependency/known profile definition, INPUT_INVALID for malformed manifest/row agreement/cycle/duplicate graph identities, FINGERPRINT_MISMATCH for stored digest/task mismatch, CAPABILITY_UNAVAILABLE for known unimplemented variants; retain INVALID_UTF8/INVALID_JSON/UNKNOWN_FIELD/INVALID_NUMBER/BUDGET_EXCEEDED/CANCELLED/READ_FAILED. Raw archive SHA mismatch is PROFILE_UNAVAILABLE. Noncanonical JSON is INVALID_SCHEMA. Error message is code only, no payload/key/path/cause/suppressed provider exception. Coexisting failures need not promise priority, but no partial handle/digest escapes.

## 7. Required independent vectors and handoff
Before accepting implementation: independent literal canonical manifest/archive fixtures and their SHA must be checked in by S1; expected bytes/SHA are derived outside production codec/JSON writer (small independent script or explicit byte assembly). Include full processing domain bytes/digest, not only primitives or production round-trips. This design provides complete schemas, not claims that such tests have run.
Positive minimum: a nonzero synthetic meeting/input/batch/file, one TXT source full SHA/size, no materials/model/prompt/parent, exact parser + processing + codec + confirmation archives, positive explicit budgets/fence; verify fresh vs reload bytes, current config change invariance, parser physical-line stable IDs, manual marks and original profile chain. Separate generation pair with all15 synthetic profiles and literal root SHA reconstructs confirmation→generation→final chain; no company call.
Required rejection/perturbation vectors: raw "{}"; missing required/null field; unsupported schema/version/contract; raw SHA mismatch; escaped duplicate key/BOM/malformed UTF8/lone surrogate/trailing root; noncanonical whitespace/key order; duplicate/missing/extra graph node/slot; wrong artifact type; contradictory codec; cycle/self-edge/depth/total byte/edge/token/count budgets; cancellation/interruption/stream ownership; manifest row disagreement; incomplete/reordered batch/changed SHA/size; wrong IMPORT nonnull model/prompt/source/parent; every base/config/schema/step field change; cross-meeting/task/fingerprint mismatch; missing previous-input facts; generation root profile disagreement; unknown old review profile; nullable final input; current-config substitution.
Strict future-parent rejection is tested now; no positive ASR/chained/PINNED test may be advertised as support until its grammar/schema is approved. Existing raw DDL fixtures remain unchanged and intentionally fail semantic recovery; legacy unknown manifest/archive data is unsupported, never auto-upgraded in place.
Rejected alternatives: caller boolean/typed-profile assertion cannot prove raw bytes; hash-only configs cannot recover settings; free-form payload maps hide unknown semantics; one mutable latest registry breaks history; embedding business data/new config tables or file kinds violates scope; binary-only LONGTEXT requires extra transport and duplicates an existing strict JSON adapter. Canonical JSON plus raw SHA plus the adopted binary typed digest gives separate, checkable responsibilities.
Next gate: root FULLREAD plus fresh independent SPEC/technical-quality review of this addendum; only then S1 author implements the new pure seam/tests. No source/POM/SQL/test/DB/services/Git/company operations or approval of production defaults occurred in this design round.
