## 1. Semantic scope

[A] Exactly seven subject kinds: `OVERVIEW` 会议概述; `DISCUSSION` 核心讨论; `CONCLUSION` 关键结论; `ACTION` 行动项; `RISK` 风险事项; `OPEN_QUESTION` 待确认项; `DISAGREEMENT` 未达成一致事项. Visual grouping cannot discard any kind.
[A] Separate directories: 敏感信息 (公司内部核心经营数据、政治敏感信息), 背景补充, 关联材料. These are not extra `minutes_element.category` values. Empty kinds display 未提取 without fabricated filler. Original “其他六类” wording conflicts with explicit seven-kind directory/B00 enum; preserve seven and expose exclusion controls only in the sensitive directory.
[A] Background cannot independently establish a meeting decision/action. Confirmed TXT segments are valid meeting evidence with no audio/time/speaker requirement. KEY/CONCLUSION/DISPUTE/GENERATION_FOCUS are complete multi-select transcript marks, not subject categories or proof of truth.
[A] Empty exclusions are default; selection affects next generated body, preserves source/core elements and existing authorized visibility. Sensitive paraphrase screening and final conflict resolution remain required; empty exclusions do not prove a complete detector.
[P] Initial executable profile is FULL + confirmed TXT + EMPTY materials/exclusions. Reserved union alternatives do not enable ELEMENT, nonempty materials/exclusions, DOCX/PDF/PPT/OCR/media or unqualified locators. Fail explicit capability checks until owning tasks implement them, rather than silently dropping inputs. B07 remains bounded; full D03/D04 functionality cannot be declared complete.
[A] B06 `ama.strict-utf8-lines.v1` is implemented but unwired; V011 preparation is not applied/adopted. B02 MeetingAccess runtime, B03 domain, B04 registry and reviewed B05 task completion remain prerequisites. No pending B05 observe implementation was consumed here.

## 2. Exact model JSON contract [P]

Schema version `ama.minutes-output.v1`; notation below defines JSON types, not a literal sample. Every field is required, unknown fields forbidden recursively, and null only where written. `elements` always has exactly these seven keys, each array may be empty. Nonblank body required; title is a suggestion and may be empty while information is incomplete.
```text
Output = {schemaVersion:"ama.minutes-output.v1",inputFingerprint:Hash,title:Text,body:NonblankText,
 elements:{OVERVIEW:Element[],DISCUSSION:Element[],CONCLUSION:Element[],ACTION:Element[],
 RISK:Element[],OPEN_QUESTION:Element[],DISAGREEMENT:Element[]},
 sensitive:Sensitive[],background:Background[],sourceRefs:Ref[],evidence:Evidence[]}
Element = {key:LocalKey,text:NonblankText,action:Action|null}
Action = {ownerMention:NonblankText|null,dueOn:Date|null}
Sensitive = {key:LocalKey,category:SensitiveKey,sourceIds:SourceId[]}
Background = {key:LocalKey,text:NonblankText,sourceIds:SourceId[]}
Ref = {sourceId:SourceId,locator:Locator}
Evidence = {target:Target,sourceIds:SourceId[]}
Target = {kind:"ELEMENT",elementKey:LocalKey,start:UInt,end:UInt}
       | {kind:"BODY",start:UInt,end:UInt}
```
`LocalKey` is ASCII `[A-Za-z][A-Za-z0-9_-]{0,63}`, unique across all output entries, response-local and never a DB ID. `SourceId` is `s` plus exactly 8 ASCII decimal digits, starting `s00000001`; assigned by server's deterministic ordered catalog, not by model. It resolves only within this inputFingerprint. Persisted source_locator IDs are separate server UUIDs; aliases never enter char(36) FK fields.
`Uuid` below is canonical lowercase nonzero 36-character hyphenated UUID; syntax never grants membership/access. Hash is exactly 64 lowercase hex. Text contains valid Unicode scalars, LF/TAB allowed, other C0 controls/DEL/NUL/unpaired surrogates rejected; preserve decoded text, no NFC/trim/case folding. Nonblank requires a scalar outside Unicode White_Space (version pinned in profile).
UInt is JSON token `0|[1-9][0-9]*`, parsed as exact integer within `0..9223372036854775807` and applicable resource/content bounds. Reject negative zero, signs, fraction/exponent, quoted numbers, booleans, overflow, NaN/Infinity; no floating-point conversion. This application bound is narrower than B00 unsigned BIGINT. PositiveUInt additionally >0.
Date is exact `YYYY-MM-DD`, valid Gregorian date in MySQL DATE range `1000-01-01..9999-12-31`; absent/relative/ambiguous source deadline stays null. ACTION alone requires Action; other kinds require null. Owner mention/date remain unreviewed suggestions, never resolved enterprise IDs/ACL or invented deadlines.
SensitiveKey [P] maps exactly `INTERNAL_BUSINESS_DATA|POLITICAL_SENSITIVE` to the two original labels; this is not a company classification dictionary. Model supplies neither exclusion flags nor support/confidence. Related-material directory is derived from fixed input, never invented by output.
Target offsets count Unicode scalars, zero-based half-open, with `0 <= start < end <= scalarCount(exact target text)`. ELEMENT resolves a unique local key; BODY is exact returned body. All source arrays in Evidence/Sensitive/Background are nonempty and duplicate-free. No-reference subject elements/body ranges remain possible but unsupported; no dummy evidence is manufactured.

### Locator union and source bounds

Each returned Ref must echo its sourceId's exact server catalog locator; all variant fields required, nonapplicable fields absent (not null), except nullable sectionPath. File version/hash and input role are pinned in catalog metadata, not supplied authoritatively by model.
```text
Locator = {kind:"TRANSCRIPT",transcriptRevisionId:Uuid,segmentId:Uuid}
 | {kind:"AUDIO",fileId:Uuid,startMs:UInt,endMs:UInt}
 | {kind:"PDF_PAGE",fileId:Uuid,pageNo:PositiveUInt}
 | {kind:"PPT_PAGE",fileId:Uuid,pageNo:PositiveUInt}
 | {kind:"WORD_PARAGRAPH",fileId:Uuid,paragraphNo:PositiveUInt,sectionPath:Text|null}
 | {kind:"TEXT_PARAGRAPH",fileId:Uuid,paragraphNo:PositiveUInt,sectionPath:Text|null}
 | {kind:"KNOWLEDGE_VERSION",materialRevisionId:Uuid}
```
TRANSCRIPT requires exact confirmation.revision_id + segment membership. AUDIO requires fixed original media and `startMs < endMs <= verifiedDurationMs`, no cross-file invented time. PDF/PPT/Word/text require exact pinned parser unit existence and matching sectionPath, not just a maximum count (TXT physical lines can have gaps). No time is synthesized for TXT.
KNOWLEDGE_VERSION resolves exact material revision/provider/file/external version/content SHA within pinned material snapshot. It promises version-level location only, not unsupported page highlighting. Missing immutable external version/hash/authorized content fails; never resolve “latest”. Pure TXT meeting evidence uses TRANSCRIPT, preserving its actual source_file_id/source_paragraph; TEXT_PARAGRAPH cannot bypass transcript confirmation.
Catalog ordering [P]: confirmed segments by ordinal first, then validated supplemental locators sorted by Encode(locator) unsigned bytes; deduplicate exact locator+role before alias allocation, fail above 99,999,999 entries or configured lower budget. Main meeting sources have role MEETING; materials role BACKGROUND regardless of their own claims. B v1 only catalogs confirmed TRANSCRIPT segments. Later capability profiles must define audio/document enumeration deterministically before activation.

### Validation and failure algorithm

1. Load fixed input/config/capability profile; reconstruct manifest/catalog and compare stored fingerprint before reading source through typed authorized ports. No model path/URL is fetched. Unavailable/corrupt/unknown input fails before model call.
2. Enforce pinned positive budgets during transport and parsing: response UTF-8 bytes, JSON depth/tokens, per-string bytes/scalars, total decoded scalars, element/directory/ref/evidence/link counts. Input/context/chunk budgets are separate. Fail rather than truncate; configured technical budgets are not product name/title limits or invented production capacity.
3. Strict UTF-8 with no BOM; streaming JSON duplicate detection before binding; one object and whitespace-only tail. Reject comments/fences/trailing documents, invalid escapes/Unicode, duplicate keys (including escape-equivalent spellings), unknown keys, missing required keys, wrong/null scalar types and unsupported schema. No substring extraction/auto-repair/drop-unknown behavior.
4. Check exact union/type/date/ID/integer/cardinality/action rules; fingerprint equals frozen input AND task. Reject duplicate local keys/source aliases, dangling references and unused returned Ref entries. All returned aliases resolve within input catalog; returned locator must equal its catalog value exactly.
5. Validate same meeting/input/confirmation/file/material/parser versions, actual page/paragraph/segment membership, safe bounds/target hashes and overflow-free arithmetic. Recheck source permission at display/read time independently of meeting ACL.
6. Structural success proves parse/membership/version/bounds consistency only. It does not prove entailment, numeric correctness, sensitive completeness, owner mapping or summary quality. A false numeric claim with a real source ID can pass structure; flag review, never call schema validation source-support proof.
7. Apply active exclusions to body-generation inputs, intermediate summaries and output review without removing authorized source/core-element review. Detectable literal reintroduction is a conflict; semantic paraphrase screening needs approved review. Nonempty exclusion with absent implementation is CAPABILITY_UNAVAILABLE, not success. Never claim zero leakage from a schema.
8. Return ValidatedOutput or sanitized failure; no partially accepted candidate/evidence. On commit recheck current task token/lease/version/epoch and aggregate state. Structural retries are bounded by pinned attempts/deadline; exhaustion fails without invented fallback output.
Safe [P] codes: MODEL_PROTOCOL_INVALID, OUTPUT_SCHEMA_INVALID, OUTPUT_BUDGET_EXCEEDED, SOURCE_NOT_IN_INPUT, SOURCE_LOCATOR_INVALID, TARGET_RANGE_INVALID, INPUT_UNAVAILABLE, INPUT_STALE, CAPABILITY_UNAVAILABLE, MODEL_TIMEOUT, MODEL_UNAVAILABLE, GENERATION_REVIEW_REQUIRED. Public/audit error contains code/trace and fixed field class only; no model text/excerpts/unknown keys/URLs/credentials/provider body or raw exception cause. Adapter policy determines retryability.

## 3. Immutable authoritative input and fingerprint [P]

Preferred R2 option: a canonical reconstructed manifest (immutable database graph + exact immutable configuration artifacts), not a new duplicate file. `generation_input` already pins confirmation/material/template/exclusion/element set/prompt/model/scope/target/base_revision. Confirmation pins transcript revision; revision pins processing_input/batch; batch pins files/order; segments pin text/source/speaker IDs/marks. Material snapshots pin revisions and external versions; template/exclusion/element rows are immutable. `durable_task` pins business_version/cancel_epoch and input ID/fingerprint. These are the authority, not current meeting pointers.
At enqueue lock/revalidate current authority and input graph using adopted lock order; allocate input ID, resolve immutable config versions, validate complete sets and build exact manifest below; insert input/task in one transaction with matching spec/fingerprint. InputId intentionally participates: same logical retry retains input, new snapshot has a different identity/digest. Worker reconstructs from that graph/task; never from current/latest settings. Input saved without its required task/config references is not usable.
Required invariants: prompt/model version resolution is append-only and returns exact stable bytes; version artifacts embed the manifest/output/hash/validation/title/support/exclusion/render/catalog profiles and all subordinate version+SHA references; root mapping cannot change beneath a version. Every task using an input must carry identical frozen subject version/epoch; retries cannot repin these. Source bytes/parse units/sets remain immutable and recoverable. Unavailable/mutated historical config fails closed; no default substitution.
No need to add a generation_input profile column if one fixed prompt/model configuration version deterministically pins the codec/profile dependency graph. `prompt_version` and `model_config_version` max 255 are references, not embedded JSON. Resolve and retain old safe artifacts; secret material is never in them. If current config infrastructure cannot guarantee this, that is an implementation prerequisite, not an assumed feature.

OPTION(T) is exactly `{mode:"NONE"}` or `{mode:"VALUE",value:T}`; NONE never means UNKNOWN. EMPTY materials permitted only while no materials are applied/pending and capability says EMPTY, not a bypass around unapplied material changes. PINNED materials need D01 immutable parser-version selection; if multiple parsed_document rows can exist, resolver version must choose one fixed profile/version, never newest; otherwise independent persistence decision is required before enabling.
The generation model does not receive mutable meeting name/info/roster/speaker-display lookups or current manual body as hidden prompt input. Its title is only a suggestion. Linked title resolution happens at adoption under unchanged root CAS and respects HUMAN origin. If product later requires these facts or custom requirements in prompt, freeze their exact revision/reference in an adopted recoverable contract first; base_revision alone cannot recover historical info or arbitrary user instructions.
For catalog sourceContentHash/sourceVersion: TRANSCRIPT uses confirmation.content_hash/revision_id; local file locators use file SHA/file ID; KNOWLEDGE_VERSION uses material content_hash/material_revision ID plus fixed external_version. Model-output Text control/blank rules do not rewrite/reject already accepted B06 source text: confirmation hashing preserves every saved scalar, including controls accepted by that source profile.
`input_fingerprint = lowerHex(SHA256(Encode(manifest)))`; fingerprint is not inside itself. Domain tag/schema and all complete fields participate. Task and candidate repeat it; no timestamps/latest config used as proxies for versions. B04 location migration changes routing but not immutable file identity/content hash. External material version + actual content SHA both participate; provider storage-version IDs are not confused with content revisions.
Encode [P]: N=0x00; false/true=0x01/02; integer=0x03||uint64BE; string=0x04||uint64BE(UTF8 byte length)||strict UTF8; array=0x05||uint64BE(count)||Encode(each); object=0x06||uint64BE(field count)||Encode(key),Encode(value), keys sorted by unsigned UTF-8 byte lexicographic order. No floats; lengths/counts checked before allocation. Every schema field present, no omitted defaults; no text normalization. Order-bearing arrays preserve ordinal; sets use declared sort. Encoding budget/profile is pinned as part of configs. N is reserved for schemas explicitly allowing null, not a substitute for NONE/EMPTY.
Confirmation hash alignment [P, B06 owns final rule]: SHA256(Encode({schemaVersion:"ama.transcript-confirmation.v1",revisionId,segments:[{segmentId,ordinal,body,sourceFileId,sourceParagraph,startMs,endMs,speakerId,marks}]})); optional values use OPTION. Marks always present including [], order KEY,CONCLUSION,DISPUTE,GENERATION_FOCUS; reject duplicates/unknowns. If B06 adopts another encoding, bind its actual version and vectors rather than silently rehash existing confirmations. Full text is read to hash, not copied into manifest. Changing any mark changes hash and invalidates current confirmation as adopted R6 requires.
For template/element/exclusion hashes encode a domain/schema-tagged complete immutable row projection: IDs/versions, template name/ordered themes; element IDs/category/order/body/support/action owner/date fields; exclusion row locator ID/full locator/category/reason. Include nullable fields with OPTION and sort rows by stable PK/order. Config hash uses exact immutable artifact bytes; source hash uses exact file bytes. Graph rebuilding must compare ID, complete fixed projection and SHA, not merely a hash of the same mutable latest query.
R2 fallback ONLY if necessary information cannot be reconstructed: propose a single immutable managed metadata file via existing file_reference attached to input, with new explicitly reviewed owner_kind/purpose and owner-lock-enforced singleton. This needs B04 registry recovery/deletion/authorization approval (PK does not enforce singleton); do not adopt it here. Alternative separately reviewed schema delta is root-owned. No manifest/config/epoch columns are added, no arbitrary JSON inserted in prompt_version or audit. Preferred graph strategy avoids this file for B-only scope; it cannot invent absent immutable parse/config guarantees.

## 4. IDs, provenance and evidence persistence

[A] Server creates persisted UUIDs. [P] Map source aliases to new/reused exact `source_locator` rows during candidate transaction; map local element keys to new minutes_element UUIDs; arrays determine ordinal. Candidate and adopted revisions have separate IDs; adopted evidence remaps to new target IDs. Model cannot assign row IDs or enterprise IDs.
source_locator maps exact union fields, nonapplicable columns NULL; evidence_link sets exactly one of element_id/minutes_revision_id and concrete locator_id. target_anchor [P] contains canonical JSON `{schemaVersion:"ama.anchor.v1",unit:"UNICODE_SCALAR",start,end,targetTextSha256}`. Owning FK identifies immutable target; verify range and exact target hash, never anchor by mutable heading. All fits existing B00 columns, no added category/provenance/quote/confidence columns.
Empty kind uses no rows and 未提取 presentation; don't insert fake blank text just to exercise NOT_EXTRACTED. [P] Candidate action_item uses owner fields NULL, due_on only a structurally valid suggested explicit date. OwnerMention remains transient review data until an approved durable representation exists; no enterprise ID mapping from text. Unknown/external owner selection remains unresolved prerequisite, no automatic ACL from owner/speaker changes.
Derived provenance labels: 发言=confirmed meeting transcript (optional media supplement); 材料=fixed local/knowledge document; 知识背景=BACKGROUND role; 模型整理=generated synthesis, compatible with source labels; 依据不足=absent/inadequate/unreviewed support. They are not extra subject categories or mutually exclusive confidence levels. Source type/role is derived from pinned graph and source links, never accepted solely from model text.
[A] Element support enum SUPPORTED/PARTIAL/UNSUPPORTED/NOT_EXTRACTED; links exclude NOT_EXTRACTED. [P] Structurally valid links default PARTIAL (“引用可定位，语义待核对”), absent direct evidence means element UNSUPPORTED with no dummy evidence_link. Partial may represent review-pending, not a calibrated probability. Explicitly review this conservative interpretation before implementation.
[P/R4] SUPPORTED requires authorized review of exact target text/hash and complete source set. B00 stores classification but no dedicated review attestation fields: use existing revision/audit identity/time plus a specifically agreed safe evidence-review event/reference convention, or separately review an immutable attachment strategy; do not invent a completed durable reviewer record. B07 may produce review-pending candidates without claiming final-quality completion. Edits reset affected support and append new versions; retained historical links do not automatically support new wording.
CONCLUSION/ACTION with only BACKGROUND sources is UNSUPPORTED even if links support contextual facts. Presence of any meeting link still does not establish entailment. Source unavailability/permission is separate from support; never show unauthorized excerpt or manufacture substitute source. No invented numeric confidence.
R3 storage gap: B00 has no generic background/sensitive-detection/owner-suggestion result table, and sensitive_exclusion only persists explicitly selected exclusions. Related materials can be derived from material snapshot; background sources can be derived from locators/roles, but arbitrary generated background text and unselected sensitive detections cannot be losslessly recovered from those rows. Do not overload minutes_element.category/body or encode hidden content in source_locator.
R3 options: (a) B07 exposes derived directories and explicit “完整检测待D03” capability; discard neither promised durable outputs nor silently claim their persistence; remove unsupported output fields from executable profile only through revised reviewed schema; (b) root approves immutable result/provenance attachments through existing file_reference with new owned kinds/purposes, binding input/target IDs/hashes and lifecycle; (c) separately reviewed D03 schema. Preferred immediate work is pure contract/validator; root must settle durable representation before enabling outputs that require it. New file_reference codes are proposals, not adopted facts.
Sensitive dual-label edge: sensitive_exclusion PK(revision_id,locator_id) permits one category per locator. Preserve both detections in prospective directory representation; options are explicit category-specific locator rows at identical physical bounds (no column change, needs reviewed dedup/selection rules), or reviewed schema change. Do not drop a label or flatten category into an undocumented delimiter string. This does not block empty-exclusion B profile.

## 5. Candidate, first effective save, manual protection and final gate

[A] POST `/meetings/{id}/minutes-generations {transcriptConfirmationId,expectedRevision}` checks owner permission, saved/current confirmation, idempotency and fixed input; returns taskId, later candidateId/inputFingerprint. Name/classification/roster may be incomplete. Source content is untrusted data and cannot instruct tool use, arbitrary networking, publication or authorization.
[A] Completion rechecks full immutable task spec, owner/attempt/unexpired lease, fingerprint, subject business version/cancel epoch, meeting/base revision and active lifecycle/governance under adopted lock order. Atomic candidate/body/elements/evidence/result registration + task/audit/outbox leaves effective pointers untouched. Rejected fenced callback writes no domain content. Historical retention of a late response needs a separate explicitly validated path, not writing after B05 completeWithEffects refuses.
R1 conflict: requirements III §5.2 say first successful generation forms a readable AI version; original B07 and B00 say candidate first and explicit adoption alone updates current body. Neither can be silently erased. Option A (minimal safety-preserving API coordination, recommended for root review): first candidate opens owner workbench with explicit “保存/采用首版”, same adoption API; “first effective saved result” means adoption committed, and participants see it then. UI/product acceptance must acknowledge this extra first-save action.
R1 option B: original confirm-and-generate action explicitly authorizes guarded first-save acceptance only when no effective body/manual title exists and captured root revision/epoch remain unchanged; still persist candidate then use one atomic internal adoption command, otherwise PENDING. This is automatic first adoption and changes B07/B00 authority; it is not adopted here. It cannot be inferred from “generation success”. Option C: keep candidate-only and mark first-result readback requirement incomplete until root rules. No option exposes PENDING to participant-current queries or overwrites a human draft.
[A] POST `/minutes-candidates/{id}/adoption {expectedRevision}` accepts PENDING only, rechecks owner/source authority/current confirmation/settings/input fingerprint, root baseline, target set revision and epoch. Compare against candidate's frozen input identity, not freshly allocated input ID. Conflict 409 preserves 人工稿, title and candidate. Idempotent adopted-request replay returns original safe result after current authorization.
[A/P] FULL adoption appends new effective saved body/set and remapped evidence, marks candidate ADOPTED, updates pointers and root/subject versions, clears current final confirmation and records audit/outbox atomically. HUMAN title remains exact even when body adoption is explicit. LINKED title defaults to meeting name under same unchanged-root CAS; AI title is suggestion until explicitly selected. Explicit relink alone changes HUMAN→LINKED; no AI/rename side effect does. Restore creates new revision, never rewinds history.
[A] Auto-save and explicit save share CAS; errors/conflicts preserve local input, saved body does not overwrite elements. Unsaved editor content is not a server revision: UI requires save/discard/continue before adoption and preserves it across task refresh, even if server CAS passes. No worker completion writes into editor state.
[A] Current-settings generation success may clear needs_generation while candidate remains PENDING; final still blocked. New elements/template/exclusion changes reassert flag and make old candidates incompatible. ELEMENT adoption later changes only target elements, keeps body and marks generation needed; v1 rejects unsupported scope.
[A] B08/D03/D04 final gate checks saved title/body; current confirmed transcript/marks; applied material/template/exclusion/element versions; complete source relations; no running/PENDING candidates or unapplied changes; resolved sensitive conflicts; meeting support for important conclusions; action rules; current authority; required name/category/confirmed roster. Empty roster, optional actual date and missing deadline remain allowed. Enterprise category dictionary is real configured data, never a hardcoded fixture list.
[A] OPEN_QUESTION/DISAGREEMENT can remain explicitly labeled and publish; don't demand all risks/questions be SUPPORTED. Final source_manifest_hash freezes exact evidence/locators/anchors and any approved review references. Published results are read-only; withdrawn/invalidated results do not restore/re-publish. Existing approved mail/governance remain separate: saved-version controlled links to authorized confirmed enterprise members, UNKNOWN reconciled, no generation-triggered sending or implicit body access/global reuse/cleanup.
