# B05 functional evidence

These are timestamped historical runs against explicitly owned local MySQL containers. They are not claims that all snapshots show the latest fixture state. The full report is `docs/acceptance/b/task-B-05-report.md`; consumer contract is `docs/acceptance/b/task-execution-integration.md`.

- `execution-manifest.json` counts suites named by each actual log. Early `*-xml` folders copied with a wildcard may contain older unselected reports. Do not sum such directories or count them as newly executed tests. Final `final-owned-green-xml`, `fixed-recovery-and-reconciler-xml`, and `final-authority-lifecycle-xml` contain only explicitly selected classes.
- `schema-red`, `task-red`, `external-red`, `permit-red`, `consumer-red`, `worker-process-red`, `reconciliation-worker-red` preserve genuine missing-behavior failures. The initial task rollback case passed with a stub and is NOT evidence of feature RED. Other failed attempts (syntax, test composition, concurrent configuration/retry, dynamic-port recovery) remain present with diagnosis in the report.
- `raw-review-*.sql.txt` were raw review-only candidate bytes on 45009, not formal V010 history. Only the separately ACKed frozen V010 was formally migrated on the positive, negative and fixed-recovery fixtures. `coordinator-freeze-ack.json` records the pre-first-apply SHA ACK.
- `formal-before`, `formal-first-success`, `negative-before/after`, `final-positive`, and `recovery-*` snapshots retain complete actual metadata, DDL, rows and Flyway history. `expected-metadata.json` is filtered from independent B00-1.2 evidence, whose full source SHA is recorded. `final-verification.json` records exact comparisons, not handwritten expected counts.
- The original dynamic positive endpoint 45979 changed to 45951 on its one authorized Docker restart. The original env remains local and unchanged; a derived env uses the same container's actual current port. That failed 30-second readiness check is not a product RED or a successful recovery test. A separate fixed-loopback 44847 fixture completed its one authorized restart with identical ID/args/port/volume and a measured 1476 ms from actual DB connectability to task completion.
- All four own containers are preserved; `final-fixture-inventory.json` contains their IDs/ports/volume identities and states. Original 46037 and all other owners' fixtures were not touched. No failed history was reset/repaired/removed.
- `fixture-wrapper.jsonl` records actual local run arguments. Script copies `b05-start-functional.py`, `b05-start-recovery.py`, `b05-refusal.py`, and `B05Migrate.java` are provenance copies of scripts originally run from `.tools/`; their relative paths assume that original location. `capture.py` runs from this evidence directory. Credential env files are deliberately excluded; `preserved-environment-hashes.json` only hashes the local preserved original/derived env.
- Process-local native-AIO-off was coordinator-authorized for NEW B05 functional fixtures after observed kernel AIO exhaustion. Actual @@innodb_use_native_aio=0 is in snapshots. This does not qualify native I/O, real company protocol, VIP/failover, production capacities, or 100-recording load.
- `final-web-unit.log` is the failed launch caused by missing local node_modules, not a skipped passing suite. After pinned `npm ci --ignore-scripts`, `final-web-unit-green.log` and `final-web.xml` show 8 executed passing tests. Python final JSON/log show 74 passing tests. Java final unit XML show 33 passing tests.

All credential-bearing local envs and generated target binaries are excluded from the committed evidence. `file-sha256.json` hashes evidence; the source hash manifest covers owned source/doc files separately. The exact handoff stash is retained, and source-only archive verification is under `../b05-formal-handoff/preservation-verification.json`.
