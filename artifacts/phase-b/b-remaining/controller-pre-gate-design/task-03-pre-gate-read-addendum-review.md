## PRD-01 — P2 — Freeze failure precedence across pre-gate discovery and authorization

**References:** addendum lines 24, 26, 30 and 34; adopted R1 lines 96–106; frozen `backend/adapters/src/main/java/ama/storage/JdbcFileRegistry.java:242–277`, `:298–310`; frozen `backend/adapters/src/main/java/ama/meeting/JdbcMeetingAccess.java:92–108`; controlled-runtime spec line 73.

The proposed sequence calls prepareRead and performs complete reference/provider discovery before the final READ gate, but does not specify what happens if those steps fail. These are real fallible operations: reference overflow, unsupported complete-provider composition, absent or unknown profile, missing current pointer/producer chain, or a bounded graph/text failure can occur before prepareRead returns. Lines 26/30 expressly require rejection, without placing observable rejection after fresh authorization.

The frozen generic path first obtains only an AVAILABLE file's meeting ID, retaining NotFound when that minimal discovery cannot select a meeting (lines 242–247). Once a meeting is selected it obtains the fresh READ gate (251–256), then examines reference rows and invokes policy prelock (257–277). An outsider or revoked member therefore cannot receive reference-graph-specific outcomes in place of that gate's denial. Moving graph-dependent failure ahead of the gate can turn the same existing-file denial into NotFound or capability/unavailable behavior according to private graph state; a blanket conversion to 503 would not preserve the existing denial contract. The finding is about newly moved graph/reference information, not a claim that the old minimal AVAILABLE-file discovery concealed all existence information.

The same gap matters for planned history/worker reads: they require owner EDIT on the same genuine READ handle. A READ-authorized member must not receive owner-only graph/preparation failure details before that operation-specific authorization. No second gate is needed to preserve this ordering.

The generic authorized case also needs an explicit outcome distinction. Frozen policy NotFound is scoped to a reference and permits another independently valid reference (272–275 and 298–307); adopted R1 line 100 preserves that rule while forbidding arbitrary-error fallback. A complete preparation that genuinely discovers no current-effective scope must not unconditionally abort an otherwise valid legacy alternative or be changed into an observable 503 merely because the new preparation call occurs before the reference loop. Conversely, budget/unsupported/incomplete-protocol failures must never be disguised as NotFound to obtain legacy fallback. This is one failure-routing omission, not a request to weaken finalization.

**Required bounded revision:** specify a registry-owned, bounded preparation outcome (or equivalent exact exception handling contract) that distinguishes successful data preparation, genuine ineligible-reference outcome, and fatal preparation failure. Retain safe internal failure data without returning graph-dependent details before the existing single final authorization. For a syntactically valid request with a known target meeting, acquire that one fresh READ gate, and required owner EDIT on the same handle for history/worker, before deciding the observable stored failure. Authorization denial takes precedence. A failed preparation authorizes no domain/source/task acquisition, pin or open. On success, proceed with the exact prepared graph only; never hash, parse or rediscover missing roots under the gate. No automatic retry or second identity/gate acquisition is introduced.

Explicitly preserve the original generic minimal file-to-meeting NotFound case and input/ambient-transaction rejection. For generic genuine current-ineligibility, preserve narrow independently-valid-reference fallback after authorization; for fatal unavailable/budget/protocol/unsupported-composition failures, abort after authorization even if a legacy reference looks valid. Keep legacy-only construction/dispatch independent of B06 preparation requirements, and state how finite discovery budgets apply without silently adding an unconfigured complete-provider prerequisite to legacy construction. Cancellation/interruption must stop work promptly and retain its semantics; do not catch it as a reusable preparation failure and continue authorization work on a cancelled request. System-wide inability to perform authorization cannot be made successful by this sequencing rule; it must remain a safe closed failure.

An internal outcome is data, not a public injectable preparation or capability. Its exact representation is an implementation choice, but the error ordering and narrow fallback behavior must be fixed in the design and tests. A catch-all 503, catch-all NotFound, preliminary authorization transaction, or hash-under-lock workaround does not close this finding.

**Closure evidence:** design names the outcome classes/handling phases and single-gate denial precedence. Prospective tests compare outsiders, revoked members, ordinary members and owners across valid graph, missing/current-ineligible graph, unknown profile, reference overflow, and unsupported provider composition; verify the known-meeting denial remains the same and owner-only history/worker failures do not preempt EDIT. Test an independently valid unchanged legacy reference alongside a genuinely ineligible complete reference, then separately alongside a fatal complete-preparation error. Assert no open on denied/fatal paths, no B06 preparation on legacy-only paths, no second gate and no hashing beneath the gate.

## Accepted design properties and prospective implementation gates

These are required implementation evidence, not additional open design findings or tests executed here.

1. **Preparation is data; held scope is authority.** Lines 10–20/24 prohibit caller preparations and bind private issuer, actor, meeting and exact operation/selector. Verify actual configured policy identity as well as authority issuer; two policy instances sharing an authority do not become interchangeable by value. Copy, foreign issuer/DataSource wrapper, altered selector/file/actor/meeting, and preparation-to-scope substitution must fail. Preparation intentionally has no transaction holder; only final scope/proofs bind the genuine gate, same DataSource and actual active holder. Ended/suspended/foreign holders cannot consume that final authority.

2. **Complete graph equality.** Lines 20/24/26/30 cover exact current pointer or explicit history chain, owner when required, complete ordered members, parent edges, input/batch/profile and full actual producer spec. Test missing, additional and changed rows as well as changed values; compare whole sets, ordered membership and parent closure, not sampled rows or subset containment. Reject cycles, cross-meeting edges and ambiguous lineage. Changed references between detached discovery and the final gate fail without selecting a new provider, expanding roots or recomputing a hash. Stale preparation may be rejected even if a fresh read could succeed.

3. **Bounded reference discovery.** LIMIT budget+1 must stop before an unbounded result allocation and reject excess; it cannot truncate to an authorizing first N. Both detached discovery and final re-read require finite bounds and complete equality. Multiple complete instances remain unsupported before sources. A current request remains a claim: it cannot make pending/RAW/history readable through generic download. One supported provider's multiple authentic scopes still require complete union acquisition and identity-based deduplication under adopted R1.

4. **Computation and acquisition boundaries.** Prepare/hash finishes without a transaction, identities, row locks, storage/network/archive stream or provider-token/name transfer. SQL length-gated LONGTEXT projection must enforce the limit in the same projected read, with bounded character streaming and exact UTF8/scalar/UTF16 aggregate accounting; a separate unlocked measure then unrestricted read is insufficient. Row/member/edge/depth/task/config allocations admit limits before growth. Exercise cancellation during discovery, streaming, graph traversal and producer computation; no partial preparation becomes usable. Final locked equality stays DB-only and bounded, with no canonical hash or strict JSON parsing.

5. **One final genuine authorization and private post-commit open.** R1's full domain rank, complete source union, all tasks before attempts, once-only finalization, authentic receipt checks and actual producer provenance remain binding. History producer success is distinct from worker RUNNING/unfinished-attempt/live DB-expiry authority. A public DTO's expiry cannot rescue a stale worker; genuine renewal need not match old DTO expiry. Finalizer failure, reference changes and failed commit prevent the sole private storage open, which occurs outside a DB transaction after successful finalization and commit. Preserve exact historical backend/key checks and stream closure.

6. **Additive compatibility.** All new CompleteReadPolicy methods are abstract; unchanged two-method legacy providers remain usable. The contextual first-bind/member method is retained. Generic complete dispatch must explicitly call prelockCurrent using the configured preparation; absent preparation cannot fall through the old INPUT_BATCH_FILE method. Planned requests reject unsupported providers. Compile checks alone do not establish unchanged legacy behavior: retain positive legacy, effective current owner/member, explicit owner RAW/WORKING history and worker cases, alongside pending/obsolete/generic-history negatives.
