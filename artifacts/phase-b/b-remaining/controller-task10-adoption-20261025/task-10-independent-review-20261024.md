## Important I1 — Unexpected preparation failures are converted into successful concurrent replay

**Locations:** `backend/adapters/src/main/java/ama/transcript/JdbcMinutesSavedCommands.java:13-15`, `:30-31`, `:53-54`; `JdbcMinutesReviews.java:15-16`; `JdbcMinutesSettingsCommands.java:18-19`; `JdbcMinutesDecisions.java:9-10` (all under the same transcript directory).

**Observed behavior:** Each new command catches arbitrary `RuntimeException` from preparation, excluding interruption/CANCELLED only. Its final transaction then claims the receipt, acquires a fresh gate, matches the request, and returns an already accepted result **before inspecting the saved failure**. For example, saved commands line 15 executes `if(stored.result()!=null)return ...` before `if(failed!=null)throw failed`. Thus, after the initial lookup misses, an unexpected `IllegalArgumentException`, null/programming failure, or non-recoverable corruption during S/A is hidden if the same key commits concurrently. Current F authorization is still performed; this is not a claim of a simple unauthenticated write bypass.

**Why this is a defect:** Adopted design §3.5 explicitly permits only named ordinary preflight failures to recover a concurrent accepted result, and prohibits catch-all recovery for auth denial, cancellation, corruption and programming errors. A normal accepted replay found at the initial lookup is different from suppressing an observed non-ordinary failure after a miss. The existing changed `JdbcSavedTranscripts.mutate` has an explicit non-ordinary-failure check before accepted return, and generation commands have an ordinary-failure classifier. The new minutes commands omit this distinction across all these operations. A committed winner can therefore turn an internal integrity/programming failure into an apparently successful API outcome, concealing a broken preparation path.

**Required fix:** Use a precise shared classification/protocol for deferred ordinary preparation errors. Preserve fresh authentication and digest matching, but do not let a non-ordinary saved error reach the successful replay branch. Preserve accepted replay precedence over *ordinary new-command* readiness/config/CAS failures; do not repair this by moving every failure ahead of all replay. Corruption must not be indiscriminately labeled ordinary just because it shares a broad unavailable code.

**Minimum focused validation:** After a genuine initial miss and concurrent same-key accepted winner, demonstrate ordinary archive/readiness unavailability still restores the winner, while an injected unexpected programming/non-ordinary integrity failure is propagated with no new business/receipt/event effects. Exercise the common mechanism for saved/review/settings/decision callers; no broad suite repetition is requested.
