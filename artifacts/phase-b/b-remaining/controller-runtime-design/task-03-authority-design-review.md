## Findings and exact closure gates

### ADR-01 — P2 — Bound the initial identity capture, before the registry gate materializes names

**References:** design lines 100, 138, 176 and 204; `backend/adapters/src/main/java/ama/meeting/JdbcMeetingAccess.java:48–56`; `backend/adapters/src/main/java/ama/transcript/JdbcProcessingFactsReader.java:66–72`; `backend/adapters/src/main/java/ama/meeting/JdbcMeetingRepository.java:68–78`.

The design promises all LONGTEXT bounds before transfer, but both `registry.lock(...)` and ordinary queue identity preparation reach `JdbcMeetingAccess.captureIdentities`, whose query selects `display_name` and immediately calls `getString`. That happens before the proposed B06 authority can apply its later domain/source bounds. The existing standalone reader already recognizes this problem and performs exact locked length measurement before calling access.lock; merely preserving that reader does not protect the new intake, current/history read and worker/queue paths.

**Required revision:** define one concrete bounded authorization entry/configuration that covers the initial actor/current-owner identity phase, including skip-locked preparation. Prefer a shared authorization-only projection of enterprise ID and status where a display name is unused, reusing the same B03 issuer, identity ordering, holder checks and ACL logic. If names are carried, enforce explicit UTF8/scalar/UTF16 and cumulative bounds under each identity lock before materialization, with the complete identity union sorted before roots. A preflight without a retained lock is insufficient because the name can change before getString. Do not add a second weaker access implementation or rely on a later check.

Preserve the existing roster save consumer: it uses `Person.name()` to persist the real full name. Do not replace that name with null/empty/truncated data or impose an undocumented product name cap. Specify the bounded entry/constructor once and how registry-owned reads and queue preparation use it; avoid adapter-specific duplicate ACL paths.

**Closure:** revised design identifies the exact entry and callers, complete identity ordering and skip semantics. Implementation gates must show that oversized/supplementary-character names are either never selected on an authorization-only path or rejected before transfer on a bounded name path; blocked identity with skip=true must not block or acquire a root; changed owner must fail coverage without late identities. Existing roster full-name behavior must remain intact. Normal-sized intake/worker/current/history paths must still authorize correctly.

### ADR-02 — P2 — Separate legacy download compatibility from mandatory planned-read finalization

**References:** design lines 25, 48–60, 62, 117 and 143; `backend/core/src/main/java/ama/storage/FileReferencePolicy.java:4–24`; `backend/adapters/src/main/java/ama/storage/JdbcFileRegistry.java:238–318`.

The design says every new policy method defaults fail closed except singleton readMembers, while generic download must now invoke finishRead for each authentic domain. Existing policies implement only prelock/validate. If their inherited finishRead throws, otherwise unchanged legacy downloads fail. Making finishRead an unconditional no-op instead would allow a newly introduced planned-read policy to omit the producer/lease final check while apparently satisfying the new protocol. Both sides need an explicit dispatch rule.

**Required revision:** freeze a small distinction between legacy context-free policy proofs and policies participating in the complete planned-read protocol. One implementable minimal option is an additive nested extension interface for planned/complete reads, with an explicitly implemented finishRead, and registry.read rejecting policies that do not implement that extension. Generic download must call that finalizer for B06 extension-policy scopes even when reached through context-free prelock; it must retain the old prelock/validate behavior for unchanged legacy policies. A legacy-only default no-op is acceptable only if new planned-read registration cannot accidentally inherit it. No caller boolean may choose the legacy bypass for a B06 scope.

Keep genuine NotFound alternative-reference fallback, but never convert an arbitrary finalizer error or absence into readable=true. Failed B06 finalization must not open storage. This distinction must not broaden generic download to owner-history/worker selectors.

**Closure:** revised signatures and dispatch specify which default applies to each path. Tests use an unchanged legacy implementation successfully, reject an unsupported new read request, prove B06 current generic download runs finishRead exactly once per authentic scope, and prove throwing/missing finalization never opens storage. Verify effective owner/member positives plus pending/obsolete/history negatives and multiple-reference fallback. Compile compatibility alone is insufficient.

### ADR-03 — P2 — Make source receipt validation against the expected gate and complete set explicit

**References:** design lines 42–44, 62, 66–68, 81–84 and 94; existing private gate/proof checks in `backend/adapters/src/main/java/ama/storage/JdbcFileRegistry.java:390–410`.

The design requires insertAndReadNew to authenticate a private B04 source receipt against its exact reservation gate and complete file set before inserting anything. The proposed public operation `sources(LockedSources held)` only returns detached CompletedSource values and does not expose an expected-gate/full-set assertion. Those values cannot themselves prove that the receipt belongs to this reservation. The one-gate-per-holder invariant helps, but the cross-adapter contract should not depend on B06 inferring hidden B04 state or treating matching DTOs as the gate proof. This is an API-contract omission, not a claim that an exploit has been demonstrated.

**Required revision:** replace the proposed getter with a narrow verifier/getter such as `sources(LockedMeeting expectedGate, LockedSources held, List<String> exactFileIds)`, or an equivalent `requireSources` plus getter. B04 checks its own private receipt class/issuer, exact DataSource/actual active holder, exact Gate identity, acquisition phase and immutable complete unique set before returning metadata. This does not grant bytes, insert rows or expose a pin. B06 still compares all original metadata observations and authenticates its own reservation; member ordinal/order remains a B06 graph check, separate from B04's canonical source set. The binding handoff must reuse and consume the same checked receipt, never silently reacquire a subset or expanded set.

**Closure:** revised signature and transition sequence state the enforcement owner. Fake implementations, another registry/issuer, ended/suspended/other holders, wrong expected gate, subset/extra/duplicate file sets and consumed receipts fail before INSERT/reference mutation/storage open. Exact positive receipt works once; wrong member order fails B06 graph validation even when the same file set is present. No new source acquisition phase or global authority cache is introduced.

## Accepted design decisions and implementation review obligations

1. **One genuine authority chain.** `registry.adopt` may reuse authentic B03 access via requirePrepared, exact actor/meeting and complete owner coverage without access.lock or late identities. Private B06 issuer/source/holder/gate/purpose/full-graph checks are necessary at every consumption. Worker and history start from fresh READ gate acquisition but must call current owner EDIT authorization on that same B03 handle. Actor status/roles, public request records, enum purpose and detached facts remain claims only. History may be read after publication when ACL permits; workers/writers separately reject ever_published/PUBLISHED.

2. **First binding needs no fake transcript.** Reserve an exact new graph while still in the domain phase; acquire all unique original sessions, then all files, before any member FK INSERT. Insert only reserved new IDs, require one affected row and fail conflicts. Read and compare the actual uncommitted batch/profile/input/full members and explicit empty own producer/output sets before sealing the first-bind proof. Reservation alone must not validate/bind/read. One source receipt and one complete bindAll handoff preserve the FK order and protective-reference rollback semantics.

3. **Complete existing-domain order.** Use the stated rank consistently: bounded transcript/parent closure by UUID, inputs, batches, profile rows, members by batch/ordinal; complete union before any session, then all files, then all task UUIDs, then attempts. This applies across full-spec batches and generic current-reference expansion. Discover closure before locks and recheck under the meeting root; reject new edges rather than locking them late. Every task in a multi-task set must be held before acquiring any attempt. SQL traces must test UUID order deliberately different from file ordinal, task input order and parent traversal order. Transaction-created rows are the sole post-source new-domain exception.

4. **Lease and history producer proofs differ.** Worker bytes require the actual durable task's full spec/state/attempt/owner and DB expiry plus matching unfinished attempt after sources. Old DTO expiry after genuine renewal is valid; future DTO expiry cannot rescue an expired DB row. Do not call queue.validLease and restart identity/root acquisition. Current/history producer validation must prove the exact RAW producer relation and immutable full spec/input/fingerprint chain; do not require a historical producer to remain RUNNING or match today's businessVersion. Generic current reads must perform these producer checks too. Task 5 final completion independently rechecks current authority after parsing.

5. **Original source and route checks.** Require exactly one matching COMPLETED original, derived UUID/purpose, non-null SHA, size/key/meeting, AVAILABLE, original cancel epoch, supported counters, current managed backend identity/type/status/revision, and exact business membership/reference. Read original uniqueness with a bounded LIMIT 2; lock discovered session UUIDs explicitly in sorted order rather than reusing the old association query as the lock primitive. No huge provider token/version/name projection is needed for source authorization. READ_ONLY is a positive case; DISABLED/missing/redefined historical route must fail without fallback. Optional client upload ID cannot replace the derived ID.

6. **Computation and source I/O boundaries.** Full bounded draft manifest/config closure and canonical hashes remain outside roots; locked comparisons use exact bounded immutable observations. New held/uncommitted capabilities do not alter standalone ProcessingFactsReader ambient rejection or existing FullRow/hash algorithms. Sidecar absent/unknown means unavailable, not inferred v1. Only a successful standalone authorization commit may produce the registry-private local pin; backend storage open/read follows commit without a DB transaction. Failed finalizer/commit cannot expose a pin. Recheck the exact historical backend before opening; no new public opener/callback/synchronization. Stream closure and actual byte size/SHA verification remain required.

7. **Atomic intake and queue composition.** Fresh CAS after exact semantic idempotency normalization; retain the real initial subject handle before sources; advance once to r+1/e and enqueue the normative TRANSCRIPT_IMPORT_V1 / TRANSCRIPT_IMPORT full spec through the registered private adopted scope. Preserve prior saved transcript, clear confirmations and set debt. Producer hashing stays before identities/roots and matches an independent golden vector. No invented current-input field, TEST grammar, dummy output or default archive substitution. Ordinary queue preparation overrides per-spec acquisition with the full shared union and respects skip on every acquired existing row.
