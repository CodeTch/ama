## Mandatory implementation and activation closure gates

These gates identify the evidence still required; they do not approve unseen code.

- **T7-G1 — Registered capabilities and atomicity.** Implementation review must inspect rejection of wrong issuer, source, holder, purpose, full-spec set, execution and staged private type. Real MySQL barriers must prove newly inserted output is validated after insertion; graph/task/task_attempt/execution/operation/audit/outbox roll back together on each failure. Legacy observation/ordinary completion semantics remain compatible.
- **T7-G2 — Fact and replay matrix.** Preserve the exact ACTIVE-stale-token assertion, genuine disabled-owner terminal exception, no nonterminal exception, old-generation contradiction quarantine, and no effects from receipt-only. Exercise terminal commit ACK loss, preparation failure and all four discovery retries. Replaying a terminal receipt cannot invoke a writer, change candidate disposition, duplicate events or mint send/admission authority.
- **T7-G3 — Provider identity eligibility.** Task 9's controlled provider must durably bind one result ID to the original request/execution and exact normalized payload across process restart; include rejected/oversized/invalid output receipt handling. Demonstrate conflict rejection, not merely equal-ID acceptance. If the actual stored/provider evidence cannot prove equivalence, keep replay unavailable and independently review the precise required durable identity/digest addition before activation. No Task 7 DDL is authorized by this review.
- **T7-G4 — Worker linearization.** Actual barriers must cover renewal already inside the monitor, queued renewal after marker commit, marker ACK uncertainty, tracker registration failure, operation loss versus observation, close versus admission and late receipt. Shared monitor ownership must be implemented in the tracker itself. A bare lost() read followed later by a write is insufficient. Verify bounded JDBC/transport/close behavior and no ordinary second completion/quarantine after MARKING.
- **T7-G5 — Durable permit recovery.** Freeze finite recovery page size, lock/statement/per-pass budgets and cross-call cursor/exhaustion behavior in the implementation. SKIP LOCKED discovery alone is insufficient if the subsequent settlement can wait indefinitely. Recovery must run on the existing bounded reconciliation maintenance cadence even when there is no claimable operation or handler slots are occupied; failed candidates must not repeatedly hide later debt. Test terminal-commit-before-settle crash, settle-before-ACK, contention, multiple pages, invalid local output, UNKNOWN and old-versus-new execution reservations. Preserve the existing capacity configuration/RR discipline.
- **T7-G6 — Genuine generation domain.** Task 9/10 acceptance must use the real B03 authority and complete fixed-input policy, not only TEST policies. Test zero/positive/missing intent, existing body, business-only stale retention, changed cancel/lifecycle/identity/publication, original graph/producers, and unchanged protected root fields. Full graphs remain mandatory, and no schema/source/budget failure turns into a zero-effect retry.
- **T7-G7 — Version and publication integration.** Task 10 must enumerate every relevant business-version writer and integrate the same complete bounded PENDING prelock/disposition helper. Task 11 must freeze and test final revision/hash representation, readiness-before-advance, publication lock representation and every direct content mutation path. The reviewed root attempt clarification resolves the potentially ambiguous word attempt: the atomic task+attempt pair is durable_task/task_attempt, not publication_attempt. Task 7's fenced branch intentionally runs no domain writer. Task 11 must expose separately the authoritative remoteOutcome from exact durable operation/execution joins and the publication attempt/application outcome; publication_attempt.PENDING may mean unapplied business state after remote terminal success. Preserve the publication/content lock, expose honest manual handling, and do not offer resend or an ordinary reconciliation claim for the already-terminal operation. A later recorded-fact business application requires its separately reviewed fresh owner/fixed confirmation/destination/request/cancel/lifecycle authority. No shared fact-only domain writer is approved.
- **T7-G8 — Regression and activation separation.** Run the specified inherited external, permit, B06, queue/transaction/outbox and worker regressions on the implemented source. Task 8's >64-candidate fairness work remains a separate prerequisite to external worker activation. Actual Tasks 9–11 graph/API/provider/fresh-JVM restart evidence is required before the controlled business loop is accepted.
